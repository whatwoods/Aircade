> 游戏目录：`games/brick-survivor/`　开发端口：5102　本地存储前缀：`aircade.brick-survivor.`
> 文档约定：

## 1. 一句话卖点与体验目标

### 1.1 一句话卖点
**左右拖动一枚棱镜核心，让几十颗霓虹弹球在步步下压的砖阵里反弹、燃烧、冻结、连锁爆炸。打砖块的手感 × 割草肉鸽的成长爆发。**

### 1.2 设计支柱
1. **每一次拖动都有理由。** 瞄准、接球充能、拾取晶体、闪避弹幕这四个目标会抢同一个水平位置，玩家每秒都在取舍。
2. **可读的混乱。** 屏上有 60 颗球、150 块砖、上千粒子时，仍然一眼能分清：颜色表示元素，形状表示行为，亮度表示重要性（球最亮，砖次之，粒子短命）。
3. **克制而有层次的爽感。** 小事件轻、大事件重。最强的反馈只留给 Boss 击破、进化和通关。

### 1.3 体验目标
- **一局时长**：通关约 12–13 分钟。新手失败局多在第 12–17 波结束，约 7–10 分钟。见 §3.16 的时长估算。
- **3 秒可玩**：首包约 90 KB gzip，标题页「开始游戏」按钮立即可点。
- **30 秒懂规则**：首局引导约 30 秒，全部在操作中完成（§6.3）。

**情绪曲线**

| 时段 | 局内节点 | 目标情绪 | 设计手段 |
|---|---|---|---|
| 0:00–0:30 | 引导 / 第 1 波 | 上手即爽 | 一击即碎的砖、首次升级在 15 秒内 |
| 0:30–3:00 | 第 1–4 波 | 构筑萌芽 | 前 4 波约 8 次升级，元素颜色开始混入画面 |
| 3:00–4:00 | 第 5 波 Boss 方碑 | 第一次紧张，然后释放 | 方碑随砖阵下压，限时击破；击破时慢动作、闪光、清屏 |
| 4:00–8:00 | 第 6–10 波 | 力量幻想上升 | 炮台、守卫加入；首次进化通常出现在 6–8 分钟 |
| 8:00–11:00 | 第 11–15 波 | 勉力支撑 | 砖阵越压越低，霓蛇 Boss 带来走位压力 |
| 11:00–13:00 | 第 16–20 波 | 决战高潮 | 终焉之核三阶段；通关时最长慢动作、全屏白闪、胜利结算 |

### 1.4 关键设计决策速答（回应主代理的追问）

| 问题 | 结论 | 详见 |
|---|---|---|
| 实时还是回合制？ | **实时**。理由：割草的核心是持续的密度和反馈；自动发射加持续拖动天然是实时的；回合制（Ballz 式「打完等球回来」）有等待空档，拖动也失去意义 | §3.1 |
| 砖块下压节奏 | **定时整排下压**：每 N 拍整排下移一格，0.32 s 缓动滑移，并量化到 BGM 节拍。不做连续下移，因为整排下压节奏可读、预警清晰；两次下压之间砖块静止，碰撞也更稳 | §3.6 |
| 波次定义 | 一波 = 从波次表生成的若干行，逐拍进场，波与波之间空 1 行喘息。每 5 波是 Boss 波，共 20 波 | §3.6 |
| 弹球生命周期 | 核心有**弹仓**，按发射间隔自动射出。球落回底部时有两种结局：**被挡板接住**，立即反弹并充能 +1；**漏接**，落出底部，0.5 s 后回到弹仓重新发射。球永不丢失 | §3.4 |
| 玩家技巧点 | ① 发射位置决定打哪一列；② 接球位置决定反弹角（边缘最大 ±60°，移动中接球再叠加侧旋）；③ 完美接球（挡板中心 25%）充能 +2；④ 走位拾取地面晶体（地面停留 7 s 后消失）；⑤ 闪避炮台和 Boss 弹幕 | §3.5 |
| 经验收集 | 晶体从砖块位置迸出并受重力下落，落到地面线后滑停。进入核心磁吸半径（初始 64 u）后飞向核心 | §3.9 |
| 升级时暂停还是慢放 | 经验满时 0.25 s 内把时间缓降到 0，场景压暗；卡片入场 350 ms 内不接受点击，防止误触；选卡后 0.4 s 内时间缓升回 1 | §3.9 / §6.5 |
| 辉光与性能 | 自研 WebGL 批渲染：**预烘焙辉光贴图 + 预乘 alpha 加色混合**，一张图集，每帧约 10 次 draw call。高画质再加 1/4 分辨率 bloom；按帧时自动降档 | §2.2–2.3 / §9 |
| 大量碰撞 | 砖块按规则网格排列，球直接换算格子坐标查询，O(1)。物理固定 120 Hz，每子步位移 ≤ 3 u 防穿透；球与球之间不碰撞 | §2.4 |

## 2. 技术选型

### 2.1 总览

| 领域 | 选型 | 理由 |
|---|---|---|
| 语言 / 构建 | TypeScript（strict）+ Vite | 符合共同约定，开发热更新快，产物是纯静态文件 |
| 渲染 | **自研 WebGL 精灵批渲染器**（优先 WebGL2，回退 WebGL1，统一用 GLSL ES 1.00 着色器） | 画面元素只有发光圆、发光圆角矩形、条带、粒子、位图文字，自研约 800 行即可覆盖。体积约 15 KB，能完全掌控混合模式和后处理 |
| 后处理 | 自研 bloom（1/4 分辨率亮度提取 + 两次可分离高斯模糊）+ 合成着色器（暗角、扫描线、色散、闪光、冲击波扭曲、去饱和） | 只在「高」档开启；中、低档靠预烘焙辉光即可 |
| 物理 / 碰撞 | 自研：固定步长 120 Hz，子步积分；圆与 AABB（含接缝平滑）、圆与圆；砖块网格直查 | 规则简单、场景规模可控，确定性好（配合种子可复现） |
| 动画 / 缓动 | 自研池化 tween + 缓动函数库 + 指数趋近 / 临界阻尼弹簧 | 不分配对象，DOM UI 和 WebGL 两侧共用 |
| UI | DOM 覆盖层（HUD、面板、按钮），按世界坐标定位，用 CSS transform 缩放到与画布对齐 | 中文字清晰，排版简单，可访问性好，Playwright 也容易定位 |
| 音频 | WebAudio 实时合成：振荡器、噪声缓冲、滤波器、包络、程序化生成的混响脉冲；带前瞻调度器的程序化 BGM | 共同约定要求原创、零外部资源 |
| 随机 | sfc32 可播种 PRNG，分 `gameplay` 与 `fx` 两条流 | `?seed` 可复现；画质档位改变粒子数量时不影响玩法随机 |
| 字体 | @fontsource/orbitron（latin 700/900）、@fontsource/rajdhani（latin 600/700），通过 `?url` 导入 woff2，用 FontFace API 加载 | 本地打包；只打包 woff2；加载完成后再把字形烘焙进图集 |

### 2.2 为什么不用 PixiJS 或 Canvas2D
- **PixiJS 8.22.0**：我实测过最小示例（Application + Sprite + Graphics + BlurFilter），esbuild 压缩后约 564 KB，gzip 后约 164 KB（WebGPU、Canvas 渲染器作为分包，运行时只加载其中一部分，预计也在 100 KB gzip 以上）。我们需要的只是一个四边形批渲染器加几个着色器，用 Pixi 等于引入 5–10 倍体积，还要绕过它的场景图做粒子池化。
- **Canvas2D**：`shadowBlur` 每次绘制都要做模糊，太慢；`drawImage` 加 `lighter` 混合在手机上绘制 3000 个以上精灵会占掉 5–8 ms CPU。Canvas2D **只在启动时用来烘焙贴图**，在烘焙阶段可以放心用 shadowBlur 和渐变。

### 2.3 霓虹辉光方案（手机稳定 60fps）
1. **预烘焙辉光**：启动时用 Canvas2D 把所有发光形体烘焙成「白色形体 + 外发光」贴图，打进一张 2048² 图集，运行时按顶点色着色。锐利贴图（砖框、字形、核心）按 3× 烘焙，软贴图（光晕、光点、条带）按 1× 烘焙，放大后也不糊。
2. **一种混合模式同时实现普通与加色**：全局固定 `blendFunc(ONE, ONE_MINUS_SRC_ALPHA)`（预乘 alpha）。顶点色 alpha = 1 是普通混合，alpha = 0 是纯加色，介于两者之间是「软加色」。因此普通精灵和加色精灵可以放在同一批次，按绘制顺序排即可，整帧几乎不切换状态。
3. **拖尾用连续条带**：相邻四边形共享边，加色叠加时关节处不会出现亮点。每颗球画两层：宽软外光加细亮内芯。
4. **Bloom 只做 1/4 分辨率**：场景 FBO → 降采样 1/4 同时做亮度阈值（0.6，软膝）→ 水平 9-tap 模糊（线性采样，5 次取样）→ 垂直模糊 → 合成。合成时同时处理暗角、扫描线、色散、闪光、冲击波和去饱和，只多一次全屏 pass。
5. **画质分档与自动降档**：

| 档位 | DPR 上限 | Bloom 与合成 | 粒子上限 | 拖尾点数 | 扫描线 / 色散 / 冲击波扭曲 |
|---|---|---|---|---|---|
| 高 | 2 | 开 | 1800 | 14 | 开 |
| 中 | 1.5 | 关（暗角和闪光改用覆盖精灵绘制） | 1200 | 10 | 扫描线用覆盖贴图；色散改为红闪 |
| 低 | 1 | 关 | 700 | 7 | 关 |

自动档：开局默认「高」，每 5 s 统计一次。若帧时 p90 超过 18.5 ms 就降一档，局内不回升以免来回跳；下一局再从上次的档位起步。设置里可以手动锁定档位。

### 2.4 碰撞与物理
- **固定步长**：逻辑和物理都以 `physics.hz = 120` 推进，单帧最多补 `physics.maxStepsPerFrame = 8` 步，真实帧间隔超过 100 ms 时截断。渲染时用插值 α = acc/step 平滑球、核心和敌弹的位置，适配 90/120 Hz 屏幕。
- **子步防穿透**：每颗球每个物理步按 `ceil(速度 × dt / physics.maxSubstepDist)` 细分，`maxSubstepDist = 3 u`，不到球半径 6.5 的一半。
- **砖块直查**：砖阵是 7 列的规则网格（§3.2）。用球的包围盒换算出所在行列范围，通常只覆盖 1–4 个格子，直接从环形网格数组 `Int32Array` 取砖块 id，不需要空间哈希。精英砖占 2×2 格，四个格子存同一个 id，按并集 AABB 计算碰撞。
- **其他对象**：Boss 部件、敌弹、晶体数量少，直接线性遍历。球与敌弹碰撞每个物理步做一次，最坏情况 60 × 120 次，约 2–3 万次圆-圆测试每秒，开销可忽略。
- **圆与 AABB 碰撞**：先求最近点。距离小于 r 时，法线 n = (球心 − 最近点)/距离；球心已进入砖内时，取穿透最浅的轴。只有 v·n < 0 时才反射：v' = v − 2(v·n)n，并沿 n 推出 (r − d) + 0.01。
- **接缝平滑**：最近点落在角上、而该角方向的相邻格子也有砖时，改用面法线。这样球擦过两块并排砖的缝时不会怪异折射。同一子步内的多个接触先把法线相加再归一化，只反射一次；每块砖都会受到伤害。
- **防死循环**：每次反弹后，若 |vy| < 速度 × sin(`ball.minAngleDeg = 12°`)，就把方向修正到最小角。每步都把速度长度重新归一化到该球的速度，防止能量漂移。
- **球与球之间不碰撞**，这是同类游戏的惯例，也省性能。
- **运动物体**：砖阵滑移和 Boss 部件按相对速度反射：v' = v − 2((v−u)·n)n，然后重新归一化速度。砖阵整体平移时，空格子也随之平移，所以不会把球挤死（证明见 §3.14）。
- **兜底**：位置出现 NaN 或越出场地 40 u 以上的球直接回收进弹仓，并在调试模式下计数。

### 2.5 动画与缓动
- `ease.ts`：linear、quad、cubic、quart、expo、back（可调过冲）、elastic、sine，均提供 in/out/inOut 三种。
- `tween.ts`：池化（预分配 256 个），目标为「对象 + 数值字段」或回调，不产生闭包垃圾。支持 delay、yoyo、onComplete，并标记跟随**游戏时间**还是**真实时间**（UI 跟真实时间，暂停时也能动）。
- `spring.ts`：数值显示（分数、经验条、Boss 血条拖尾）用指数趋近 `v += (t − v)(1 − e^(−k·dt))`；弹性形变（砖块受击缩放、挡板挤压、连击数字弹跳）用临界阻尼 / 欠阻尼弹簧。

### 2.6 音频
- 链路：`sfxBus` 和 `musicBus` → `master` → DynamicsCompressor（−14 dB, 4:1）→ 低通滤波（平时 20 kHz；暂停和慢动作时扫到 600 Hz 制造发闷感）→ destination。
- 首次 pointerdown 时创建或恢复 AudioContext。页面隐藏时 suspend，恢复后 resume；iOS 的 `interrupted` 状态也会处理。
- 音效在每次播放时新建节点（创建很便宜）。按类别限流，例如砖块命中音每 35 ms 最多 1 个，同时活动节点 ≤ 32 个。噪声缓冲和混响脉冲（1.2 s 指数衰减噪声）只在启动时生成一次。
- 设计细节见 §5.4。

## 3. 玩法与规则

### 3.1 核心循环

```
 ┌─────────────────────────────────────────────────────────────────┐
 │ 拖动核心 ─► 自动发射弹球 ─► 反弹击砖（元素/行为触发）─► 砖碎      │
 │    ▲              ▲                                     │       │
 │    │         接住=充能+1                               掉落经验晶体│
 │    │         漏接=0.5s后回弹仓                            ▼       │
 │ 闪避弹幕 ◄── 砖阵按拍整排下压 ◄── 越线扣血        走位拾取→经验满  │
 │                                                          ▼       │
 │        Boss 每 5 波 ◄── 构筑成型 / 进化 ◄── 升级三选一（时间冻结） │
 └─────────────────────────────────────────────────────────────────┘
```

**为什么用实时**：割草类的乐趣来自持续的高密度反馈和指数式成长，要求画面一直在动。自动发射保证玩家的注意力全在**走位**上，而走位只有在实时下才有价值：球的落点、晶体的消失、弹幕的到达都是时间敏感的。回合制会出现「等球回来」的空档，接球、拾取、闪避这三类决策也就不存在了。

### 3.3 操作
- **触屏 / 笔**：在屏幕任意非按钮位置按住拖动，做**相对拖动**：`targetX += Δ指针x × input.dragGain(1.25)`。手指不会挡住核心，拇指放在屏幕下方即可。只跟踪最近一次按下的那根手指。
- **鼠标**：**绝对跟随**，`targetX = 指针x`，不必按住按键，打砖块游戏在桌面上惯用这种方式。按住拖动同样有效，Playwright 用哪种方式都能操作。
- **键盘**：← / → 或 A / D，目标速度 700 u/s，加速度 7000 u/s²；P 或 Esc 暂停；1/2/3 选卡；R 刷新。
- **核心跟随**：`x += (targetX − x)(1 − e^(−player.follow·dt))`，`follow = 30`，约 50 ms 追上目标；速度上限 `player.maxSpeed = 2400 u/s`。x 限制在 [wallL + 半宽, wallR − 半宽]。核心的瞬时速度 `vx` 用于计算侧旋。
- 核心只做水平移动，y 固定在接球线上。

### 3.4 弹球生命周期

```
 [弹仓] ──发射间隔到且弹仓>0──► [飞行] ──下落穿过接球线且在挡板范围──► [接住] ─反射+充能─► [飞行]
   ▲                                │
   │                         落出 dropY（漏接）
   └──── reloadDelay 0.5s ◄──── [回收] （充能清零；碎片球、回响球直接销毁）
```

| 字段 | 初始值 | 说明 |
|---|---|---|
| `ball.startCount` | 3 | 开局拥有的主球数（弹仓 + 飞行中） |
| `ball.maxMain` | 12 | 主球上限 |
| `ball.fireInterval` | 0.40 s | 弹仓非空时的发射间隔 |
| `ball.reloadDelay` | 0.5 s | 漏接后多久回到弹仓 |
| `ball.speed` | 600 u/s | 恒定速率 |
| `ball.radius` | 6.5 | 主球半径 |
| `ball.baseDamage` | 10 | 基础伤害 |
| `ball.spreadPatternDeg` | [0, −7, 7, −3.5, 3.5] | 依次循环的发射偏角（相对竖直向上） |
| `ball.fireEnglishFactor` | 0.5 | 发射时侧旋按接球侧旋公式的一半计算，上限 ±8° |
| `ball.hitCooldown` | 0.06 s | 同一颗球对同一块砖的重复命中间隔 |

- **发射**：从棱镜尖端 `(x, catchY − 22)` 射出。角度 = 发射偏角循环 + 侧旋。每颗球在发射时按**元素轮换**获得元素（§3.8.1）；充能为 0；穿透次数重置为当前等级值。
- **主球永不丢失**：漏接只损失充能，外加 0.5 s 装填延迟。弹仓数量用挡板上方的小光点显示（最多 12 个；光点颜色是下一颗球的元素色）。
- **碎片球**（分裂）与**回响球**（棱镜回响）属于临时球：也能接，但不会充能（回响球除外，它继承母球的充能），落出底部就销毁。碎片球另有寿命 6 s，最后 0.5 s 淡出。

### 3.5 接球、弹道与技巧点

**接球判定**（每个子步检查）：
- 球满足 vy > 0，球底在本子步内从 catchY 上方穿到下方，且 |球x − 核心x| ≤ 半宽 + 0.5r；
- 或者「铲球」：球心位于 [catchY − r, catchY + `catch.scoopDepth = 10`] 区间内、仍在下落，同时挡板这一帧快速移到了它下方。这个容错能让快速横扫接球手感更好。

**反射角**：
```
t      = clamp((球x − 核心x) / 半宽, −1, 1)
θ      = t × catch.maxDeg(60°) + clamp(vx × catch.englishDegPerUps(0.012), ±catch.englishMaxDeg(15°))
θ      = clamp(θ, ±(90° − ball.minAngleDeg))
v      = speed × (sin θ, −cos θ)
```
- **完美接球**：|球x − 核心x| ≤ `player.perfectZone(0.25)` × 挡板宽 / 2，即挡板中心 25% 的区域，宽 19 u。
- **充能**：普通接球 +1，完美接球 +2，最多 `charge.max = 3` 层。每层使伤害 +25%（`charge.perStack = 0.25`），满层 +75%。充能一直保留到这颗球漏接为止，所以连续接住同一颗球，它会越来越亮、越来越痛。
- **侧旋**：边移动边接球，会额外改变反弹角，最多 ±15°。核心以 1000 u/s 横扫时约偏 12°，能把球斜送进侧边缝隙。

**左右拖动的决策意义**：
1. **瞄准**：球从核心所在位置向上发射，所以站在哪里就打哪一列。应优先处理越线预警行、炮台、守卫砖（护盾源），以及能引发连锁的炸药砖。
2. **接球**：多颗球同时下落时，优先接充能高的球（光圈层数可见），或者接能维持火力的球。高充能球下落时，接球线上会显示**落点预告**（§6.4）。
3. **角度**：用挡板边缘接球能打出大角度斜射，可以钻缝，或把球送到砖阵上方的空腔里形成「笼中弹」，连续命中。
4. **拾取**：晶体落地后停留 7 s，最后 2 s 闪烁，需要专门走过去吸取。
5. **闪避**：炮台弹（第 6 波起）、Boss 弹幕和光柱都需要横向躲开；球能击毁敌弹，所以「让球线挡在身前」也是一种防守。

### 3.6 砖阵推进与波次

**推进方式：定时整排下压，量化到节拍**
- 每次推进，整个砖阵下移一格（28 u），滑移 `advance.slideTime = 0.32 s`，easeInOutCubic，末尾有 2 u 的回弹。
- 推进间隔以拍计，取自波次表的 `stepBeats`。计时器到期后，等到**下一个 BGM 拍点**才执行推进（最多多等 0.5 s），让推进的「咚」声与音乐同步。音乐关闭时用一个静默的虚拟节拍时钟。
- **冻结减速**：推进计时器的流速 = 1 − min(减速上限, 每块冻结砖的减速 × 冻结砖数)，数值见 §3.10 冰冻。
- **空场加速**：屏上存活砖块少于 `advance.sparseThreshold = 5` 时，下一次推进改为 `advance.sparseBeats = 2` 拍后，避免强力玩家面对空场等待。
- **新行进场**：新行在天花板上方（y = 40）生成，随推进滑入，出现时有 0.3 s 的缩放（0.6→1，easeOutBack）和描边白闪。
- **开局预填**：第 1 波开始时，前 3 行在 1.5 s 内以每拍一行的速度快速进场。Boss 击破后，下一波的前 2 行也这样快速进场，保证画面立刻有内容。

**越线**：推进结束时，底边超过 dangerY 的砖块会撞到警戒线上爆裂，不掉落晶体，并按砖块类型扣血（§3.7）。
- **单次推进的扣血上限**为 `advance.breachCapPerStep = 4`。
- 发生越线后，下一次推进额外延后 `advance.postBreachBeats = 2` 拍，作为喘息。
- **预警**：下一次推进就会越线的砖块，红色描边以 3 Hz 脉冲；警戒线在这些砖所在的列变为实线亮红，并带危险斜纹。

**波次推进**
- 一波 = `rows` 行。这些行每次推进进场 1 行，最后 1 行进场后再空 1 行（`waves.gapRows = 1`），然后下一波的第 1 行进场。
- 新一波的第 1 行进场时，HUD 的波次数字翻牌，同时出现横幅「WAVE 07」。
- Boss 波（5/10/15/20）：上一波最后 1 行与空行进场后，进入 Boss 预警。砖阵的推进方式改为由 Boss 规则决定（§3.11）。Boss 击破后进入下一波。

**行生成**（`waves.ts`）
1. 先从图案库按权重选一个图案：随机、棋盘、V 字、双墙、立柱、满行，后几种在后期波次出现，并按密度裁剪。
2. 每格按密度 `density` 决定是否有砖。每行至少 2 块，最多 7 块。
3. 有砖的格子按概率替换为特殊砖（下表），同时遵守每行和全屏的数量上限。
4. 精英砖（2×2）放在本波最后 2 行，左上格的列在 0–5 之间随机。
5. 砖块 HP = `baseHp(w) × 类型倍率`，再乘以行内 ±10% 的随机浮动，四舍五入为整数。

### 3.8 伤害、元素状态与反应

**单次命中伤害**
```
dmg = ball.baseDamage × (1 + 超载加成) × (1 + 0.25 × 充能层数) × 球种倍率(主1 / 碎片0.5 / 回响0.6)
      × (目标已冻结 ? 1 + 冻结易伤 : 1) × (目标受护盾 ? 0.5 : 1)
```
不设暴击，满充能命中就相当于暴击。只有满充能（3 层）命中、爆炸、热冲击和 Boss 受击会弹出浮动伤害数字，普通命中只让砖上的 HP 数字跳动。

#### 3.8.1 元素轮换
- 元素共三种：**燃烧（橙）、冰冻（青）、爆炸（品红）**。获得某个元素后，它加入元素轮换表 `run.elementCycle`，顺序即获得顺序。
- 每颗主球**从弹仓发射时**按轮换表依次领取一个元素，只有一个元素时所有球都是它。元素的效果强度取对应强化的等级。
- 没有任何元素时是**无属性**球：白色内芯，淡紫拖尾。
- 碎片球和回响球继承母球元素。
- 进化「超新星」会把燃烧和爆炸合并为「新星」元素，见 §3.10.3。

#### 3.8.2 状态规则

| 状态 | 施加 | 效果 | 叠加与刷新 | 互斥 |
|---|---|---|---|---|
| **燃烧** | 燃烧球命中 +1 层 | 每 0.5 s 结算一次：层数 × 每层秒伤 × 0.5 × 基础伤害 × (1 + 超载)。跳伤不计入连击 | 层数上限随等级；每次命中刷新持续时间 | 冻结时会熄灭燃烧（冒一团白汽） |
| **寒冷** | 冰冻球命中 +1 层 | 本身没有效果，持续 4 s，命中时刷新 | 达到 `freezeAt` 层时转为冻结 | — |
| **冻结** | 寒冷达到阈值 | 持续 `freezeDur`；受到的伤害 + `vuln`；拖慢砖阵推进（见 §3.6）；炮台无法开火 | 冻结期间免疫寒冷；解冻后寒冷层数清零 | — |
| **热冲击**（反应） | 燃烧或新星球命中**冻结**砖 | 本次命中额外造成 150% 伤害；立即解冻；白橙蒸汽爆发，弹出「热冲击!」 | — | 消耗掉冻结状态 |
| **爆炸** | 爆炸球命中 | 以接触点为圆心，对半径内所有砖造成「本次命中伤害 × AoE 倍率」（不含被直接命中的砖） | 每颗球的爆炸冷却 0.30 s；爆炸不会递归触发爆炸，炸药砖和超新星除外 | — |
| **受护盾** | 守卫砖周围 8 格 | 受到的伤害 −50% | 被多个守卫覆盖也不叠加 | — |

**Boss 受元素影响**：燃烧照常生效。冰冻不会冻结 Boss，改为每层寒冷使 Boss 的移动和攻击速度 −5%，最多 −30%。爆炸照常生效。热冲击不会对 Boss 触发。

### 3.9 经验、晶体与升级
- **晶体**：从砖块中心迸出，初速向上 80–160 u/s、横向 ±60 u/s；重力 420 u/s²，下落末速 240 u/s；碰墙反弹；落到 floorY 后以 0.3 的弹性衰减弹跳并摩擦滑停；落地后 `gems.floorLife = 7 s` 消失，最后 2 s 闪烁。
- **种类**：小晶体 1 XP（金色菱形，5 u）；中晶体 5 XP（8 u，带闪光）；大晶体 20 XP（12 u，旋转的八面体，外加光环）。屏上晶体超过 `gems.max = 250` 时，新晶体并入最近的已有晶体，累加数值。
- **磁吸**：晶体与核心中心 `(x, catchY)` 的距离小于 `gems.magnetRadius = 64` 时，以 2600 u/s² 加速飞向核心（上限 950 u/s）；距离 ≤ 14 时收取。Boss 击破后，全屏晶体都会被吸走。
- **治疗芯片**：白色十字，薄荷色光晕，回复 1 HP，下落和拾取规则与晶体相同。
- **升级经验**：`xpToNext(L) = xp.base(5) + xp.perLevel(3) × (L − 1)`，即 5、8、11 … 到第 30 级为 92。一局约收集 1450 XP，升到 30 级左右。
- **升级流程**：
  1. 经验条满时闪白，核心爆出紫色光环，屏幕中央出现「LEVEL UP」。时间缩放在 0.25 s 内从 1 缓降到 0（easeOutQuad，按真实时间计）。
  2. 场景压暗（高画质时由合成着色器做去饱和加压暗，其他档位用覆盖层），三张卡依次入场，间隔 70 ms。
  3. 入场后 `levelup.inputLockMs = 350` 内不接受点击；选择必须是一次新的 pointerdown 加 pointerup，防止拖动中松手误选。
  4. 选中后，卡片闪白并飞向底部构筑条。时间在 0.4 s 内从 0 缓升到 1（easeInQuad）。
  5. 有多级待升时，下一个面板立即接着出现，标题旁显示「+2」。
  6. Boss 击破的慢动作期间获得的升级，会排队到慢动作结束后再弹出。
- **刷新**：开局 1 次，每击破一个 Boss +1 次，刷新会重新抽三张卡。

**三选一抽取规则**（`offers.ts`）
1. **槽位**：武装最多 `upgrades.weaponSlots = 4` 种（从 7 种武装里选），模块最多 `upgrades.moduleSlots = 3` 种（从 5 种模块里选）。槽位满了以后，只会出现已拥有且未满级的强化。
2. **权重**：武装 1.0，模块 0.8；已拥有的 ×1.6；同一次抽取不重复。
3. **进化**：满足进化条件时，必定占用一张卡，卡面为金色。
4. **首次升级**至少包含一个元素（燃烧、冰冻、爆炸三选一），让画面尽早出现颜色。
5. **兜底卡**：候选不足 3 张时，用以下卡补足：「能量电池」回复 2 HP；「数据缓存」获得 150 × 波次的分数。
6. **配方提示**：卡面上，若该强化是某个进化配方的一部分且玩家已拥有另一半，会显示「⛓ 进化：+爆炸 Lv3 → 超新星」。

### 3.10 强化表

### 3.11 Boss 设计
**通用规则**
- **登场**：先是 2.0 s 预警：上下边出现红色斜纹跑马灯，中间显示「WARNING」，伴随警报声，音乐的滤波向下扫。然后 Boss 在 1.5 s 内从 y = −120 降到驻留位置，**沿途碾碎所有与 Boss 本体重叠的砖**（不掉晶体，只有碎裂特效）。降落时 trauma 0.3，名牌（中文大字 + 英文小字）从中央滑入并停留 1.2 s。登场完成 1.0 s 后 Boss 开始攻击。
- **碾压**：Boss 本体与砖块重叠时直接碾碎砖块。霓蛇例外，它遇砖会掉头。
- **血条**：位于顶部 y = 74–90（§6.4），阶段阈值处有刻度；受击时白色拖尾延迟 0.4 s 后追上。
- **受击**：只用圆形碰撞体（视觉可以是多边形）。部件受击时闪白 50 ms，并弹出小号浮动伤害数字（每个部件每 0.15 s 最多 1 个）。
- **奖励**：大晶体 ×3（60 XP），全屏晶体被吸走，回复 3 HP，刷新次数 +1，然后立刻弹出一次升级三选一。
- **击破演出**：先 hitstop 150 ms；接着时间缩放 0.15，持续 1.2 s 真实时间；镜头放大到 1.06 并聚焦 Boss；Boss 身上依次爆开 6 个小爆炸，然后是最终大爆炸；全屏白闪（alpha 0.9→0，0.45 s）；冲击波环从 Boss 处扩散，0.6 s 内扫清全屏砖块（被扫到的砖照常掉落晶体，并计入连击）；最后时间缩放在 0.5 s 内回到 1。音效是反向渐强、巨响加长尾音。

**Boss 1 · 方碑 MONOLITH（第 5 波，HP 2400）：限时击破**
- **外观**：淡紫白色的六棱柱核心，r 40，内部有一只红色眼睛，瞳孔追踪核心位置，约每 5 s 眨一次眼。外围 6 块靛蓝护板（视觉 24×12 圆角板，碰撞圆 r 12），在半径 72 处以 50°/s 公转。
- **护板**：每块挡 3 次命中后碎裂，碎裂后 6 s 重建，重建时有 0.5 s 线框生长动画。
- **移动**：x = 195 + 70·sin(2πt/8)，驻留 y = 180。**方碑随砖阵推进**：本 Boss 战期间推进照常（6 拍一次），但不生成新行；每次推进方碑也下移 28 u。
- **威胁**：方碑底部碰到警戒线时**砸地**，造成 4 点伤害，然后在 1.2 s 内升回 y = 180。按每 3 s 推进一次计算，约 50 s 就会砸到，所以这是一场 DPS 检测。
- **攻击 A·阵列召唤**（每 9 s）：先预警 0.8 s，核心发白，Boss 下方 2–3 行处有 3 个空格显示虚线预告；随后生成 3 块普通砖（HP 19），这些砖随推进一起下压。
- **阶段 2（HP ≤ 50%）**：护板转速提到 90°/s。新增**攻击 B·棱光弹**（每 4 s）：2 块护板闪红 0.5 s 后，各向核心发射一颗敌弹（200 u/s）。
- **击破**：护板向外飞散并碎裂，核心裂缝中射出 6 道光束，然后爆炸。
- **配色**：本体 #CDB8FF，护板 #5A4BFF，眼睛 #FF3355。

**Boss 2 · 脉冲星 PULSAR（第 10 波，HP 8000）：走位与分裂**
- **外观**：圆形恒星核心，r 36，白热的中心向外渐变为猩红 #FF3355；外围 3 圈虚线环（r 52/64/78，转速和方向各不相同，纯装饰）；外缘有闪烁的日冕尖刺。
- **砖阵**：推进暂停，残余砖块作为掩体。
- **移动**：在 3 个巡航点（x = 90/195/300，y = 200）之间移动，每段 1.6 s（easeInOutSine），到点停留 1.2 s。
- **攻击 A·扇形弹幕**（每次停留时）：预警 0.6 s，核心收缩，5 条细红线指向核心所在区域，扇形张角 50°；随后发射 5 颗敌弹（210 u/s，r 6）。
- **攻击 B·俯冲**（每 14 s）：先在屏上标出一条红色竖向警示柱 1.0 s；然后 0.5 s 内俯冲到 y = 470，放出一圈 10 颗敌弹（160 u/s）；悬停 1.5 s，期间受到的伤害 +25%（风险与机会并存）；最后 0.8 s 返回。
- **阶段 2（HP ≤ 50%）**：hitstop 120 ms 后**分裂为两颗子星**（r 26），各自拥有剩余 HP 的一半（血条显示两者之和）。两颗子星各自巡航，交替发射 3 颗一组的扇形弹，不再俯冲，速度 ×1.3。其中一颗被击破后，另一颗进入狂暴，攻击间隔 −30%。
- **击破**：向内坍缩后，爆出一次红白色的新星闪光。

**Boss 3 · 霓蛇 SERPENT（第 15 波，HP 22000）：致敬 Centipede**
- **外观**：14 节。蛇头 r 18，有红眼和颚；13 节身体 r 14，节距 30，是六角甲片，紫色 #8A5CFF，身体中间有一条白色光脊相连；蛇尾带尾刺。
- **HP**：蛇头 2400，每节身体约 1508，合计 22000。
- **砖阵**：推进暂停。
- **移动**：沿行道（与网格行对齐）水平移动，速度 120 u/s。碰到墙或有砖的格子时，在 0.25 s 内下降一行（28 u）并掉头。后续各节沿蛇头的路径历史跟随。
- **断蛇**：击毁中间某一节后，蛇从该处断开，后半段变成新的一条蛇（第一节长出颚，成为新蛇头），反向行进。每条蛇的速度 = 120 + 5 × (14 − 本蛇节数) u/s，上限 190。
- **残骸**：被击毁的身体节如果所在格子为空，会在那里留下一块普通砖（HP 90）。蛇碰到砖就会下降，所以打得越碎，蛇下降得越快，这就是 Centipede 式的张力。
- **威胁**：蛇头到达警戒线时扣 3 点血，然后该蛇以 0.6 s 的故障闪烁瞬移回顶行继续行进。
- **攻击**：位于 y > 300 的蛇头每 6 s 向核心喷出 3 颗一组的敌弹（200 u/s）。
- **击破**：最后一节被击毁时触发慢动作。

**Boss 4 · 终焉之核 OMEGA（第 20 波，HP 60000）：三阶段终战**
- **外观**：「被腐化的棱镜」。黑色核心 r 48，白色边缘，外圈有彩虹色散并不时故障闪烁，还有一个旋转的三角光环；外围 10 个护盾格（碰撞圆 r 13）公转。驻留在 (195, 220)，带轻微漂浮。
- **阶段 1·棱镜壁垒**（100–66%）：
  - 护盾格在半径 88 处以 40°/s 公转，每个挡 4 次命中，碎裂后 5 s 再生。
  - **两侧列推进**：只在第 0、1、5、6 列生成新行，每 6 拍一次，HP = 197 × 0.8，越线照常扣血。
  - 每 5 s 向核心发射 3 颗一组的瞄准弹。
- **阶段 2·天罚**（66–33%）：
  - 阶段转换：hitstop 120 ms、trauma 0.4、闪光 0.3，并伴随咆哮。
  - 护盾格转速提到 70°/s，侧列推进继续。
  - **光柱**（每 5 s）：预警 1.0 s，在核心当前 x 和另一个至少相距 80 u 的随机 x 各出现一条细红线，最后 0.25 s 以 10 Hz 闪烁；随后两道宽 34 u 的竖直光柱从核心直落到地面，持续 0.6 s，命中扣 2 点。瞄准弹改为每 6 s 一次。
- **阶段 3·崩坏**（33–0%）：
  - 护盾永久碎裂，核心暴露，受到的伤害 +30%；核心上移到 y = 150。
  - 侧列推进加快到 4 拍一次。
  - **螺旋弹幕**：双臂，每秒 7 颗，以 120°/s 旋转，弹速 150；每 6 s 持续 3 s。光柱改为每 7 s 一次。
  - 画面周期性出现 0.1 强度的色散脉冲（不影响可读性）。
- **击破即通关**：hitstop 200 ms，时间缩放 0.1，持续 1.5 s；所有粒子被吸向核心（内爆），然后全屏白闪（0.95→0，0.6 s），冲击波清屏；「VICTORY · 通关」横幅出现，接着进入结算。

**Boss 区域约束**：终焉之核占据第 2–4 列、y 68–360 的区域，这里不生成砖。方碑登场时碾碎重叠的砖；它摆动时扫到的残余砖也会被碾碎。

### 3.12 生命、失败、胜利与无尽
- **生命**：`player.maxHp = 10`，用 10 格血条显示。
- **伤害来源**：
  - 越线：按砖块类型计算，单次推进最多扣 4。
  - 敌弹：1 点。命中后有 `player.iFrames = 1.0 s` 的无敌时间，**只对敌弹和光柱生效**，越线照扣。
  - 光柱：2 点。
  - 方碑砸地：4 点。
  - 霓蛇触线：3 点。
- **回血**：精英砖掉落的治疗芯片（+1）、Boss 奖励（+3）、护盾强化（每级 +2）、兜底卡「能量电池」（+2）。
- **低血量**：HP ≤ 3 时，屏幕暗角以 1.2 s 周期泛红脉冲，音乐加入心跳低音，HP 格也随之脉冲。
- **失败**：HP 归 0 时，时间缩放 0.25，持续 0.8 s；核心碎裂成彩色棱镜碎片，画面去饱和并出现故障线，音乐通过低通扫频后静止；1.4 s 后进入结算。
- **胜利**：击破第 20 波的终焉之核。结算页提供「进入无尽」，沿用当前构筑和分数从第 21 波继续；无尽模式中死亡时，结算标注「无尽 · 第 N 波」。

### 3.13 连击与计分
**连击**
- 增加：主球、碎片球、回响球的直接命中，爆炸波及的每块砖，以及热冲击，各计 +1。燃烧跳伤不计。
- 窗口：`combo.window = 1.8 s` 内没有新的命中，连击归零。玩家**受到任何伤害**时，连击立即中断。
- 档位与计分倍率：`combo.tiers = [10, 25, 50, 100, 200, 400]`，对应 `combo.mults = [1.2, 1.5, 2.0, 2.5, 3.0, 4.0]`；10 连击以下为 ×1.0。
- 显示与升档效果见 §5.3。

**计分**（`config.score`）

| 项 | 公式 |
|---|---|
| 击碎砖块 | 10 × 类型计分倍率 × (1 + 0.15 × (波 − 1)) × 连击倍率 |
| 完美接球 | 20 × 连击倍率 |
| 用球击毁敌弹 | 5 |
| 击破 Boss | 2000 × Boss 序号（1–4）；本场未受伤再 ×1.5 |
| 通关奖励 | 10000 + 剩余 HP × 1000 + max(0, 900 − 用时秒) × 10 |
| 无尽波次 | 上述所有得分 ×1.5 |

**最高分**存入 `aircade.brick-survivor.best`，内容为 `{score, wave, timeSec, victory, date}`。

### 3.14 边界情况
| 情况 | 处理 |
|---|---|
| 球陷入近水平的往返 | 每次反弹后保证与水平方向夹角 ≥ 12° |
| 球速很高时穿过砖块 | 子步位移 ≤ 3 u |

### 3.16 难度曲线与时长估算
- **自平衡机制**：砖阵离核心越远，球往返越久，DPS 越低。所以砖阵会稳定在「玩家 DPS 与砖阵来压 HP/s 相等」的深度，**砖阵所在的高度就是难度的直观读数**。
  - 前期：一击即碎的砖，砖阵停在上半屏。
  - 中期：元素组合起来后，玩家能把砖阵推回去。
  - 后期：构筑一般的玩家，砖阵会压到下 1/3，带来真正的越线压力。
- **来压与火力的增长**：
  - 来压：HP 第 19 波约为第 1 波的 17 倍；密度 ×1.6；推进间隔 ×0.67。合计来压 HP/s 约为开局的 40 倍。
  - 火力：主球 3→9（再加碎片），伤害 ×1.6 × 充能均值 1.3，球速 ×1.2，元素与进化 ×2–4。合计约 30–60 倍。
  - 结论：构筑好的玩家后期会越打越轻松（力量幻想）；构筑散乱的玩家会被压到线边。
- **时长估算**：
  - 普通波：每波（行数 + 1）× 推进间隔。第 1–3 波共 63 s；第 4 波 20 s；第 6–9 波 87.5 s；第 11–14 波 84 s；第 16–19 波 96 s。合计约 350 s。
  - Boss：目标击杀时间合计 265 s，加上登场和击破演出各约 7 s，合计约 293 s。
  - 升级选择：约 29 次 × 3.5 s，约 100 s。
  - 引导约 30 s。
  - **通关合计约 12.9 分钟**。
- **验证方法**：用调试接口 `__game.simulate()` 跑无渲染的自动驾驶模拟，输出每波时长、砖阵平均最低行、受伤次数和通关率，据此调整波次表（§8、§10）。

### 4.4 辉光与质感
- **辉光**：见 §2.3，预烘焙光晕加加色混合；高画质再加 1/4 分辨率 bloom（强度 0.8）。
- **扫描线**：每 3 物理像素一条，强度 0.06，纹理每秒下移 1 px，营造缓慢「滚动」感。
- **暗角**：径向暗角，边缘压暗 55%。危险时（砖阵距警戒线 ≤ 3 行，或 HP ≤ 3）暗角混入红色。
- **背景分层**（由远到近）：
  1. 竖直渐变：void → deep → violet。
  2. 星云：启动时烘焙的 256×512 值噪声，品红与靛蓝，12% alpha，缓慢漂移。
  3. 星空：60 颗，各自闪烁。
  4. 合成波透视网格地面：占画面底部 30%，灭点在 y = 560，线色 grid；**每次推进时网格向前滚动一格**，与节奏呼应。
  5. 场地内额外叠一层 void 35%，提高砖块对比度。
- **Boss 战**：背景渐变在 1 s 内过渡到偏红紫（#1A0716 → #2A0A22），网格变成暗红色。
- **墙体**：细线加辉光；被球撞击处的 24 u 线段闪亮 120 ms。
- **噪点**：合成着色器叠加 2% 的胶片颗粒（时间随机），中、低档关闭。

- **标题**：「通关」（金色，Orbitron 的 VICTORY 叠在其后）或「信号中断」（红色，后面叠 GAME OVER）。
- **分数**：72 u 大字，1.2 s 内从 0 滚动到最终值，伴随滴答声。
- **统计**：分数下方 6 行，依次错开入场：到达波数、用时、最大连击、击碎砖块、击破 Boss、等级。
- **构筑**：一排强化图标，带等级小点；进化图标是金色的。
- **新纪录**：「新纪录！」印章，scale 从 2.0 缩到 1.0（easeOutBack），旋转 −8°；面板后方 WebGL 层喷出霓虹纸屑；伴随号角音效。
- **按钮**：底部是大号主按钮「再来一局」和次级按钮「返回标题」；通关时多一个金色的「进入无尽」。

## 5. 动效清单

### 5.1 强度层级规则
- **6 个层级**：
  - 0 环境：只有微动画。
  - 1 微：闪光或数字跳动，不震屏。
  - 2 小：轻微 trauma，不停顿。
  - 3 中：明显 trauma，hitstop ≤ 60 ms。
  - 4 大：强 trauma，hitstop 80–120 ms，同时有色散或闪光。
  - 5 高潮：慢动作、全屏闪光，每局只会出现几次。
- **Trauma 模型**：
  - 偏移 = 9 u × trauma²；旋转 = 1.0° × trauma²。
  - 噪声用种子化的 1D 值噪声，频率 18 Hz；trauma 衰减 1.8/s，上限 1。
  - **层级 ≤ 2 的事件，每帧累计贡献不超过 0.12**，防止割草时满屏乱抖。
- **Hitstop**：
  - 全局 timeScale 置 0，按真实时间计时；同时触发多个时不叠加，取最大值。
  - 层级 < 4 的 hitstop 之间至少间隔 0.15 s。
  - 停顿期间仍会渲染，相机震动和 UI 照常运行。
- **触感**：用 `navigator.vibrate`（Android 支持，iOS 不支持时静默忽略），受设置开关控制。
- **闪光**：「减少闪光」开启时，全屏闪光 alpha 上限 0.35，色散关闭。
- 所有数值都放在 `config.juice.<事件>` 中：`{ trauma, hitstopMs, particles, sfx, haptic, tier }`。

### 5.4 音乐与音效合成要点
- **BGM**：120 BPM，C 小调，用前瞻调度器生成（每 25 ms 检查一次，提前 0.12 s 排程）。
  - 声部：底鼓（正弦，音高包络 150→45 Hz）、贝斯（八分音符琶音，锯齿波 + 带包络的低通）、踩镲（十六分音符，高通噪声）、Pad（失谐双锯齿波 + 1.2 kHz 低通，慢起音）、主音琶音（方波，第 6 波起加入）。
  - 和声：普通段 Cm–A♭–E♭–B♭，每个和弦 2 小节。
  - **强度参数 0–1**：由砖阵危险度和 Boss 状态决定，控制各声部音量和滤波开度。
  - **Boss 段**：贝斯改为失真十六分音符，加入军鼓，和声换成 Cm–D♭–Cm–B°（小二度张力）。终焉之核阶段 3 再叠加故障切片。
  - **标题曲**：只有 Pad 和慢速琶音，没有鼓。
- **音高一致**：砖块命中的五声音阶与 BGM 同一个调，所以割草时的命中声会构成和谐的旋律。
- **推进对拍**：推进量化到拍点，与底鼓重合。

### 6.9 转场
- **场景切换**（标题 ⇄ 游戏 ⇄ 结算）：一条横向霓虹扫描线从上向下扫过，0.45 s（easeInOutCubic）；扫过的区域切换为新场景，切换时带 2 u 的色散错位；伴随一声风声。
- **面板**：进入时 opacity 0→1、translateY(16)→0、scale 0.96→1，耗时 240 ms（easeOutCubic）；退出 160 ms。
- **波次横幅、Boss 名牌**：见 §5.2。
- **游戏中断后恢复**（暂停、升级）：时间缩放按真实时间缓升，不会瞬变。

### 6.10 桌面适配与输入
- **缩放**：世界列按 `scale = min(可用宽/390, 可用高/844)` 等比缩放并居中。可用区域扣除 safe-area-inset。画布铺满整个视口，背景着色器覆盖两侧区域。
- **两侧装饰**：背景网格、星云和星空延伸到两侧；另有竖直霓虹立柱（世界列外侧 12 px 处各一根，从上到下有呼吸渐变）；还有淡淡的「数据流」列，一串串十六进制字符缓慢下落，8% alpha。
- **侧边面板**：任一侧剩余宽度 ≥ 260 px 时显示（DOM 玻璃面板）。左侧是「构筑」，即强化列表和配方进度；右侧是「战况」，即分数、最高分、用时、最大连击，以及键位提示「←/→ 或 A/D 移动 · 鼠标跟随 · P 暂停」。宽度不足时不显示面板，只保留装饰。
- **画布像素**：后备缓冲 = CSS 尺寸 × min(devicePixelRatio, 档位 DPR 上限)；尺寸变化在 resize 事件里节流，100 ms 内只处理一次，世界坐标不受影响。
- **防误操作**：
  - CSS：`touch-action: none`、`user-select: none`、`-webkit-touch-callout: none`、`overscroll-behavior: none`。
  - 事件：阻止 `contextmenu`、`gesturestart`、`dblclick`。
  - viewport meta：`width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover`。
- **鼠标光标**：位于世界列上方时换成自绘的小十字（CSS cursor 使用内联 SVG data URI，不请求外部资源）。

**关键数据结构**（示意）
```ts

  id: number; type: BrickType; col: number; rowAbs: number; cw: 1|2; ch: 1|2;
```

## 9. 性能预算与策略

**目标**：中端手机（如 iPhone 11、骁龙 7 系）在高或中档下稳定 60fps；桌面高档运行，帧时间 ≤ 6 ms。

**单帧预算（16.6 ms）**

| 项 | 预算 |
|---|---|
| 逻辑与物理（2 个 120 Hz 步） | ≤ 2.5 ms |
| 粒子与拖尾更新、批次构建 | ≤ 3 ms |
| GPU（中档） | ≤ 7 ms |
| DOM（HUD 仅在数值变化时写入，只用 transform 和 opacity） | ≤ 0.5 ms |
| 余量 | ≥ 3 ms |

**数量上限**

| 对象 | 上限 |
|---|---|
| 主球 / 碎片球 / 回响球 | 12 / 60 / 16（合计 ≤ 88，常态 20–60） |
| 砖块 | 屏上最多 22 × 7 = 154，对象池 200 |
| 粒子 | 1800 / 1200 / 700（随画质档位） |
| 晶体 | 250（超出时合并） |
| 敌弹 | 120 |
| 浮字 | 48 |
| 每帧精灵四边形 | ≤ 8192，超出时自动分批 flush |
| draw call | ≤ 12（背景 1 + 世界 1–2 + 扫描线 1 + 后处理 4） |

**策略**
1. **零分配热路径**：对象池加 SoA 类型化数组；事件对象池化；热循环中不用闭包、`map/filter` 和临时向量（数学函数通过 out 参数返回）；HUD 文本只在变化时写入。
2. **一张图集、一种混合模式**：预乘 alpha 的普通与加色共批，整帧几乎不切换状态。
3. **顶点格式紧凑**：每个顶点 20 字节（位置 2f + UV 2f + 颜色 4ub）；静态索引缓冲；动态 VBO 用 `bufferSubData` 只上传本帧实际用到的长度。
4. **碰撞 O(1)**：砖块网格直查；球与球不碰撞；球与敌弹每个物理步检测一次。
5. **按负载降级拖尾**：屏上超过 30 颗球时，拖尾点数减半，外层光晕减为一层。
6. **自适应画质**：§2.3。启动时如检测到 `navigator.hardwareConcurrency ≤ 4` 且为触屏设备，直接从「中」档起步。
7. **烘焙分帧**：图集烘焙拆成约 6 个任务，用 `requestIdleCallback`（不支持时用 `setTimeout`）在标题页空闲时执行，每帧 ≤ 8 ms，不卡标题动画。
8. **音频限流**：按类别限流（§2.6），活动节点 ≤ 32；跳伤、撞墙这类高频事件做概率抽样。
9. **首包**：无运行时依赖，debug 模块分包，字体只打包 woff2 的 latin 子集，合计约 90 KB gzip。3 秒内可开始游戏。
10. **验收方法**：Chromium 开 CPU 4× 降速，用 `?debug=1&seed=7&wave=17&autoplay=1` 跑 60 s 记录 p95 帧时；用 Performance 面板检查 GC（目标是 60 s 内没有超过 2 ms 的 Minor GC 尖峰）。

## 11. 实现偏差记录（阶段 2）

实现基本照本文档完成。下面列出与正文不一致之处和原因，以代码中的 `config.ts` 为准。

**数值（由 autoplay + simulate 批量调出）**
- Boss HP：方碑 1500、脉冲星 4200、霓蛇 22000、终焉之核 30000。12 个种子的中位用时：方碑约 50 s，脉冲星约 65 s；全局 394–1330 s，12/12 通关。
- 脉冲星扇形弹幕的张角为 60°、弹速 190 u/s；它的子星相位错开半个周期。终焉之核的螺旋弹为每臂 7 发/s；它的护盾格要打 3 下，8 s 后再生。
- 霓蛇触底伤害为 2。首局 T5 引导时 HP 为 20；引导期间砖块越线不扣血。
- Boss 弹会被砖块挡住。霓蛇身体用绳索跟随（不按轨迹回放），在 HUD 下方淡入。
- 击败 Boss 额外奖励一次升级。

**界面**
- HP 数字移到标签行右侧，避免与波数重叠。
- 结算分数字号为 52 u（72 u 放不下 7 位数），GAME OVER 描边背景字为 34 u。出现「新纪录」印章时，「最高分」行淡出，数据行下移让出位置。
- Boss 名牌加了深色渐变底，「BOSS DOWN」横幅、标题 Logo 和各类横幅都用 DOM 实现。
- 浮字的 y 不高于 92 u，x 限制在 30–360 u，以免被 HUD 遮住。连击里程碑环按档位着色；「完美」「MAX」字样有节流。
- 旋转提示只在触屏上出现；k 写成小写；开始按钮的呼吸效果做在辉光上；转场为 0.28 s 扫光加 0.28 s 幕布。
- 数据流背景为程序生成，十六进制字形用伪位图。

**技术**
- WebGL 不可用时，显示 `nogl` 兜底页（`scene=nogl`）。
- 在软件渲染（SwiftShader）下，GL 画布不进 DOM。每帧经 PBO + fence 回读到 2D 画布，并用 fence 背压：上一帧回读完成才渲染下一帧，看门狗 2 s。fps 和自动降档按实际呈现的帧计。
- 波次导演逻辑分在 `game.ts` 与 `app.ts` 两处。debug 接口另加了 `startRun()`。autoplay 在升级界面停留 0.7 s 后自动选卡，选卡时更看重「多球」。
- Boss 血量判定加了 epsilon 修正，避免出现残血 0 的情况。
