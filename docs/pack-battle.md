## 1. 一句话卖点与体验目标

**一句话卖点：** 在木桌上把俄罗斯方块形状的装备塞进皮革背包，摆对位置就会亮起加成连线，然后看它们自己打完一场噼啪作响的桌游式乱斗。

**核心爽点（按优先级）**
1. **摆放的手感**：拿起时装备挂在手指下摆动，放下时弹一下落进格子，"咔"地卡到位。
2. **连线的顿悟**：把磨刀石挨着剑一放，两件之间亮起一道流光，攻速 +25% 的字飘起来，玩家马上就懂了相邻加成。
3. **看自己的作品打架**：冷却环转满，装备闪光弹起，墨迹斩击飞向对面的纸板立牌，血条扣下去还留一截残影。

**一局时长**：10–14 分钟（10 轮，每轮整理约 40 秒、战斗 10–25 秒（1× 速度）、转场与结算约 6 秒；输了重打会多 1–2 轮）。

**情绪曲线**

| 阶段 | 轮次 | 玩家感受 | 设计手段 |
|---|---|---|---|
| 上手 | 1–2 | "原来这么简单" + 第一次加成很爽 | 引导里亲手搭出剑+磨刀石；对手很弱，稳赢 |
| 第一次受挫 | 3–4 | "得针对对手调整" | 毒蛛的中毒无视护盾；骷髅护盾很厚，逼你想战锤或中毒 |
| 首个高潮 | 5（首领） | 紧张，可能掉一颗心 | 食人魔半血狂暴，红灯、震屏、"狂怒！"印章 |
| 成型 | 6–7 | 构筑有了方向，合成到 ★★/★★★ | 商店里能合成的卡带"可合成"标签；稀有度提升 |
| 精通考验 | 8–9 | "我的背包能扛住吗" | 黑骑士减伤、游侠冷箭，克制关系更明显 |
| 终极高潮 | 10（首领） | 史诗感，赢下后释放 | 古龙半血喷龙炎、余烬粒子，通关证书和满背包战利品 |

## 2. 技术选型

| 领域 | 选型 | 理由 |
|---|---|---|
| 构建 | **Vite 8.3.4**（`~8.3.4`）+ **TypeScript ~5.9.3**（strict） | 遵守共同约定。TS 7（原生编译器）7 月才发布，工具链兼容性还在变，选成熟的 5.9。Vite 8 要求 Node ≥ 22.12，当前环境 22.22，满足 |
| 渲染 | **原生 Canvas 2D**，单个全屏 canvas，加离屏缓存分层 | 手绘风需要逐像素生成纹理（纸、皮革、木纹）和变宽墨线，本来就要用 Canvas 2D。同屏对象少（≤ 60 件装备、≤ 300 个粒子），用不着 WebGL。不引入 Pixi/Phaser，首包体积可控 |
| UI | 也画在 Canvas 里（自写的轻量控件：按钮、开关、面板、气泡） | 每个界面元素都能统一墨线抖动、纸纹、蜡封质感，转场也好做。`window.__game.ui()` 导出所有可点区域的屏幕坐标，方便 Playwright 操作 |
| 动画 | 自写 `tween.ts`（缓动函数）+ `spring.ts`（弹簧-阻尼，固定 120Hz 子步） | 惯性摆动和弹性落位本质都是弹簧，GSAP 这类库解决不了，自写约 250 行 |
| 拖拽 | 原生 Pointer Events + `setPointerCapture`，自写手势识别（轻点/长按/拖拽/第二指轻点） | 鼠标、触屏、Playwright 共用一套代码 |
| 音频 | 原生 WebAudio 实时合成（振荡器、噪声、滤波、包络、Karplus-Strong 拨弦、生成的混响脉冲） | 共同约定要求全程序化，不需要 Tone.js（太大） |
| 随机 | 自写 sfc32 + 字符串哈希派生流 | 支持 `?seed=`，商店掷骰可复现 |
| 字体 | `@fontsource/patrick-hand@5.3.0`（latin 400，woff2 24KB）用于数字和英文；`@fontsource/kalam@5.3.0`（latin 700，woff2 22KB）用于 Logo 和大标题 | 合计 46KB，低于 150KB 上限。**不 import 包里自带的 css**（它会把 .woff 一起打包），而是在 `styles.css` 里自写 `@font-face`，只 `url()` 引用 woff2 文件 |
| 数值验证 | `scripts/balance.ts`，用 Node 22 直接跑 TS（已实测原生类型剥离可用） | 战斗模拟是纯函数，可以离线批量跑参考构筑。需要 `allowImportingTsExtensions` + `erasableSyntaxOnly`，不用 enum/namespace |

## 3. 核心循环、完整规则与初始数值

### 3.1 核心循环

```
标题 ─▶ [第 r 轮] 收入账单 ─▶ 整理阶段（买 / 摆 / 转 / 合成 / 卖，不限时）─▶ 点「开战」
        ▲                                                                   │
        │                    ┌──────── 胜：r+1（r=10 → 通关结局） ◀─────────┤
        └────────────────────┤                                             ▼
                             └──────── 负：失去 1 颗心，重打同一个敌人 ◀── 自动战斗（回放）
                                       （心 = 0 → 失败结局）
```

- **1 局 = 打赢 10 个敌人**，**3 颗心**。每场战斗双方都满血开局，生命不跨轮保留。
- **输了不前进**：失去 1 颗心，回到整理阶段，照常领本轮收入外加失败补偿，然后再打**同一个敌人**。对手的背包全程公开，所以输了能针对性调整，这是设计重点。
- "轮次"指第几个敌人（1–10）；同一轮第几次挑战记为 `attempt`，HUD 上显示"再战"小标签。

### 3.2 背包、暂存与相邻

- **背包**：6 列 × 5 行，共 30 格（`BAG.cols=6, rows=5`）。用户说的"5×6"在竖屏下按宽 6 高 5 实现，更省纵向空间；改 config 就能换成 5×6。
- **桌边暂存**（stash）：背包下方的木桌上有 5 个槽位（`SHOP.stashSlots=5`）。暂存的装备**不参战**，跨轮保留；放进去不限形状，按比例缩小显示。
- **相邻的精确定义**：A、B 两件装备只要有至少一对格子**共享一条边**（上下左右），就算相邻；只碰到对角不算。同一对装备不管共享几条边，都只算 **1 次**。只有背包内的装备参与相邻计算。
- **方向性**：只有「号角」一件。号角占 2 格，有"尾"和"口"两端，从尾指向口就是号声方向。从口格沿这个方向一直到背包边缘，这条线上所有被占据的格子所属的装备（去重，不含号角自己）都获得加成。号声能穿过中间的装备。旋转号角就会改变方向。
- **加成叠加**：同类加成相加（两块磨刀石 = +50%）。攻速/冷却速度的总倍率 = 1 + Σ加成，**上限 ×3**（`BATTLE.speedCap=3`）。

**装备定价（按稀有度定基准，再按格数/强度微调，具体见装备表）**：普通 3–4，精良 5–6，稀有 7–8，传说 10–11。

**累计金币预期**（全胜、无利息无钱袋）：第 1 轮 12 → 2 轮共 22 → 3 轮 33 → 5 轮 56 → 7 轮 81 → 10 轮约 122。大约能买 22 件（含合成材料），背包最终能摆下 10–13 件，"空间"逐渐成为真正的约束。

**商店规则**
- 5 个槽位（`SHOP.slots=5`）。每个槽先按轮次权重掷稀有度，再在该稀有度内均匀选一件（不含敌人专属装备）。
- 玩家已拥有（背包或暂存）、且等级 < 3 的同名装备，被选中的权重 ×1.6（`SHOP.ownedWeightMul`），合成更容易凑齐。
- 同一次商店里同名装备最多 2 件（`SHOP.maxDupPerShop=2`）。
- 第 1–3 轮保底至少 1 件武器（`SHOP.weaponGuaranteeUntil=3`）：没掷到就把最后一个槽换成随机普通武器。
- 商店掷骰的随机流 = `hash(seed, round, attempt, refreshIndex)`，同种子同操作下结果完全一样。

**说明与边界**
- "伤害 +X"是加在每一下打击上的（回旋镖两下都加）。"×1.5"在所有加法之后计算，然后向下取整。
- 月光石只增强**护具和药物**自身产出的护盾量/回复量（含开场护盾、药水、炼金釜、复活生命），不增强铁剑的攻击附带护盾（铁剑是武器），也不增强铁盔减伤。结果向下取整。
- 长弓的"相邻空格"= 背包内与长弓共享边、且没有被占据的格子；背包边缘外不算。拿起长弓时这些空格上会出现铅笔小圆点和"+2"。
- 雷霆之杖的"任意装备"按件数计，不分标签。
- 钱袋在战斗中没有效果。整理开始时结算的是**上一次开战那一刻**在背包里的钱袋。

### 3.5 合成

- **怎么合成**：把一件装备拖到**同名、同等级、且等级 < 3** 的另一件上，松手就合成。目标会提前显示金色脉冲描边和"合成 ★★"印章。
- **判定**：抓取格（按下时手指所在的那个装备格）的视觉中心落在目标装备的任意一格上，就进入合成模式，优先级高于普通摆放。
- **来源不限**：背包→背包、暂存→背包/暂存、**商店→背包/暂存**（买和合成一步完成，钱不够时拿不起来）。点商店卡打开详情，如果已拥有可合成的同级装备，按钮会显示「购买并合成」，自动并入那件（优先背包里的）。
- **结果**：目标升 1 级，保留**目标的位置和朝向**，形状不变；被拖的那件消失；`value` 相加。
- **不能合成的情况**：等级不同（目标抖动，提示"需要同等级"）；已满 ★★★（目标变灰，提示"已满级"）；名字不同时按普通摆放处理（重叠就判为非法）。
- **视觉**：被拖件吸入目标 → 目标压扁弹起 → 白闪 → 星芒和纸屑爆开 → "★★"墨章盖下。★★ 卡片描银色双线；★★★ 描金色双线，每 3 秒有一道光扫过。

### 3.6 战斗规则

**整体做法**：点开战后，先用固定步长把整场战斗**一次性模拟完**（<5ms），得到事件时间线 `BattleEvent[]`，再按时间回放给画面。逻辑和表现彻底分离：结果确定、可以测试、可以快进。

**模拟步骤**（`BATTLE.dt = 1/60` 秒，模拟时间）
1. **t=0 开场**：先玩家、后敌人，依次结算 `start` 类装备（皮甲、龙鳞）。所有冷却计时从 0 开始。
2. **每个 tick**：
   1. 处于眩晕的一方，眩晕计时减少，**它的装备计时本 tick 不推进**（中毒照常结算）。
   2. 其余装备的计时 += dt × 速度倍率（1+Σ攻速/冷却速度加成，上限 3；首领狂怒的加成也算在里面）。
   3. 收集计时 ≥ cd 的装备，按以下顺序结算：越早越过阈值的越先（超出量/倍率越大越早）→ 同时则玩家先 → 再按装备左上角格的阅读顺序。每件结算后计时 −= cd。
   4. 处理到期的延迟打击（回旋镖第二下，在第一下 0.3s 后）。
   5. 每结算完一件就检查死亡；有人倒下（且没有复活）**立即结束**，本 tick 剩下的触发作废。
   6. 中毒：每方各有一个 2.0s 的中毒计时（`BATTLE.poisonInterval`），到点受到 = 层数 的伤害。**双方同时结算**后再检查死亡。
   7. 风暴（超时）见下文。
3. **伤害结算**（一下打击）：基础伤害 + 加法加成 → 乘法（独行 ×1.5）→ 向下取整 → 减去目标减伤（铁盔/龙鳞），**最低 1**（`BATTLE.minHit`）→ 先扣护盾再扣生命。
   - 战锤：目标有护盾时，每 1 点伤害削 2 点护盾；护盾削光后，剩余伤害按 1:1 扣生命。
   - 中毒和风暴伤害**无视护盾和减伤**。
4. **护盾**：累加，**不衰减**，没有上限（风暴无视护盾，所以不会出现无限拖时间）。
5. **回复**：不超过最大生命，溢出浪费（显示小字"满"）。
6. **条件触发**：每次扣生命后检查。治疗药水：生命 ≤ 50% 且未用过时触发；有多瓶时一次只触发一瓶，下一次扣血后才轮到下一瓶。凤凰羽毛：生命 ≤ 0 且未用过时，生命设为 ⌊最大生命 × 比例⌋，清空中毒，战斗继续（风暴致死也能触发）。
7. **状态效果**（只有两种，克制使用）：
   - **中毒**（紫色）：层数累加、不衰减，每 2 秒造成"层数"点伤害，无视护盾。炼金釜每次触发解除 N 层，凤凰复活时清空。
   - **眩晕**（黄色）：目标一方所有冷却计时暂停。再次眩晕取剩余时间和新时间中较大的那个，不叠加；眩晕结束后 0.5s 内免疫（`BATTLE.stunImmunity`），避免永久控制。
8. **时长上限**：`BATTLE.softLimit = 30s` 时沙漏耗尽，进入**风暴**：之后每 1 秒双方同时受到 2k 点真实伤害（k = 风暴第几跳，`BATTLE.fatigueStep = 2`）。同时倒下时，剩余生命（可以是负数）更高的一方胜；完全相同判玩家胜。`BATTLE.hardLimit = 60s` 保底：按剩余生命百分比判胜负，相同判玩家胜。
9. **胜负**：敌人生命 ≤ 0 → 玩家胜；玩家生命 ≤ 0（且没有复活）→ 玩家负。同一 tick 内按结算顺序，先倒下的输。

**首领特性 `EnemyDef.traits`**
- `enrage`（食人魔）：生命首次 ≤ 50% 时，所有装备速度倍率 +50%。
- `dragonRage`（古龙）：生命首次 ≤ 50% 时，立刻对玩家造成 20 点真实伤害（"龙炎"），之后所有装备速度倍率 +30%。

**回放与加速**
- 回放时钟 = 真实 dt × 速度 × timeScale；hitstop 期间回放时钟冻结。
- 速度按钮在 **1× → 2× → 4×** 之间循环（`BATTLE.speeds`），会记住设置。投射物飞行时间 = 0.22s / √速度。
- 血条、护盾数字等"显示值"在投射物命中时才变化。最后一个事件显示完 0.6s 后出结算。
- 首局第一场的前 2.5 秒以 0.6× 播放（`TUTORIAL.slowmo`），让新手看清冷却环。

### 3.8 失败、胜负与计分

- **心**：3 颗（`PLAYER.hearts`）。输一场掉 1 颗；掉光后进入失败结局，显示"冒险终结于第 N 轮"和击败你的敌人立牌。
- **通关**：打赢第 10 轮古龙后进入通关结局（证书 + 装满战利品的背包）。
- **计分**（`SCORE`）
  - 每赢一场：`winBase 100 × r` + `round(winHpBonus 40 × r × 剩余生命比例)`
  - 通关：`clearBonus 2000` + 每颗剩余的心 `heartBonus 500`
  - 输掉的场次不加分也不扣分
  - 理论上限：140 × 55 + 2000 + 1500 = 11200
- **最高分**：本地保存 `{score, round, cleared, date}`。结算时显示历史最高；破纪录会盖"新纪录！"印章并撒纸屑。
- **趣味统计**（结局页 3 行）：最痛一击、合成次数、总花费。

### 3.10 数值校准方法

- **弱**构筑：第 1–2 轮能赢，之后大多会输。
- **中**构筑：每轮都赢，但只剩 15–50% 生命（第 5、10 轮首领允许 50% 的构筑变体输）。
- **强**构筑：稳赢，剩余生命 50% 以上。
- 战斗时长：第 1–3 轮 6–12s，第 4–7 轮 10–18s，第 8–10 轮 14–25s。

只调 config 里的敌人生命、敌人装备等级/布局和少量装备数值，不改规则。

### 4.2 字体

- **Logo 拉丁字**：Kalam 700。字母逐个旋转 ±3°，基线上下抖 ±2px；羊皮纸色填充、5px 墨描边，再加一层 (3,4) 的深色投影。
- **数字/英文**：Patrick Hand 400（金币、生命、伤害跳字、价格、计时、速度）。
- **中文**：系统字体栈 `"PingFang SC","Hiragino Sans GB","Microsoft YaHei","Noto Sans CJK SC",sans-serif`。字号：正文 13–15px，按钮 18–22px（字重 700，字距 2px），标题 20–28px（字重 900）。
- **混排**：`font-family: "Patrick Hand", <中文栈>`，数字自动用手写体，汉字回落到系统字体。
- **"手写感"中文标题**：字重 900，3px 墨描边，整体旋转 −2°，加 1–2px 的错位印刷投影（蜡封红偏移 2px，透明度 35%）。
- 浅底（纸）上用墨色字；深底（木、皮）上用羊皮纸色字 + 3px 墨描边。

### 4.3 手绘风格的程序化实现

全部在启动时生成到离屏 canvas 并缓存；运行时只做 `drawImage`，不读写像素。

| 元素 | 做法 |
|---|---|
| **噪声基础** | 带种子的 value noise、fbm（3–4 个八度）、worley（F2−F1），见 `render/noise.ts` |
| **木桌** | 生成 256×512 的竖向纹理贴片，再放大 2 倍（木纹本身柔和，可以低分辨率）：每像素 `v = sin((x·0.045 + fbm(x·0.01, y·0.0025)·5) · 2π)`，在木桌主色和木桌亮之间插值；用暗色细线画年轮。上面用全分辨率矢量补细节：每 ~110px 一块木板，板缝 = 暗线 + 1px 亮线；随机 1–2 个木节（椭圆扭曲 + 同心环）；每块木板色调差 ±4%。最后叠加：顶部中央暖灯径向渐变（`soft-light`，18%）+ 四周暗角（`multiply`，边缘 60%）。按视口尺寸缓存成一张背景图，resize 时重建 |
| **皮革** | 256×256 贴片：fbm 细颗粒（比例约 3px）`multiply` + worley 卵石纹（阈值后 15% 透明度）+ 随机浅色细划痕 + 边缘抛光加深。外框形状：圆角 18 的矩形，边缘亮部在左上、暗部在右下，加内阴影 |
| **缝线** | 沿外框内缩 7px 的路径，每 10px 一针：6px 长的圆头短线（缝线色），每针随机偏转 ±4°，下方 1px 深色阴影，两端各一个深色小针孔 |
| **黄铜** | 线性渐变 `#f1cf7a→#c8963e→#8a6224` + 墨描边 + 一道白色高光短弧 + 铆钉小圆点。用于包角、扣具、按钮边 |
| **羊皮纸** | 256×256 贴片：底色 + fbm 污渍（纸阴影色，低频）+ 纤维（随机 1px 短弧，4% 透明度）+ 四周向内的焦边渐变。面板边缘做**毛边**：沿边每 6px 一个点，向内随机缩进 0–2.5px，连成多边形，再描 1px 纸焦边色 |
| **墨线抖动** | `ink.stroke(points, w)`：按 6px 重采样，每点沿法线偏移 `noise(seed+i)×1.0px`；用**变宽带状多边形**填充，宽度 `w(t)=w·(0.65+0.35·sin πt)·(1+0.12·noise)`，两头自然收尖；再叠一遍偏移 0.6px、透明度 0.5 的细线，模拟干笔。矩形、圆、任意 Path2D 都走这个函数 |
| **线条沸腾** | 手绘动画里常见的"线条蠕动"：关键元素（Logo、高亮按钮、引导手势、加成连线）每 120ms 换一次抖动种子（约 8fps）。缓存 3 帧变体循环播放，几乎没有额外开销。`prefers-reduced-motion` 时关闭 |
| **排线阴影** | `ink.hatch(path, angle=-45°, gap=4, alpha=.25)`：裁剪到形状内，只在暗部（右下）画平行抖动细线；重阴影加一层 +45° 交叉线 |
| **水彩填色** | 先平涂底色，再在形状内描一圈 3px 加深色（透明度 0.25，往内两次递减）模拟水彩积边，最后叠一层羊皮纸贴片（`multiply`，裁剪在形状内）带出纸纹 |
| **蜡封** | 半径加噪声的不规则圆，填蜡封红；内圈压印环；中间是浮雕字形（亮边 + 暗边）；左上一道镜面高光 |
| **麻布 / 柳条 / 铁皮**（敌人背包） | 麻布：横竖两组正弦纹相乘；柳条：斜向交错的胶囊形；铁皮：拉丝噪声 + 铆钉 |

**装备卡片（tile）**
- 底板 = 多格形状的并集轮廓：先描出外边界（正交多边形），向内偏移 3px，凸角用 `arcTo` 做半径 6 的圆角，凹角保持直角。
- 底板填羊皮纸，并按稀有度轻微着色：普通原色；精良偏青 `#e3ece0`；稀有偏靛 `#dfe5ef`；传说偏金 `#f5e2b8` + 金箔边。
- 2px 抖动墨线描边。格与格之间画淡铅笔点线，让玩家一眼看出占几格。
- 右上角格放稀有度宝石点（普通没有）；左上角格盖等级星章（★ / ★★ / ★★★）。
- 每张卡缓存为 `(itemId, level)` → 在 cell=54 × DPR 下画一次；其他尺寸（战斗 46、敌人 34、商店约 20）用高质量缩放 `drawImage`。旋转在运行时用 `ctx.rotate`。阴影精灵（模糊过的剪影）单独缓存。

**装备图标的绘制思路**
- 每件装备一个 `draw(ctx, box)` 函数，在"格子单位"坐标系下绘制（I3 的剑：刃从 (0.5,0.12) 到 (0.5,2.25)，护手在 y=2.3，握柄到 2.8，配重球在 2.9）。
- 共享图元（`icons/primitives.ts`）：刀刃（长度、宽度、弧度、血槽）、缠绕握柄（斜线绑带）、黄铜护手、宝石（多面切割 + 高光）、玻璃瓶（瓶身轮廓 + 液面 + 高光）、木头（木纹线）、金属（渐变 + 高光条）、布料（褶皱线）、叶子。
- 统一流程：水彩填色 → 排线阴影 → 高光（左上一道亮笔触）→ 抖动墨线描边。
- ★★：图标边缘加银色细描边，加 1 个小闪光；★★★：金色描边，宝石镶嵌，柔光。

## 5. 动效清单

### 5.1 强度层级

| 层级 | 震屏 trauma | hitstop | 震动 `navigator.vibrate` | 用于 |
|---|---|---|---|---|
| T0 微 | 0 | 0 | 无 | UI 点击、悬停 |
| T1 轻 | 0.12 | 0 | 6ms | 落位、普通受击 |
| T2 中 | 0.25 | 30ms | 12ms | 大伤害、护盾击破、合成 ★★ |
| T3 重 | 0.45 | 80ms | 25ms | 击杀、合成 ★★★、药水急救、新纪录 |
| T4 极 | 0.70 | 160ms | [40,30,60] | 首领阶段转换、凤凰复活、玩家倒下 |

震屏用 **trauma 模型**：偏移 = 10px × trauma² × 柏林噪声(t)，旋转 = 1.2° × trauma² × 噪声；trauma 每秒衰减 1.5，上限 1。HUD 只承受 40% 的震动。设置里可以关闭；`prefers-reduced-motion` 时减到 30%。整理阶段**不用** hitstop。
**防止高频小事件叠成持续抖动**：T1 的 trauma 增量有 150ms 冷却，两次手机震动至少间隔 200ms；hitstop 进行中又来一个 hitstop，取较长的，不累加。

### 5.3 拖拽物理（惯性摆动 + 弹性落位）

所有弹簧都用半隐式欧拉，**固定 120Hz 子步**：`a = ω²(target − x) − 2ζω·v; v += a·dt; x += v·dt`。

### 5.4 加成发光连线的绘制

- **端点**：在 A、B 之间找一对**相邻的接触格**（a∈A，b∈B，取离两件形状质心都最近的一对），连线从 a 的中心画到 b 的中心。线很短，不会满屏交叉。
- **路径**：二次贝塞尔曲线，控制点沿 A→B 的左侧法线偏移 0.18×|AB|（固定朝一侧，两条线不会重叠）；分成 10 段，每段加 0.8px 的法向噪声，以 10fps 沸腾。
- **三遍描边**（叠在装备上方，`globalCompositeOperation='lighter'`，**不用 shadowBlur**）：外层宽 10px、透明度 0.18；中层宽 5px、透明度 0.35；芯线宽 2px、颜色向 `#fff3c4` 偏、透明度 0.9。线帽圆头。
- **流光**：2 颗预渲染的径向渐变光点（10px）沿曲线从源流向目标，速度 0.9 个全程/秒，两颗相位差 0.5。互相加成的（铁剑↔木盾）两个方向各一颗，颜色分两段。
- **端点符文**：两端各一个半径 4 的小圆环，缓慢脉动。
- **颜色按受影响的数值**：攻速/冷却 琥珀 `#f0a83a`；伤害 朱红 `#d65a3a`；护盾 钢蓝 `#6f9cc4`；回复 苔绿 `#8fbf4f`；中毒 紫 `#9b6cc0`；沙漏 金 `#f3cf6a`；月光石 青 `#4fa49a`。
- **生长/断开**：新建时用 `setLineDash([L, L])` + `lineDashOffset = L×(1−t)` 在 250ms 内画出来，然后闪一下；断开时 200ms 淡出并滴下墨点。
- **拖拽预览**：按"假设放在这里"的布局算出连线，画成 50% 透明度、呼吸闪烁的虚线；会新增的加成旁边标"+25%"。
- **号角**：不画连线，改为从号口沿线传出的 3 道声波弧")))"（每 0.8s 一组），线上的格子铺一层淡琥珀色，受影响的装备右上角亮一个小环。
- **长弓**：拿起或选中时，相邻空格显示铅笔小圆点和"+2"。
- **战斗中**：某次触发用到了某条加成，那条连线就闪一下（芯线透明度 1，宽 ×1.5，持续 120ms），让玩家看到"是磨刀石让剑更快"。

### 5.5 音频

- **结构**：`master → DynamicsCompressor → destination`；音效总线 0.8，音乐总线 0.35；共享一个卷积混响（启动时生成 1.2s 的衰减噪声脉冲，模拟小酒馆），音乐和部分音效接发送。
- **噪声**：预生成 1s 白噪声 buffer，复用。
- **限流**：同一音效最短间隔 30ms；同时最多 24 个声部，超出时抢占最老的；4× 速度下次要音效（命中、护盾）按 50% 概率跳过。
- **拨弦**：首次用户手势解锁后，用 Karplus-Strong 离线生成约 15 个音（D3–D5）的 AudioBuffer（每个约 0.8s），供音乐和弓弦音效使用。
- **程序化音乐**（lookahead 100ms 调度，切换时 600ms 交叉淡化）：
  - 整理「旅店小调」：D 大调，84 BPM，8 小节 D–A–Bm–G｜D–G–A–D；拨弦分解和弦（八分音符），低八度拨弦贝斯在 1、3 拍，沙锤（高通噪声十六分音符，很轻）。
  - 战斗「擂台鼓点」：同样的和弦，112 BPM，加手鼓（正弦 90→50Hz + 噪声拍）在 1、2&、3、4 拍，铃鼓（8kHz 带通噪声）。
  - 首领：D 小调 Dm–B♭–C–A，100 BPM，低音持续音（两路失谐锯齿波 → 300Hz 低通 + 慢速 LFO），太鼓（正弦 60Hz 下滑 + 噪声），拨弦更稀疏。
  - 胜利/失败短乐句见 5.2。首领入场、凤凰复活时音乐压低 4dB，持续 200ms。
- **解锁**：第一次 pointerdown 时创建/恢复 AudioContext；页面隐藏时 suspend。音效、音乐分别有开关，存在本地。

### 6.1 屏幕适配与坐标系

- 用 CSS 读取 `env(safe-area-inset-*)`，得到可用区域 aw × ah。

- 下面的坐标都按 **Hlog = 844** 给出。Hlog 在 760–844 之间时，按比例压缩"弹性间距"（每组之间的空隙和底部留白），商店卡高度 122→110；Hlog > 844 时，多出的高度分配到弹性间距里。
- 游戏区外面是同一张木桌背景的延伸（不是白边，也不是黑边）。
- canvas 铺满视口，DPR 上限 2；如果总像素数 > 420 万，自动降低 DPR。

```ts
interface ItemDef {
  id: ItemId; name: string; tag: Tag; rarity: Rarity; price: number;
  shape: string[];                 // rot0，如 ['##','#.','#.']
  mouth?: [number, number];        // 号角口格（rot0 坐标）
  trigger: Trigger; cd?: number; shieldBreak?: number; // 战锤 = 2
  lv: [LevelStats, LevelStats, LevelStats];
  adj: AdjRule; enemyOnly?: boolean;
  text: { effect: string; adj: string };   // 含 {dmg} 等占位
}
interface ItemInst {
  uid: number; id: ItemId; lv: 1 | 2 | 3; rot: Rot;
  zone: 'bag' | 'stash'; x: number; y: number; slot: number; // 背包坐标或暂存槽
  value: number; boughtStamp: number;                       // 用于全额退款判断
}
interface ShopSlot { id: ItemId | null; price: number; }
interface RunState {
  seed: number; round: number; attempt: number; hearts: number; gold: number; score: number;
  phase: 'receipt' | 'arrange' | 'toBattle' | 'battle' | 'result' | 'ending';
  bag: ItemInst[]; stash: (ItemInst | null)[]; shop: ShopSlot[]; locked: boolean;
  refreshIndex: number; lastResult: 'win' | 'loss' | null; pouchGold: number;
  stats: { bestHit: number; merges: number; spent: number; roundScores: number[] };
}
interface Derived {                // synergy.ts 输出
  uid: number; cd: number; speedMul: number; dmg: number; hits: number; shield: number;
  shieldOnHit: number; heal: number; poison: number; cleanse: number; stun: number;
  reduce: number; reviveFrac: number; startShield: number; lowHpHeal: number;
  sources: { uid: number; label: string }[];   // 明细，用于详情卡
}
interface Link { id: number; kind: 'speed' | 'dmg' | 'shield' | 'heal' | 'poison' | 'boost' | 'hourglass';
  from: number; to: number; a: [number, number]; b: [number, number]; mutual: boolean; label: string; }
interface EnemyDef { round: number; name: string; title: string; hp: number; cols: number; rows: number;
  frame: FrameStyle; bag: { id: ItemId; lv: 1 | 2 | 3; x: number; y: number; rot: Rot }[];
  traits: ({ kind: 'enrage'; at: number; speed: number } | { kind: 'dragonRage'; at: number; trueDmg: number; speed: number })[];
  hint: string; portrait: PortraitId; boss?: boolean; }
interface BattleEvent {
  t: number; type: 'start' | 'fire' | 'hit' | 'shield' | 'heal' | 'poisonApply' | 'poisonTick' | 'cleanse'
    | 'stun' | 'lowHp' | 'revive' | 'phase' | 'fatigue' | 'end';
  side: 0 | 1; uid?: number; amount?: number; absorbed?: number;
  hp: [number, number]; shield: [number, number]; links?: number[];
}
interface BattleResult { winner: 0 | 1; duration: number; events: BattleEvent[]; hpEnd: [number, number]; }
```

**分层原则**：`game/` 只有纯数据和纯函数，通过 `bus` 发事件（`bought`、`placed`、`merged`、`linkAdded`……）；`render/` 和 `audio/` 订阅事件来表现。`battle/sim.ts` 可以被 `scripts/balance.ts` 和 `__game.simulate()` 直接调用。

## 8. 调试接口

URL 参数：
- `?debug=1`：左上角 DOM 浮层显示 `FPS · 帧时间 ms · seed · 第 r 轮 · 阶段 · 粒子数`，并挂载 `window.__game`。
- `?seed=<数字>`：固定种子（不填则用时间戳，结局页会显示种子）。
- `?debug=1&round=7`：直接以"中"参考构筑进入第 7 轮整理（方便审查）。
- `?debug=1&notut=1`：跳过引导。

`window.__game` API（坐标一律返回 **CSS 像素**，可以直接交给 Playwright 的 `mouse`）：

| API | 作用 |
|---|---|
| `state()` | 当前快照：阶段、轮次、attempt、心、金币、分数、背包（id/lv/rot/x/y）、暂存、商店、锁定、敌人 |
| `ui()` | 当前所有可交互元素 `{id, x, y, w, h, enabled}`，例如 `btn.start`、`btn.fight`、`btn.refresh`、`btn.lock`、`btn.pause`、`btn.speed`、`btn.continue`、`shop.0`…`shop.4`、`stash.0`…、`enemyCard` |
| `cell(col,row)` / `shopSlot(i)` / `stashSlot(i)` / `itemRect(uid)` | 单个元素的屏幕矩形（中心可直接拖拽） |
| `addGold(n)` / `setGold(n)` / `setHearts(n)` | 资源修改 |
| `gotoRound(n, build?)` | 跳到第 n 轮整理阶段；`build` 为 `'none'`/`'weak'`/`'mid'`/`'strong'`（默认 `'mid'`，使用参考构筑） |
| `boss(5 \| 10)` | 跳到首领轮并装上"中"构筑 |
| `give(id, lv?, where?)` | 给装备：`'stash'`（默认）/`'bag'`（自动找空位）/`{x,y,rot}` |
| `place(id, x, y, rot?, lv?)` | 直接放进背包，返回 uid；位置非法时返回 null |
| `clearBag()` / `clearStash()` | 清空 |
| `setShop(ids[])` / `reroll()` | 指定商店货品 / 免费刷新 |
| `startBattle()` | 等同点击开战 |
| `winBattle()` / `loseBattle()` | 立刻以胜/负结束当前战斗（整理阶段调用则跳过战斗直接出结果） |
| `win()` / `lose()` | 直接进入通关 / 失败结局 |
| `simulate()` | 用当前背包对当前敌人模拟，返回 `{winner, duration, hpEnd, events: 数量}`，不影响状态 |
| `speed(x)` | 战斗回放速度（1–8） |
| `timeScale(x)` | 全局时间缩放（含动效） |
| `skipTutorial()` / `resetTutorial()` / `resetHints()` | 引导控制 |
| `fx(name)` | 手动触发某个反馈，供审查：`'shake1'`…`'shake4'`、`'merge2'`、`'merge3'`、`'revive'`、`'enrage'`、`'record'` |
| `items()` / `enemies()` | 返回配置表 |
| `seed` | 当前种子（只读） |

调用时机不合法（例如战斗中 `place`）返回 `{ok:false, reason}`，不会抛错，也不会产生控制台报错。

## 9. 性能预算与策略

| 项目 | 预算 |
|---|---|
| 首屏 | JS gzip ≤ 50KB、字体 46KB；标题首帧 < 1s（中端机 4G）；「开始」按钮首帧就能点 |
| 启动生成 | 木桌 + Logo ≤ 60ms（先画标题）；皮革、羊皮纸、当轮装备精灵在标题页空闲时分批生成（每帧 ≤ 6ms 的任务队列）；点开始时如果还没生成完，同步补完（≤ 100ms） |
| 每帧 CPU | 中端手机（如 iPhone 11 / Pixel 6）DPR 2 下 ≤ 6ms；绘制调用 ≤ 200 |
| 粒子 | 池上限 400，常态 ≤ 150；跳字池 40；Tween 池 256 |
| 内存 | 离屏缓存 ≤ 40MB（装备精灵约 26×3 张，按需生成） |

**策略**
- **分层缓存**：背景（木桌 + 暗角 + 桌面道具）按视口缓存为一张图；背包外框 + 格子缓存为一张；装备卡片按 (id, lv) 缓存；静态中文标签缓存成文本精灵，内容变化时才重画。
- **运行时不用** `shadowBlur`、`filter`、`getImageData`；发光用预渲染的径向渐变精灵 + `lighter` 叠加；阴影用预模糊的剪影精灵。
- **零分配热路径**：粒子、跳字、投射物、Tween 都走对象池；每帧复用数组；事件回放用游标，不 splice。
- **逻辑**：rAF 中 dt 限幅 50ms；弹簧固定 120Hz 子步（每帧最多 4 步）；战斗是预先模拟好的，回放没有计算压力。
- **自适应画质**：连续 2 秒平均帧时间 > 18ms → DPR 下调 0.25（最低 1），粒子上限减半，关闭线条沸腾。
- **后台**：页面隐藏时停止 rAF，挂起 AudioContext。
- **字体**：`document.fonts.load` 最多等 300ms，超时先用回退字体绘制，加载完成后让文本缓存失效并重绘。

## 10. 实现计划与风险

### 10.1 实现顺序（先做出可玩的核心循环，再上画面和动效）

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M1 骨架 | Vite 项目、stage（DPR、安全区、缩放）、loop、input、storage、rng、config、debug 浮层 | `npm run dev/build/preview` 正常，控制台干净 |
| M2 规则内核 | shapes、grid、synergy、shop、economy、battle/sim、enemies；`npm run balance` | 报表能跑通，参考构筑的胜负和时长大体符合 §3.10 |
| M3 可玩核心循环 | 整理阶段完整交互（拖拽/旋转/合成/出售/暂存/刷新/锁定）、战斗回放（简洁但整齐的画面）、结算、心、结局；`__game` 全部接口 | 用 Playwright 在 390×844 下靠指针事件打通一整局（含 `gotoRound` 跳关） |
| M4 美术 | 纹理、墨线工具、26 个装备图标、10 个立牌、行囊/摊位/HUD/面板、标题和 Logo | 每个画面截图都像成品 |
| M5 动效与音频 | 弹簧拖拽物理、加成连线、战斗特效、跳字、震屏/hitstop、粒子、转场、全部音效、程序化音乐 | §5.2 表格逐条核对 |
| M6 流程完善 | 引导和情境提示、暂停、设置、结局与新纪录、桌面侧边装饰 | 首次进入 30 秒内能完成引导并开打 |
| M7 打磨 | 数值校准、性能检查（自适应画质）、边界情况（§3.9 逐条）、Playwright 截图回归 | 稳定 60fps，零报错零警告 |

### 10.2 风险与对策

| 风险 | 对策 |
|---|---|
| 26 个图标 + 10 个立牌的绘制量大 | 用共享图元组合；先把 M3 用的"卡片底板 + 名称"占位做整齐；图标按出场顺序做（前 3 轮用到的优先）；立牌用参数化模板（头型、眼睛、配饰、配色） |
| 触屏旋转不好发现 | 引导第 3 步专门教；顶部详情条常驻"轻点旋转"提示（前两轮）；支持第二指轻点、R 键、右键、滚轮 |
| 小屏上格子太小、手指挡住 | 格子 ≥ 43px（最小缩放下）；拖拽上抬 48px；用视觉中心判定；落点预览明显 |
| 数值失衡（某套构筑无敌或首领打不过） | 战斗确定性 + 离线 balance 脚本；只动 config；输了重打同一敌人本身就是安全阀；首领的半血机制给玩家可见的应对窗口 |
| 战斗信息太多看不清 | 冷却环只在徽章格；4× 速度下削减次要特效和音效；跳字按数值分级；加成连线战斗中平时变暗，只在被用到时闪 |
| Canvas 手绘 UI 难以自动化测试 | `__game.ui()` 和各种 rect 接口导出屏幕坐标；所有操作都有指针路径 |
| 程序化纹理启动慢 | 低分辨率噪声 + 高分辨率矢量细节；分帧生成；标题页只依赖木桌和 Logo |
| 4× 速度下音效刺耳 | 声部上限、同音效限流、次要音效概率跳过、压缩器兜底 |
| 用户想要"5×6"竖版背包 | `BAG.cols/rows` 可以直接改；布局按格数自动算格子大小（格子 ≤ 54），文档里已说明为什么选 6×5 |

### 10.3 本版不做（刻意收窄）

- 不做中途存档（刷新页面这局就没了）；最高分、设置、引导标记会保存。
- 不做敌人随机变体（每轮敌人固定，方便学习和复盘）。
- 不做背包扩容和"背包类"道具；状态效果只有中毒和眩晕两种。
