## 1. 一句话卖点与体验目标

**卖点：举着烛火走进漆黑的地牢——每个数字都是周围怪物的等级之和。靠推理决定先打谁、何时喝药，一路升级，最后屠掉盘踞在中央的 13 级巨龙。**

| 项目 | 目标 |
|---|---|
| 一局时长 | 胜局 4–6 分钟（约 55 次翻格 + 10–15 次标记）；败局平均约 3 分钟 |
| 上手 | 30 秒引导局在操作中教会：数字 = 等级和、战斗扣血得经验、数字归零自动展开、「上限推理」、标记、目标 |
| 通关率目标 | 新手 30–40%，理解规则的玩家约 70%，技巧型玩家（会控制升级时机、会囤宝箱和血瓶）约 85–90% |
| 核心情绪 | 「黑暗中的谨慎」→「推理成立的爽快」→「压线升级回满血的惊险」→「屠龙的释放」 |

**情绪曲线（一局）**

```
强度
 ▲                                             ┌─屠龙(L4)─┐
 │                                   紧张期 ╱╲╱    巨龙苏醒  │╲  释放：光照充满整座地牢
 │                       推理节奏 ╱╲╱╲╱╲╱                   │ ╲ 结算
 │      首次升级 ╱╲    ╱╲╱                                   │
 │ 好奇 ╱╲╱╲╱  ╲╱╲╱                                          │
 └──────────────────────────────────────────────────────────────▶ 时间
  0:00  0:30         2:30              4:00       ~5:00
```

- 0:00–0:30 **好奇/上手**：入口火把亮起，光从底部流出；外圈都是 1–2 级小怪，30 秒内第一次升级。
- 0:30–2:30 **推理节奏**：沿边缘扩张，捡血瓶、宝箱，等级 3–6，暖光一块块覆盖地图。
- 2:30–4:00 **紧张期**：逼近中央龙巢，大怪变多、生命预算吃紧（模拟中死亡集中在玩家 7–9 级）。
- 4:00–5:00 **高潮**：生命上限达到 14，巨龙睁眼。玩家要决定：立刻挑战，还是继续清图拿分。
- 屠龙：约 3.6 秒的演出，随后整座地牢被点亮，进入结算。

## 2. 技术选型

| 领域 | 选型 | 理由 |
|---|---|---|
| 语言/构建 | **TypeScript（strict）+ Vite** | 遵守共同约定。冷启动快，产物是纯静态文件，设 `base: './'` |
| 渲染 | **Canvas 2D 单画布 + 自研轻量渲染层**（不引入引擎） | 场景只有 108 格，加上粒子、光照和剪影。Canvas 2D 在 Chromium/Safari 上有 GPU 加速，`drawImage`、`globalCompositeOperation` 和低分辨率光照图放大都很便宜。不用 PixiJS/WebGL，可以省下约 150KB 首包，也没有着色器兼容风险。3D 翻牌用仿射挤压、抬升缩放、阴影、明暗和厚度条来模拟（§5.2），不需要真正的透视 |
| UI 覆盖层 | **DOM + CSS**（标题、暂停、设置、结算、引导气泡、对话框、Toast） | 中文排版清晰，按钮可以直接用 Playwright 选择器点击，CSS 过渡也便宜。HUD（血条、经验、图鉴）画在 Canvas 里，因为它要和粒子、光照联动 |
| 动画/缓动 | **自研 tween 池 + 缓动函数表**（约 150 行） | 预分配对象池，每帧零分配。支持延迟、链式、yoyo，受全局时间缩放影响（hitstop/慢动作）。不用 GSAP 之类，避免体积和每帧闭包 |
| 音频 | **WebAudio 实时合成**（振荡器、噪声缓冲、Biquad、Convolver 程序化混响、DynamicsCompressor） | 遵守约定。音效按「配方」函数生成；背景音乐是程序化氛围层（§5.6） |
| 随机 | **mulberry32** 可播种 PRNG；地图、贴图变体、烛台位置都从种子派生 | `?seed=` 可复现 |
| 字体 | **Cinzel（可变字重，latin 子集）** 用于数字和 HUD；**Cinzel Decorative 700（latin）** 只用于英文 Logo 和 LEVEL UP。中文用系统字体栈 | 古典碑刻感，符合美术分区。通过 `?url` 只引入需要的 woff2 文件，用 `FontFace` API 加载，加载完成后再烘焙 Canvas 字形图集 |

## 3. 核心循环与完整规则

### 3.1 核心循环

```
观察数字 ──▶ 推理（安全格 / 确定等级 / 等级上限）──▶ 选择行动
   ▲                                                  │
   │       ┌──────── 翻开安全格：数字、连锁展开、光照扩散
   │       ├──────── 主动打已知怪：扣血、得经验、数字下降 ──▶ 可能连锁展开
   │       ├──────── 冒险试探：上限 < 生命的格子（不会死，但可能挨打）
   │       └──────── 资源择时：开宝箱（经验）、喝血瓶、压线升级回满血
   └────────────────── 新信息 ◀────────────────────────────┘
目标：生命 ≥ 14 时挑战巨龙（13 级）→ 胜利
```

**核心技巧**（规则里不写，玩家自己能发现）：
1. **上限推理**：数字 N 表示它周围任何一只怪物的等级都 ≤ N。只要 N < 当前生命，点它的任意邻格都不会死。引导局会教。
2. **压线升级**：先扣血、后算经验，溢出的经验会带入下一级，而升级会回满血。所以快升级时去打大怪，等于用旧血条付账、新血条白赚经验。
3. **资源囤积**：宝箱和血瓶翻出来后可以留到任意时刻再用。快升级又残血时开宝箱，相当于一次免费回满。

### 3.2 地图与布置

- 网格 **9 列 × 12 行**（竖屏）。也就是用户说的「12×9」转成竖向，适配 390×844。坐标 `(x, y)`，`x ∈ 0..8` 从左到右，`y ∈ 0..11` 从上到下。
- **龙巢**：`x 3–5, y 4–6` 共 3×3 格。巨龙中心在 `(4, 5)`。
  - 水平方向严格居中（左右各 3 列）。12 行没法让 3 行巢穴严格居中，所以选「上 4 行、下 5 行」：视觉中心略偏上，正好符合视觉重心，也给底部入口留出更多纵深。
  - 龙巢 3×3 让巨龙有足够的画面尺寸（120×120px），成为整张图的视觉焦点。它不计入数字，不能标记，也不会被连锁展开。
  - 开局时龙巢就在画面上，但被黑暗笼罩，只能看到一对眼缝和呼吸时的余烬光，对应「藏在中央」。离龙越近、玩家等级越高，它显露得越多（§4.6）。
- **入口**：`x 3–5, y 10–11` 共 3×2 格，保证为空地。开局自动翻开 `(4,11)`（楼梯），由于它的邻格全在入口内，数字为 0，必然连锁展开。
- **可玩格**：108 − 9（龙巢）= **99 格** = 38 怪物 + 4 宝箱 + 3 血瓶 + 54 空地（其中 6 格是入口）。
- **环带**：以到龙巢的切比雪夫距离 `d` 划分。`d=1` 内环（16 格，龙卫）、`d=2` 中环（24 格）、`d=3` 外环（32 格）、`d=4–5` 边缘（27 格，含入口）。越靠近巨龙越危险，这是玩家很快能学到的空间直觉。

### 3.3 完整规则（无歧义版）

**R1 格子内容**：每个可玩格是以下之一：空地、怪物（1–9 级）、宝箱、血瓶。开局只有入口连锁展开的格子和龙巢是可见的。

**R2 数字**：每个已翻开的非怪物格（空地、未拾取或已拾取的道具格、已击败怪物留下的格子、入口）显示 **N = 周围 8 格中「仍未翻开且存活」的怪物等级之和**。
- 巨龙和龙巢**永不计入**。
- 标记不影响 N（标记只是笔记）。
- **怪物被击败后，周围数字实时减少**（滚轮动画）。所以数字永远表示「周围还剩多少未知的危险」。
- 道具格在右下角用小字显示 N，拾取后数字移到格子中央。
- N = 0 时不显示数字（只留一个淡淡的符文点）。

**R3 翻开**：点击未翻开格。
- 空地或道具：翻开，显示数字或道具。**道具不会自动拾取。**
- 怪物：**立即进入战斗**（R5）。

**R4 连锁展开**：任何已翻开的信息格只要 N = 0，就自动翻开它周围所有未翻开格（包括被标记的格子，它们的标记会被擦掉），并递归进行。连锁**永远不会翻出怪物**（N = 0 已经说明周围没有怪）。这条规则对开局、普通翻开、击败怪物导致的 N 归零、快开**统一生效**。连锁翻出的道具同样不会自动拾取。

**R5 战斗结算顺序**（严格按这个顺序）：
1. `hp -= monster.level`
2. 若 `hp <= 0` → **死亡，游戏失败**（**恰好归零也算死亡**；本次战斗不给经验，也不会因为这一击带来的升级而复活）
3. 否则 `xp += monster.level`（经验 = 怪物等级）
4. `while (xp >= xpToNext[level])`：`xp -= xpToNext[level]`，`level += 1`，`maxHp = maxHpByLevel[level]`。可以一次连升多级
5. 若本次发生了升级：`hp = maxHp`（回满）
6. 怪物移除，该格变成「骸骨地面」，显示自己的 N；周围数字更新 → 触发 R4
7. 若全图怪物（巨龙除外）都已被击败 → **肃清**：`hp = maxHp`，并得肃清分（R10）

**R6 宝箱**：翻出后以宝箱形态留在格子上，**随时点击即可打开**。打开后获得金币（计分）和经验（可能触发升级与回满）。**宝箱没有任何风险**（风险全部由怪物承担；5 级怪「宝箱怪」只是外观，它和普通怪物一样遵守 R2/R5，翻开格子就开战，不会藏在已经翻开的宝箱里）。宝箱有三种外观档次（木 / 铁 / 金），长按宝箱会显示确切数值。

**R7 血瓶**：翻出后留在格子上，随时点击饮用：`hp = min(maxHp, hp + 5)`。**满血时点击无效**（瓶子摇晃一下，提示「生命已满，留着以后用」），不会白白浪费。

**R8 标记**：长按（桌面右键）未翻开格，弹出标记轮盘：`1–9`、`?`（可疑）、`○`（安全）、`✕`（清除）。标记只是笔记，不影响任何规则。
- 被标记的格子仍然可以点击翻开：
  - 标记是数字且 **≥ 当前生命**（致命标记）：第一次点击只会让格子红光抖动并提示「致命！再点一次硬闯」，**2 秒内再点一次**才会翻开。
  - 其他标记：直接翻开。
- 格子被翻开时标记擦除。如果数字标记和真实怪物等级一致（或 `○` 下面确实没有怪），会出现「猜中」的粉笔星光（纯反馈，不计分，防止乱标刷分）。

**R9 巨龙**：点击龙巢任意一格。
- `hp >= 14`（严格大于 13）：如果场上还有存活怪物，先弹确认框「现在挑战巨龙？剩余怪物的分数将无法获得」，选择【挑战】或【再等等】；如果全图已肃清，则直接开战。战斗中 `hp -= 13`（必然存活），**胜利**。
- `hp < 14`：**不会开战**。巨龙睁一只眼、喷出鼻烟，提示「巨龙之威：需要至少 14 点生命」。这避免了无意义的送死。
- 生命上限要升到 10 级才能达到 14，所以屠龙必须先成长。

**R10 计分**（结算时逐项显示）

| 项 | 公式 | 条件 |
|---|---|---|
| 击杀 | Σ 怪物等级 × 10 | 始终 |
| 金币 | 宝箱金币之和（40/60/80/120） | 始终 |
| 屠龙 | +1000 | 胜利 |
| 余勇 | 屠龙后剩余生命 × 30 | 胜利 |
| 迅捷 | max(0, 600 − 用时秒数) × 1 | 胜利 |
| 肃清 | +300 | 屠龙前击败全部 38 只怪物 |

典型胜局约 2,200–2,500 分，全清胜局约 3,000–3,300 分，败局约 300–900 分。本地记录**最高分**、**最快通关时间**、**通关次数/总局数**。

**R11 计时**：引导结束（或入口点亮动画结束）开始计时。暂停、对话框、页面失焦时停止。

**R12 输入锁定**：一次战斗演出期间（约 420ms）忽略新的点击，不缓冲，以免连点触发两场战斗。连锁翻牌动画期间，已经落定的格子照常可以点击；正在翻转的格子不响应。

**R13 快开（P1，设置里默认开启）**：点击一个 N > 0 的数字格时，如果它周围的未翻开格中，数字标记之和恰好等于 N、没有 `?` 标记、并且还有未标记或 `○` 标记的格子，就一次翻开所有未标记格和 `○` 格。标记错误时会照常遇怪战斗；如果中途死亡，剩余的翻开取消。按住数字时会预览将被翻开的格子（淡金描边），在格子外松手即可取消。条件不满足时，点击数字只闪一下 3×3 邻域框，方便数数。

**边界情况汇总**

| 情况 | 处理 |
|---|---|
| HP 恰好为 0 | 死亡 |
| 一次获得的经验够连升多级 | 逐级结算，最终回满到最终上限，演出「LEVEL UP ×2」 |
| 宝箱经验触发升级 | 同 R5 第 4–5 步，回满 |
| 满血点血瓶 | 无效，提示，血瓶保留 |
| 生命 < 14 点龙巢 | 不开战，只有惊扰演出 |
| 全图清空但生命 < 14 | 不可能出现：肃清会回满血，而仅怪物经验（137）就足以升到 13 级（需要 126，上限 17 ≥ 14）；如果宝箱也全开（145），可以升到 14 级（上限 18） |
| 点击被标记的格子 | 致命标记要二次确认；其他直接翻开 |
| 连锁翻到被标记的格子 | 翻开并擦掉标记（它一定安全） |
| 长按已翻开格 / 道具 / 龙巢 | 已翻开格：显示 3×3 邻域框；道具：显示数值浮窗；龙巢：显示「巨龙 Lv13 · 需生命 14」 |
| 多指触控 | 只追踪第一个指针，其余忽略 |
| 动画期间暂停 | 整个世界时间冻结；恢复后从原处继续 |
| 页面隐藏 | 自动暂停，挂起 AudioContext |
| 等级超出表 | `maxHp = 5 + (level-1)`，`xpToNext = 末项 + (超出级数)`。实际最高只能到 14 级 |

### 3.4 开局保障

1. 入口 6 格保证为空地；起点 `(4,11)` 的 N 必然为 0，开局至少翻开 6 格。
2. **入口护卫**：与入口矩形切比雪夫距离 ≤ 2 的格子里，只能放 ≤ 2 级的怪物。开局生命是 5，所以入口附近任何一格都不可能一击致死（开局的前几步一定能活下来）。
3. **重抽**：生成后模拟开局连锁，翻开格数必须在 `[9, 28]` 之间（太少没有信息，太多没有挑战）。不满足就用 `seed + k` 重新生成（k 递增，最多 50 次，之后接受最后一张）。约 74% 的地图一次通过，重抽开销小于 1ms。
4. 生成器校验（失败就重抽，并在 debug 模式下报告）：怪物总数和各等级数量与配置一致；龙巢和入口没有放东西；经验总量 ≥ 升到 10 级所需经验（静态断言）。

### 3.5 生成算法

1. 标记龙巢和入口格为不可放置。
2. **按等级从高到低**放置怪物（9 → 1）。每只怪物在合法格中按权重随机抽取：`w = bandFalloff ^ |d − band.pref|`，其中 `d ∈ [band.min, band.max]`，并遵守入口护卫。
3. 放宝箱（按 `d` 加权，越靠近巨龙权重越高）。按与巨龙的距离排序后，最近的宝箱分到最高档奖励。
4. 放血瓶（偏中外环）。
5. 其余为空地。烛台装饰：每个空地格以 18% 的概率（由种子派生）成为烛台格（纯视觉，见 §4.4）。

### 3.7 平衡推算与模拟证明

**简短推算**：到达 10 级需要 78 经验，而战斗经验和伤害 1:1。从各级满血出发，1–4 级「上限 − 1 ≥ 所需经验」，光靠打怪就能升级。5–9 级合计缺 8 点，可以由以下来源补上：宝箱经验 8、血瓶 3×5 = 15 生命、压线溢出（每次升级前用最后一击多打出 2–5 点经验带进下一级）。这些来源合计远超缺口，所以**完美信息下必然可通关**。难点在于信息不完全时被迫的猜测，以及猜测发生时生命是否足够。

**模拟**（`scratchpad/dungeon-sweeper/sim/sim.mjs`，3000 张种子图，规则与本文一致）：

| 机器人策略 | 胜率 | 平均击杀 | 平均翻格/操作 | 每局「可能致死」的猜测 |
|---|---|---|---|---|
| 新手型：只用 N=0 和单格推理，带噪声地凭感觉猜，残血才喝药 | **36%** | 18.4 | 46 | 2.6 |
| 熟练型：加子集推理和上限安全试探 | **69.5%** | 20.2 | 55 | 0.87 |
| 技巧型：再加囤宝箱（快升级残血时开）和按需喝药 | **87%** | 21.3 | 57 | 0.44 |

- 胜局在 10 级屠龙时平均翻开 72/99 格。死亡集中在玩家 7–9 级，说明后期才是压力最大的阶段，和情绪曲线一致。
- 「技巧型」比「熟练型」高 17 个百分点，说明资源择时是真实存在的技巧维度，不是纯运气。
- 机器人每局平均只有 0.4–0.9 次真正有风险的猜测，所以技巧型玩家基本靠推理就能通关，运气只决定少数局。

## 4. 美术方向

### 4.1 风格关键词

**「烛光下的石室」**：炭黑、冷灰蓝的石砖构成黑暗，琥珀色烛光是唯一的温度。画面要有体积光、强暗角、火光闪烁和石材颗粒。整体克制：大面积暗部加少量高饱和点缀（烛火、眼睛、血、金），不用霓虹和高光泛滥。所有素材用 Canvas 程序化绘制并在启动时烘焙。

### 4.4 光照与质感（核心）

**分层（游戏画布从下到上）**

1. **背景层**（resize 时烘焙一次）：大块石砖墙（每块 64–96px，带砖缝、裂纹、苔痕、像素级噪点颗粒），加棋盘外框（6px 刻花石框，四角铜钉）。
2. **棋盘层**：暗砖、地面、贴花（骸骨焦痕）、烛台底座、道具、龙巢底图（焦黑石面和散落金币）、巨龙身体。
3. **光照层**（每帧）：见下文。
4. **光后层**：数字（乘以本格光照值作 alpha 调制，保证可读）、粉笔标记（自带冷白微光，不受黑暗影响）、按压/悬停高亮、引导高亮。
5. **特效层**：剪影、碎片、刀光、粒子（发光类用 `lighter` 混合）、跳字。
6. **HUD 层**：不受棋盘震屏影响。
7. **覆盖层**：标记轮盘、debug 浮层。

**光照实现：低分辨率光照图 + 放大合成**

- 维护两张小画布，分辨率为每格 8 texel，外加 1 格边距：`(9+2)×8 × (12+2)×8 = 88×112`。
  - `darkCanvas`（黑暗遮罩）：每帧先 `fillRect` 雾蓝暗色（`rgba(7,9,18,0.86)`），再用 `destination-out` 把每个光源的**预烘焙径向光斑 sprite**（64×64，白→透明，按 smoothstep 曲线衰减）按强度 `globalAlpha` 绘制上去，「挖」出光。
  - `glowCanvas`（暖光晕）：清空后用 `lighter` 叠加琥珀色光斑 sprite（龙巢用龙焰色，血瓶用粉色，升级时叠加熔金）。
- 合成：`darkCanvas` 以 `source-over`、开启 `imageSmoothingEnabled` 放大绘制到棋盘区域（双线性插值得到柔和渐变）；`glowCanvas` 以 `lighter`、alpha 0.22 放大叠加，形成暖色辉光（类 bloom）。整张图每帧只有 2 次大面积 `drawImage`，小画布上约 100 次小 `drawImage`，CPU 成本约 0.3ms。
- **光源**
  - 每个已翻开格：半径 1.5 格、强度 `cellLight`。翻开时随波纹在 500ms 内从 0 缓动到 0.85，光顺着翻牌波前流过去。
  - 烛台格：在格子左下角画一个小烛台（8×12px），作为强光源，半径 2.4 格、强度 1.0，带火焰 sprite 和上升余烬。入口两侧固定有两支火把（半径 3 格）。
  - 前沿渗光：未翻开格如果有已翻开邻格，自动获得约 0.35 的亮度（由光斑半径自然溢出）。远处暗砖保持约 0.12–0.18 的可见度：冷蓝、能看清砖块轮廓，但神秘。
  - 指尖/鼠标火把：跟随指针，半径 1.1 格、强度 0.35（按下时 0.5），让黑暗中要点的那块砖可读。
  - 龙巢：龙焰色，呼吸周期 3.6s，强度在 0.25–0.55 之间起伏；巨龙苏醒后提高到 0.6–0.9。
  - 血瓶：粉色小光源，半径 0.9 格、强度 0.4。
  - 全局事件：升级时所有光源 ×1.6，持续 300ms 后用 700ms 回落；死亡时光源从死亡格起按距离波纹熄灭；胜利时整图强度缓动到 1.0。
- **闪烁**：强度 × (1 + A·(0.6·n₁(t·f₁+s) + 0.4·n₂(t·f₂+s)))。n 是预计算 256 点值噪声表，用余弦插值；地面光 A = 0.05，烛台 A = 0.14（f₁ = 1.7Hz，f₂ = 5.3Hz）；烛台光斑位置还有 ±0.6 texel 的抖动，让阴影「活」起来。
- **雾**：黑暗区域漂着 6 张大块柔雾 sprite（雾蓝，alpha 0.06–0.10，缓慢平移和缩放），画在遮罩之后；在已照亮区域按光照值淡出。
- **体积光**：屏幕左上方有一道斜向光柱（预烘焙线性渐变条，`lighter` alpha 0.05–0.08，缓慢漂移），里面漂浮尘埃粒子。标题页更明显。
- **暗角**：resize 时烘焙全屏径向渐变（中心透明 → 边缘 `#07080D` alpha 0.75），每帧 1 次 `drawImage`。
- **颗粒/条带**：石材噪点直接烘焙进所有贴图，既是质感，也掩盖暗部渐变的色带。不使用运行时滤镜。

**贴图细节**

- **暗砖（未翻开）** 40×40：圆角 4，四周留 1px 缝；顶面从左上 `#4A556B` 渐变到右下 `#343D50`；左上 2px 高光 `#6E7C96`（α 0.6），右下 2px 阴影 `#161A24`；表面有 8% 噪点、1–2 条细裂纹（随机游走线）；15% 的砖角带苔痕（`#3C5A3A` α 0.3）。共 4 个变体。
- **地面（已翻开）** 40×40：比暗砖低半级的凹槽感（左上 2px 内阴影），基色 `#4A3A2E` 带暖色斑点和偶尔的石子。共 3 个变体。
- **骸骨地面**：地面贴花，焦痕径向暗斑（大小随怪物等级）加 2–3 根小骨头（`#CDBFA8` α 0.5）。

### 4.6 巨龙

- **龙巢静态**（3×3 = 120×120 烘焙图）：巨龙蜷伏俯视。巨大的角首枕在交叠的前爪上，位于下方中央；双翼像斗篷一样收拢，覆盖整个巢；尾巴沿巢的边缘绕半圈，尾尖垂出巢外。剪影本体是 `#0A0910`，鳞片用暗上加暗的菱形纹理。鳞缝里是**龙焰色余烬裂纹**（单独一层，随呼吸改变 alpha）。巢底是焦黑石面和零星金币（龙的宝藏）。

## 5. 动效与反馈

### 5.1 强度层级

| 层级 | 用途 | 震屏 trauma | hitstop | 震动 | 粒子规模 |
|---|---|---|---|---|---|
| L0 微 | 翻格、UI、标记 | 0 | 0 | 0–6ms | ≤ 6 |
| L1 轻 | 1–3 级怪、宝箱、血瓶、连锁 ≥ 10 格 | 0.10–0.18 | 40–60ms | 8–12ms | ≤ 20 |
| L2 中 | 4–6 级怪、升级、肃清 | 0.22–0.30 | 70–90ms | 18–22ms | ≤ 45 |
| L3 重 | 7–9 级怪、濒死一击、新纪录 | 0.35–0.45 | 100–120ms | [25,20,35] | ≤ 70 |
| L4 史诗 | 屠龙、胜利、死亡 | 0.6–0.8 | 160–220ms | 模式序列 | ≤ 160 |

- **trauma 模型**：偏移 = 10px × trauma² × 噪声(t·22Hz)，旋转 = 1.2° × trauma² × 噪声；trauma 每秒衰减 1.5，叠加后封顶 1。**只震棋盘层**，HUD 不动。
- **hitstop**：世界时间缩放 = 0，持续 N ms（真实时间）。多个 hitstop 取最大值，不叠加。震屏和 UI 继续运行。
- 怪物击杀的强度按等级插值：`trauma = 0.08 + 0.035·Lv`，`hitstop = min(120, 30 + 10·Lv) ms`。
- **减少动效**（设置项，默认跟随 `prefers-reduced-motion`）：震屏 ×0.25、无旋转，翻牌时长减半，关闭慢动作和全屏闪光。

### 5.2 3D 翻牌与波纹（实现要点）

- 进度 p ∈ [0,1]（260ms），角度 θ = π·easeInOutQuad(p)，挤压 c = max(0.04, |cos θ|)，抬升 L = sin(πp)。
- 翻转轴垂直于「波纹源 → 本格」方向 φ，这样格子会顺着波向外翻滚。变换矩阵 = `T(中心)·R(φ)·S(c·(1+0.12L), 1+0.12L)·R(−φ)·T⁻¹`，直接用 `setTransform` 设置，不用 save/restore。
- p < 0.5 画暗砖面（叠加黑色 α = (1−c)·0.5 表现转离光源），p ≥ 0.5 画背面（地面、数字或道具），永远不镜像。c < 0.3 时沿翻转轴画一条 2px 深色厚度条。格子下方画阴影 sprite，偏移 (0, 3L)，α = 0.4L。落定时有 4% 的微回弹（easeOutBack 尾段）。
- **波纹**：延迟 = min(520, 34ms × 欧氏距离(源, 格))。波前叠加一个淡金色环形光（环形 sprite，半径随时间扩张，α 0.25→0），本格光照在翻转开始时启动 500ms 的缓动。
- 数字在翻牌落定后做 140ms 的缩放淡入（1.3→1）。

| 2.30 | 碎裂 | 约 60 片碎片外飞，缝隙透出金光；时间缩放 0.3（600ms）后恢复 | 大型碎裂音加长混响尾 | — |
| 2.90 | 光之冲刷 | 金光从龙巢向外扩散，所有剩余暗砖大波纹翻开（#30），整图点亮 | 凯旋号角开始 | — |
| 3.60 | 结算 | 结算石板升起 | | |

### 5.5 待机与环境动画

- 烛火：火焰 sprite 每帧根据噪声做缩放（0.9–1.1）和倾斜（±6°），向上飘余烬，每支烛台每秒 0–2 粒。
- 暗砖：每隔 4–7 秒随机一块暗砖被一粒「尘光」掠过（细高光一闪）。
- 雾：缓慢漂移。体积光：缓慢移动。
- HUD：心形图标每 1.6s 一跳（低血时加快）；盾徽每 6s 一道流光；图鉴剪影轻微上下浮动（各自相位不同）。
- 巨龙：呼吸（§4.6）。宝箱：流光。血瓶：液面晃动。

### 5.6 音频系统

- 节点图：`sfxBus(1.0)`、`musicBus(0.6)` → `master(0.8)` → `DynamicsCompressor(threshold −18dB, ratio 4)` → destination。混响用 `ConvolverNode`，脉冲响应程序化生成（2.8s 指数衰减的立体声噪声），作为两条总线的 send。
- 首次 `pointerdown` 或 `keydown` 时创建并 `resume()` AudioContext。iOS 的 `interrupted` 状态在下一次手势时恢复。音效、音乐开关分别保存在本地。
- 同时发声最多 24 个；同类音效节流；噪声缓冲启动时预生成 1 秒，之后复用。
- **程序化背景音乐**（D 多利亚调式，无固定节拍）：
  1. 底层持续音：锯齿 D2 和 A2，失谐 ±6 音分，低通 320Hz，LFO 0.07Hz 调制截止频率 ±80Hz，增益 0.05。
  2. 洞穴风：白噪声过带通 600Hz（Q 0.5），中心频率由 0.03Hz LFO 在 300–900Hz 间摆动，增益 0.015。
  3. 水滴：每 2.5–6s 随机一次，从 {D5, F5, A5, C6} 中取音的正弦，4ms 起音、180ms 衰减，混响湿度 0.6。
  4. 竖琴动机：每 8–14s 一句，3–5 个音取自 D F G A C，三角波拨弦（快衰减加低通）。
  5. 紧张层（危险度 = f(玩家等级 ≥ 7、低血、离巢距离)）：每 1.2s 一声低鼓（正弦 55Hz 下滑），加高音震音弦（锯齿 587Hz，6Hz 颤音，低通 1200Hz，增益 0.01），按危险度淡入淡出。
  6. 苏醒层：生命达到 14 后，合唱垫（锯齿 D3 F3 A3，失谐，缓慢膨胀）淡入。
- 大事件发生时，音乐压低 6dB（侧链式自动增益）。

### 5.7 震动

`navigator.vibrate`（Android/Chrome 支持；iOS Safari 不支持，静默忽略）。设置里可以关闭。所有调用经过 `haptics.ts`，按层级映射（§5.1），最短间隔 40ms 防止嗡嗡连震。

### 6.4 标记轮盘（手机好用是第一位）

- **触发**：按住未翻开格 120ms 后出现蓄力环，380ms 时轮盘弹出，并轻震 8ms。桌面右键立即弹出。
- **几何**：环半径 78px，11 个槽（直径 42px）。从正上方开始顺时针排列：`1 2 3 4 5 6 7 8 9 ? ○`，每槽间隔 32.7°。中心是「✕ 清除」（格子已有标记时），否则是「取消」。底盘是半径 104px 的深石圆盘（α 0.92），刻符文环。
- **边缘处理**：轮盘中心钳制在栏内，距边 ≥ 106px；偏移后有一条细线连回原格，原格高亮。
- **两种用法都支持**：
  1. **按住滑选**（熟练玩家）：按住不放滑到某个槽，松手即确认。判定用「离指针最近的槽中心」，且距离 ≤ 槽半径 × 1.35。
  2. **松手点选**（新手）：长按后原地松手（位移 < 10px），轮盘保持打开，再点某个槽确认；点轮盘外关闭。
  - 滑到空白处松手：关闭，不做改动。
- **信息**：数字槽 ≥ 当前生命时为红色并带小骷髅；悬停槽放大 1.18×。轮盘上方显示一行小字「此格周边上限 ≤ 3」（取周围已翻开数字的最小值，只是把屏幕上已有的数字整理出来，不额外泄露信息）。
- **桌面快捷键**：悬停格上按 `1–9` 直接标记，`0`/`Backspace` 清除，`Q` 标 `?`，`S` 标 `○`；滚轮在悬停的暗砖上循环标记数字（P1）。

**标记外观**（画在光后层，所以在黑暗中也清晰）
- 数字：粉笔白手写感数字（用 Cinzel 600 烘焙，再用噪点 `destination-out` 做粉笔颗粒，每个数字 2 个变体随机），下方一道粉笔短弧线，带冷白微光。
- 致命：同一数字转为致命红，外加 1.2s 周期的余烬脉冲，右上角小骷髅。生命变化时实时切换（升级后变回白色）。
- `?`：粉笔问号，α 0.75。
- `○`：薄荷色粉笔圈。

### 6.5 暂停 / 设置 / 结算 / 对话框

- **暂停**：按 ‖、`Esc`/`P`、`blur`、`visibilitychange` 都会触发。画布 CSS `filter: blur(6px) brightness(.45)`（暂停时画布不重绘，开销为零），石板面板 300 宽：标题「暂停」，按钮【继续】【重新开始】（二次确认）【设置】【返回标题】，下方两个快捷开关（音效、音乐），底部小字「种子 #123456」便于复现。
- **设置**（标题页和暂停页共用）：音效、音乐、震动、减少动效、数字快开（各为开关），以及【重看引导】【清除记录】（二次确认）。全部存入 `aircade.dungeon-sweeper.settings`。
- **结算**：见 §4.7 D。「再来一局」直接在当前场景重置，不回标题。快捷键 `Enter`/`Space`。
- **对话框**（挑战巨龙、重开确认、清除记录）：小石板，两个按钮，主按钮在右；`Esc` 取消。

### 6.6 转场

| 转场 | 做法 | 时长 |

### 6.7 桌面适配

- 两张画布：`#bg` 铺满窗口（DPR 1，30fps 更新），`#game` 只覆盖居中的游戏栏（DPR ≤ 2）。
- 两侧装饰：更大块、更暗的石墙；每侧约 35% 高度处一支壁挂火把（铁托架），火焰摇曳，在墙上投下光池；还有垂下的铁链，鼠标移动时轻微视差（±4px）。游戏栏两侧有半透明石柱边缘过渡，不出现白边或纯黑边。
- 鼠标：悬停格高亮加火把光跟随；右键弹轮盘（屏蔽系统右键菜单）；快捷键见 §6.4；`M` 静音，`Esc` 暂停。
- 横屏手机：同一套栏宽逻辑（栏宽由高度决定），两侧显示石墙装饰。

### 6.8 平台约束

`<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no,viewport-fit=cover">`；`html, body { position: fixed; overflow: hidden; overscroll-behavior: none; touch-action: none; user-select: none; -webkit-user-select: none; -webkit-touch-callout: none; }`；阻止 `contextmenu`、`gesturestart`、`dblclick` 的默认行为。安全区通过 CSS `env(safe-area-inset-*)` 写到一个探针元素的 padding 上，再读取其计算值。`resize`/`orientationchange` 时重新计算布局并重烘焙背景（节流 150ms）。

**关键数据结构**

```ts
  kind: Uint8Array; level: Uint8Array;            // 怪物等级 1–9
  revealed: Uint8Array; dead: Uint8Array; collected: Uint8Array;
  mark: Int8Array;                                 // −1 = ?，−2 = ○，0 = 无，1–9
  number: Uint8Array;                              // 缓存的 N（仅信息格有意义）
  itemValue: Uint16Array; itemXp: Uint8Array;      // 宝箱金币/经验，血瓶回复量
  candle: Uint8Array; variant: Uint8Array;         // 视觉用（由种子决定）
  neighbors: Int16Array;                           // 108 × 8，−1 填充
}
interface PlayerState { level: number; hp: number; maxHp: number; xp: number; }
interface RunState {
  seed: number; phase: Phase; board: BoardState; player: PlayerState;
  score: number; gold: number; kills: number; killXp: number; timeMs: number;
  correctMarks: number; dragonAwake: boolean; isTutorial: boolean;
}
type GameEvent =
  | { t: 'reveal'; origin: number; cells: number[]; dist: number[] }
  | { t: 'fight'; cell: number; level: number; hpBefore: number; hpAfter: number; lethal: boolean }
  | { t: 'xp'; amount: number; from: number }
  | { t: 'levelUp'; from: number; to: number; maxHp: number }
  | { t: 'numbers'; cells: number[]; before: number[]; after: number[] }
  | { t: 'collect'; cell: number; item: 'chest' | 'potion'; gold: number; xp: number; heal: number }
  | { t: 'potionRefused' | 'dragonBlocked' | 'dragonAwake' | 'fullClear'; cell?: number }
  | { t: 'mark'; cell: number; mark: Mark } | { t: 'markResult'; cell: number; correct: boolean }
  | { t: 'lethalWarn'; cell: number }
  | { t: 'victory' | 'defeat'; breakdown: ScoreBreakdown; cell?: number };
```

- **逻辑和演出分离**：`rules.ts` 同步结算，立即更新真相并返回事件数组；`director.ts` 按时序播放事件，HUD 显示的是 director 推进后的「显示值」（生命在出击那一刻掉，经验在光点到达时涨）。演出可以快进（例如快速连点时，上一段剩余动画加速 3 倍）。

## 8. 调试接口

URL 参数：
- `?debug=1`：左上角浮层显示 FPS、帧时间（平均/最大）、粒子数、绘制调用数、当前种子，并暴露 `window.__game`。
- `?seed=<整数>`：固定种子。「再来一局」时沿用同一种子（便于复现）；不带参数时用随机种子，并显示在暂停面板。
- `?tutorial=1` 强制引导；`?tutorial=0` 跳过引导；`?mute=1` 静音启动；`?fast=1` 所有演出 ×3 速（审查截图用）。

`window.__game` API（仅在 debug 下存在，所有方法同步返回，异步演出可以 `await __game.idle()`）：

| 方法 | 说明 |
|---|---|
| `state()` | `{phase, seed, hp, maxHp, level, xp, xpToNext, score, gold, timeMs, revealed, alive: {1..9: n}, dragonAwake, isTutorial}` |
| `board()` | 9 × 12 数组 `{x, y, kind, level, revealed, dead, mark, number}`（真相，含隐藏信息） |

| `revealSafe()` | 翻开所有非怪物格（不拾取道具） |
| `xray(on)` | 渲染叠加真相（怪物等级半透明显示） |
| `addXp(n)` / `setHp(n)` / `setLevel(n)` / `heal()` | 数值作弊 |
| `killAll()` | 按等级从低到高击杀全部怪物（带奖励，快速演出），直达「巨龙可战」状态 |
| `dragonReady()` | 把生命和等级设为可以挑战巨龙 |
| `fightDragon()` | 立即进入屠龙序列（必要时自动补足生命） |

| `fx(name)` | 单独触发特效：`'levelup' \| 'shatter' \| 'shake' \| 'fullclear' \| 'record' \| 'death'` |

| `clearSave()` | 清除本游戏的全部本地存储 |

## 9. 性能预算与策略

**预算（中端手机，例如 Pixel 6a 或 iPhone 11，390×844，DPR 2）**

| 项 | 预算 |
|---|---|
| 帧率 | 稳定 60fps；单帧 CPU ≤ 8ms（桌面 ≤ 4ms） |
| 首屏可点 | DOM 标题 ≤ 300ms；全部烘焙 ≤ 120ms（背景 40、格子 20、剪影/碎片 40、字形 10），分片在标题页空闲时完成 |
| 首包 | ≤ 130KB（JS ≤ 75KB gz + 字体 40KB） |
| 绘制调用 | 常态 ≤ 450 次/帧，峰值（屠龙）≤ 900 |
| 对象上限 | 粒子 400、碎片 160、跳字 24、tween 256、同时发声 24 |
| 内存 | 画布总量 ≤ 30MB；稳态每帧零分配，30 秒待机内无 minor GC |

**策略**
1. **烘焙一切**：贴图、渐变光斑、剪影（含白版和碎片）、字形、暗角都在启动或 resize 时画进离屏画布。运行时**禁止** `shadowBlur`、`ctx.filter`、`createRadialGradient`、`getImageData`、逐帧 `fillText`（变化频繁的 HUD 数字走字形图集）。
2. **低分辨率光照图**：88×112 两张，放大合成（§4.4）。
3. **SoA 和对象池**：粒子、碎片、tween 都用预分配的 TypedArray 加交换删除；事件数组复用；邻接表预计算。
4. **直接 `setTransform`**，不用 `save/restore` 栈；按状态批量绘制（先画所有暗砖，再画所有地面），减少 composite op 切换。
5. **静态层缓存**（P1）：未在动画中的格子合成到 `boardCache`，只在格子状态变化时局部重绘；动画中的格子单独画。
6. **自适应质量**：连续 2 秒平均帧时间 > 18ms 时，依次执行：关雾 → 光照图分辨率减半 → 粒子上限减半 → DPR 降到 1.5。恢复不回退，避免抖动。
7. 暂停或页面隐藏时停止 RAF；`#bg` 只以 30fps 更新。
8. 逻辑是事件驱动的，没有每帧逻辑；主循环 dt 限幅 50ms；粒子和碎片用固定步长 1/120s 积分。

### 10.1 优先级

- **P0（必须）**：本文 §3 全部规则（快开除外）、引导、标记轮盘（滑选和点选）、光照系统、翻牌和波纹、9 种剪影加巨龙、碎裂、升级演出、屠龙序列、HUD 和图鉴、音效、背景音乐（底层、风、水滴、竖琴）、全部界面和转场、debug 接口、桌面适配。
- **P1**：数字快开、静态层缓存、紧张层和苏醒层音乐、滚轮标记、自适应质量、情境提示全集。
- **P2**：`npm run sim` 平衡脚本、图鉴槽点击浮窗。

### 10.2 阶段

| 阶段 | 内容 | 完成标准 |
|---|---|---|

### 10.3 风险与对策

| 风险 | 对策 |
|---|---|
| 低端机全屏合成掉帧 | 光照图低分辨率；不用滤镜和阴影模糊；静态层缓存；自适应质量四级降档；DPR 上限 2 |
| 黑暗太重、看不清暗砖或标记 | 暗砖基色偏亮（albedo 和光照分离）；远处可见度保底 0.12；前沿渗光；指尖火把；标记画在光后层并带自发光；截图逐项检查对比度 |
| 「数字 = 等级和」和「数字会变」难理解 | 引导前两步专门教；数字滚轮动画让变化可见；图鉴给出全局剩余；消息行实时说明 |
| 平衡偏难或偏易 | 数值集中在 config；模拟脚本可重跑；debug 接口快速验证后期；引导局使用固定的温和布局 |
| 长按与系统手势冲突（iOS 放大镜、文本选择、右键菜单） | CSS 禁用加 `preventDefault`；`setPointerCapture`；长按期间屏蔽 `contextmenu` |
| 演出和逻辑不同步 | 逻辑同步结算、视图只消费事件；director 支持快进；R12 输入锁 |
| 字体加载晚于烘焙 | `FontFace.load()` 超时 1500ms；超时先用衬线回退烘焙，加载完成后重烘字形图集 |
| iOS 音频解锁或中断 | 每次手势都检查 `ctx.state`；`interrupted` 时恢复；静音开关独立 |
| 范围膨胀 | 严格按 P0 → P1 → P2；阶段 A 先保证完整流程可玩，再叠加画面 |
| 种子重抽导致复现不一致 | 重抽使用确定性的 `seed + k` 序列，debug 浮层显示「种子 #s（第 k 次重抽）」 |
