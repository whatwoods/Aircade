## 1. 一句话卖点与体验目标

**一句话卖点**：丛林遗迹里，一串刻着 2、4、8……的玉石珠子沿着石槽滚向金蛇之口。你转动中央的玉蛇图腾，把数字珠射进链条：**相同数字相邻就合成翻倍，并把整条链往回拉一格**；合成出的新珠又和邻居相同就继续连锁，像 2048 一样「咔—咔—咔」一路翻上去，直到凑出本关的**金印数**（64、128……2048），金光一闪，封印消除。

**玩家必须懂的一条规则**（引导、标题副标、首关 HUD 都围绕它）：
> **相同数字挨在一起就合成翻倍，链条往回缩；凑到金印数就封印。在链头进入金蛇口之前，完成本关的金印数量。**

### 1.1 体验目标

| 项 | 目标 |
|---|---|
| 一局时长 | 首局 4–6 分钟（含约 30 秒引导，通常止步第 4–6 关）；认真玩家 9–13 分钟（第 9–12 关）；高手进入无尽，15–20 分钟内结束 |
| 单关时长 | 前 2 关 25–50 s（快速给成就感）；中后期 45–80 s |
| 重开节奏 | 结算点「再来一局」到能再次发射 ≤ 2 秒 |
| 首屏 | ≤ 1 秒出现标题和可点击的「开始」，≤ 3 秒进入可操作状态 |
| 理解规则 | 30 秒内，靠 4 步操作式引导（§6.3） |
| 核心爽点（按优先级） | ① 阶梯连锁：一发打出 4、5、6 连，音阶一级级上行，数字一格格翻 ② 金印封印：金光、钟声、链条被震退 ③ 千钧一发：链头离蛇口只差两球时一发连锁把链拉回来 ④ 「三合一」：左右都相同，直接 ×4 |

### 1.2 压力从哪里来（核心设计问题的回答）

1. **持续推进**：链条尾部被入口闸门不断推出，链头一刻不停地逼近蛇口。
2. **弹性推进（rubber band）**：链头离蛇口越远，推进越快（最多 3.5 倍）。玩家一波大连锁把链拉回去，链条会以肉眼可见的速度「追回来」。**打得好换来的是喘息，而不是永久的安全**，所以高手也始终有压力，这是对第一批「中期没压力」问题的结构性回答。
3. **2048 式碎片化**：链上的数字会越合越大。大数字（32、64……）彼此不相邻时就成了「拦路石」，要凑它们得花好几发。凑数需要时间，时间就是距离。
4. **遮挡**：轨道盘绕，前排的珠子挡住后排。想打的目标未必打得到。
5. **关卡递进**：后面的关推进更快，金印数相对出生数字更大（需要更多次合成），轨道更长、更绕、有石桥遮挡。
6. **无尽**：第 12 关后进入无尽，推进速度每关 ×1.08，必然终结。

释放来自：每次合成链头回缩 1 球；金印封印回缩 3 球并全链定身 1 秒；缺口两端相同时前段自动回吸，连锁继续。

### 1.3 情绪曲线（单关）

```
紧张度
 高 │                          ╭╮千钧一发  金印!           ╭─╮最后一枚金印 → 退潮结算
    │              ╭─╮        ╱ ╰╮        ╱╲        ╭────╯  ╰╮
 中 │   ╭─╮      ╭╯  ╰╮ ╭───╯   ╰─╮   ╭─╯  ╰──╮ ╭╯          ╰──
    │ ╭╯  ╰──╮ ╭╯     ╰╯          ╰──╯        ╰╯
 低 │╯滚入    ╰╯
    └─开场滚入(3s)─┬─搭阶梯(10-30s)─┬─追赶与反扑(30-70s)─┬─收官─→ 时间
```

- 开场链条从闸门快速滚入，停在轨道约 28% 处，横幅报出「金印 64 × 3」。
- 搭阶梯：玩家寻找 `4·8·16·32` 这样的升序段，射最小的那头。
- 追赶与反扑：弹性推进把链头推到 50–70%，危险区开始泛红，一枚金印把它震回去。
- 收官：最后一枚金印落下，入口闸门关闭，残链倒流回闸门，每颗珠子化成分数。

## 2. 技术选型

### 2.1 总览

| 层 | 选择 | 理由 / 对比 |
|---|---|---|
| 渲染 | **Canvas 2D**：一张静态背景画布（每关烘焙一次：丛林庭院 + 石槽轨道）+ 一张动态主画布（链条、图腾、弹道、粒子、跳字）+ DOM UI 浮层 | 同屏最多约 85 颗珠子 + 600 粒子，每颗珠子 3 次 `drawImage`，Canvas 2D 在中端手机上绰绰有余。PixiJS/WebGL 运行时 400 KB+，首包翻好几倍；本作没有需要着色器的大面积特效（光束、光尘都可以用预渲染渐变精灵 + `lighter` 混合做）。第一批 sling-merge 已验证同类方案能稳 60fps |
| 核心算法 | **路径约束运动学**，不需要物理引擎：轨道 = 圆角折线 → 每 2 px 采样的弧长查找表（LUT）；链条 = 若干「段」（segment），段内珠子以 D 等距排列；弹丸 = 240 Hz 子步的圆–圆检测 | Matter.js（gzip 25.8 KB）这类刚体引擎解决的是自由碰撞，而祖玛链条是「沿曲线一维移动」，用引擎反而要用约束硬拽回轨道，且不确定。一维模型完全确定、可复现，同一份代码可以被 Node 里的模拟器直接调用 |
| 逻辑步进 | 固定步长 120 Hz（弹丸再细分 2 个子步），渲染插值；单帧最多追 8 步 | delta time + 限制最大步长 |
| 动画/缓动 | 自研 `tween`（缓动函数 + 补间池）+ `spring`（自适应子步），约 2 KB | GSAP 太重；第一批踩过的坑：低帧率下弹簧发散，所以弹簧按 `ceil(dt·ω·2.5)` 细分 |
| UI | 原生 DOM + CSS（无框架） | 面板、按钮用 DOM：文字清晰、可访问（role/aria）、Playwright 可用 `getByRole` 定位。分数、金印、链头进度等 HUD 也用 DOM（只在数值变化时写，transform/opacity 动画） |
| 音频 | WebAudio 实时合成：振荡器、FM、噪声、双二阶滤波、包络、卷积混响（程序生成的脉冲响应）、压缩器 | 素材约定要求程序化；连锁音高要按连锁步数实时升调，合成器天然适合 |
| 字体 | `@fontsource/bungee`（latin 400，14.3 KB）做 Logo/标题/分数；`@fontsource/big-shoulders-display`（latin 800，14.6 KB）做珠子上的数字和 HUD 数字。共 **28.9 KB** | 见 §4.3 的实测数据 |
| 构建 | Vite 8 + TypeScript 6（strict，`erasableSyntaxOnly`），npm | 与第一批一致。`erasableSyntaxOnly` 让 `src/game/` 的纯逻辑可以被 Node 22 原生类型剥离直接运行（已在本机 Node v22.22.0 验证 `.ts` 互相 import 可直接 `node` 执行），模拟器不需要额外依赖 |

### 2.3 轨道与链条算法（实现依据）

**轨道**
- 每条轨道是一组控制点 + 每个拐角的圆角半径（§3.10）。构建时把直线段和圆弧段按弧长采样，每 2 px 一个点，存成 `Float32Array` 的 x、y、切线角三张表。`posAt(s)` 是查表 + 线性插值，O(1)。
- 轨道参数：`s ∈ [0, Ltrack]`。`s < gateLen`（64 px）的部分在入口闸门石拱里（看不见、打不到）。`s = Ltrack` 是金蛇口（洞）。
- 可选的 `tunnels: [s0, s1][]`：石桥遮挡段。珠子画在桥下（只露出 30% 透明轮廓），不能被击中；弹丸撞到桥面会碎掉。

**链条**
- 珠子结构：`{ id, level, s, seg, renderOffset, pendingCheckAt, flags }`，对象池 160。
- 链条由若干**段**组成，段内珠子紧贴：`ball[k].s = seg.headS − k·D`。段按从链头到链尾排序。
- 每个逻辑步：
  1. **尾段**（含最后一颗珠子、与入口相连）以推进速度 `v` 前进（§3.6）；全链「定身」时不动。
  2. **非尾段**默认静止。若被标记「回吸」（缺口两端数字相同，§3.4），则以 `attractSpeed` 向后（朝尾部）移动。
  3. 后段的头珠与前段的尾珠距离 ≤ D 时两段**接合**为一段，并在接合点做一次合成判定（§3.4）。
  4. 入口补珠：如果仍在出珠，且尾珠 `s ≥ D`，就在 `s = 尾珠 s − D` 生成一颗新珠。
- **插入**和**合成**是离散的模型操作，立即改写数组和 `s`；视觉上用 `renderOffset`（弹簧衰减，约 120–180 ms）把跳变抹平。这让模型保持简单、确定，同时画面上珠子是「挤开」和「滑回」的。

**弹丸**
- 速度 `shot.speed` = 1500 px/s，半径同珠子。每个子步检测与所有「可击中」珠子（在轨道可见段、不在石桥下）的距离 `< D·0.92`。命中后计算插入侧（§3.3）。
- 弹道预测（瞄准线）：从图腾口沿瞄准方向做射线–圆求交，取第一颗可击中的珠子（同样考虑石桥遮挡）。弹丸飞行时间很短（通常 < 0.3 s，链条只移动 < 15 px），预测与实际的偏差在可接受范围；为了让预测与实际一致，命中判定与预测使用同一个函数 `raycastChain()`，并在发射瞬间锁定「目标珠 id + 插入侧」：如果真实命中的是同一颗珠子，插入侧沿用锁定值，避免链条微移导致左右侧翻转。

### 2.4 渲染方案

- **画布分层**：`#bg`（桌面两侧装饰，30fps 上限）、`#field-static`（本关静态场景烘焙图）、`#field`（每帧绘制）、DOM UI。`#field` 内的绘制顺序：轨道动态光（危险红光、缺口光）→ 链条阴影 → 链条 → 石桥前景 → 弹丸与拖尾 → 图腾 → 瞄准线与幽灵珠 → 粒子 → 跳字 → 放大镜。
- **珠子精灵**：每个等级在启动时烘焙三层（按 DPR，上限 2）：
  1. **本体纹理**（随滚动旋转）：材质底色 + 程序噪声纹理 + 一圈刻纹/镶嵌，旋转角 = `s / r`，能看出在滚；
  2. **光影层**（固定不转）：左上主高光、右下暗部、边缘环境光、底部反光，统一光源方向（夕照来自右上）；
  3. **数字层**（始终正立）：Big Shoulders 800，带 1 px 刻痕阴影 + 描边，颜色按等级（§4.4）。
  同屏 85 颗珠子 × 3 次 drawImage ≈ 255 次，远低于预算。
- **静态烘焙**：背景（渐变 + 噪点 + 石板 + 苔藓 + 藤蔓 + 暗角）和石槽轨道（槽壁斜面、金线镶边、苔藓斑）每关烘焙一次到 `#field-static`。
- **动态光**：god rays（3 束预渲染的渐变楔形，`lighter` 混合，缓慢摆动）、光尘（40–70 颗，池化）、萤火虫（夜色关卡多一些）。
- **自动质量档**（参考 sling-merge 的经验）：同时看 JS 帧耗时与 rAF 间隔，三档：高（全部效果）、中（光尘减半、无 god rays 摆动、粒子上限 400）、低（粒子 200、无光尘、无辉光精灵）。

### 2.5 音频

- WebAudio 在首次用户手势（点「开始」）后 `resume()`。主总线：音效总线 + 音乐总线 → 压缩器 → 输出。设置里音效、音乐可分别开关，并记住。

## 3. 核心玩法与规则

### 3.1 核心循环

```
看链条（找相同数字 / 找阶梯） → 瞄准（看幽灵珠和合成提示） → 必要时交换当前球
      ↑                                                      ↓
  链条推进 ← 链条回缩 / 定身 ← 合成·连锁·封印 ← 发射插入
```
- 一关的目标：在链头进入金蛇口之前，完成本关要求数量的**金印封印**。
- 一局 = 从第 1 关开始连续闯关，有 2 枚**玉佩**（生命）。失败一次碎一枚玉佩并重打本关；玉佩用完则本局结束。分数累计，最高分和最远关卡存本地。

### 3.2 数字与等级

- 珠子等级 `k ≥ 1`，数值 `2^k`：k=1 → 2，k=2 → 4，……，k=11 → 2048。
- 每关有出生范围 `[lo, hi]`（例如第 1 关是 2–8，即 k=1..3）和**金印等级** `sealLevel`（第 1 关为 6，即 64）。
- 静止时链上**不存在相邻相同**的珠子（不变式）：出生器保证不生成；任何时刻出现相邻相同都会立即触发合成。

### 3.3 发射与插入

1. 弹丸命中珠子 B（链上序号 i，0 = 链头）。
2. **插入侧**：取 B 处轨道切线（指向链头方向）`t`，若 `(P_hit − B)·t > 0`，插在 B 的前面（链头一侧，新序号 i），否则插在后面（新序号 i+1）。
3. 插入后，新珠前方（链头一侧）的所有同段珠子向前推 1 球（`s += D`）。即：**一次不产生合成的插入会让链头前进 1 球**。
4. 新珠在 `merge.settleDelay`（90 ms）后进行合成判定。视觉上弹丸从命中点滑入槽位（90 ms，outQuad），两侧珠子被挤开。
5. 弹丸飞出场地边界：记为「落空」，连击（§3.8）中断，没有其他惩罚。
6. 弹丸撞到石桥：碎成石屑，记为落空。
7. 发射冷却 `shot.cooldown` = 0.22 s；场上最多同时 2 颗弹丸。

### 3.4 合成、连锁、三合一、封印、缺口回吸（判定顺序）

**触发**：一颗珠子 X 需要判定（刚插入、刚合成出来、或段接合时的两颗接触珠）时，到 `pendingCheckAt` 时刻执行：

1. 只看**同段内紧贴**的前邻 F（链头一侧）和后邻 R。
2. 若 F 与 R 都等于 X：**三合一**。三颗合成一颗，等级 +2（数值 ×4），结果放在 R 的槽位，F 和 X 的槽位移除，F 之前的所有同段珠子后退 2 球。
3. 否则若 F 等于 X 或 R 等于 X：**合成**。两颗合成一颗，等级 +1，结果放在**靠尾一侧**那颗的槽位，另一颗移除，结果前方的同段珠子后退 1 球（链头回缩 1 球）。
4. 否则：结束，本次连锁终止。
5. 合成结果 Y 若 `Y.level ≥ sealLevel`：进入**封印**（见下）。否则 Y 在 `stepDelay(n)` 后再判定一次（回到 1），形成**连锁**。`stepDelay(n) = max(60, 130 · 0.88^(n−1))` ms，n 为本次连锁的第几步，越连越快，节奏感上扬。

**封印**（Y 达到金印数）：
1. Y 变成金印：定格 0.35 s（金光包裹、数字放大），同时**全链定身** `seal.freeze` = 1.0 s（推进和回吸都停）。
2. 0.35 s 时 Y 碎成金粉飞向 HUD 的金印计数，Y 被移除，原地留下 1 球的**缺口**，链在此处断成前后两段。
3. 前段被**震退** `seal.knock` = 2 球（0.4 s，outCubic）。缺口扩大到 3 球。
4. 若缺口两端（前段尾珠、后段头珠）数字相同：前段被标记**回吸**，定身结束后以 `attractSpeed` = 420 px/s 向后滑，接触时合成，**连锁计数延续**（算作同一发的连锁）。
5. 若两端不同：前段静止，等后段被推上来接合；接合时照常判定一次（通常不合成）。
6. 封印数 +1。达到本关配额时进入**收官**（§3.7）。超出配额的封印照样得分。

**补充规则与边界**
- 同时有两处等待判定（例如两颗弹丸先后命中），按 `pendingCheckAt` 时间先后处理；同一时刻按链上序号从链头到链尾处理。一颗珠子在判定前已被别的合成吞掉，则它的判定作废。
- 三合一 3 颗中任何一颗正处于另一个判定流程中，也照常执行（判定是即时的，没有锁）。
- 若合成导致整段被清空（只可能是封印），段删除。
- 弹丸可以击中正在回吸的段、已停下的前段，规则相同。
- 新数字珠在入口闸门内（`s < gateLen`）时打不到，但会参与连锁（它就在链里）。
- 链条每颗珠子的数字永远是 2 的幂。数值 ≥ 10000 时显示为 `16K` 这类缩写（实际上金印最高 2048，只有三合一在封印瞬间可能短暂出现 4096、8192，它们 4 位数可以完整显示）。

**为什么这样设计**
- 「合成让链头回缩」把 2048 的合成直接翻译成祖玛的「消除即后退」：一发 1 次合成 = 抵消这次插入；连锁 ≥ 2 才真正把链拉回去。连锁越长退得越多，爽点和生存绑定。
- 只靠合成，链条永远只会「变短变大」而不会消失；**封印**是唯一的移除手段，它把「凑数」变成明确的目标（凑 64），同时制造祖玛式缺口和回吸，延续连锁。
- 关卡不要求清空链条（数学上清不空），胜利条件是封印配额，残链在收官时倒流结算，不会出现「最后几颗消不掉」的卡关。

### 3.5 发射球的数字（弹药）

- 弹药队列：**当前球**（在图腾口里）+ **下一个**（在图腾中央的眼窝里，始终可见）。
- **交换**：点击图腾（半径 46 px 内）、或底栏「交换」按钮、或桌面右键/空格。无限次，动画 140 ms。
- **生成规则**（每次需要新球时）：
  1. 候选等级 = 链上（只算可见可击中段的珠子）出现过的等级 L，且 `lo ≤ L ≤ sealLevel − 2`。链上没有候选时给 `lo`。
  2. 权重 `w(L) = sqrt(1 + count(L)) · ammo.decay^(L − lo)`，`ammo.decay` = 0.8（偏向小数字）。
  3. **救场**：链头进度 `p ≥ 0.7` 时，以 `ammo.rescueChance` = 0.3 的概率改为从最靠近链头的 6 颗珠子里随机取一颗的等级（若 ≤ sealLevel − 2）。
  4. **防重复**：若与前两颗生成的等级都相同，重抽一次。
- **失效重抽**：某个等级从链上完全消失时，队列里该等级的球在 0.25 s 内「符文翻转」变成新抽的等级（祖玛的同类规则，避免手里拿着无处可用的球）。
- 上限 `sealLevel − 2` 的原因：手里不会出现「射一发就封印」的球，金印必须靠连锁凑出来。
- **翡翠灵珠**（万能球）：一发引起的连锁步数 ≥ `wild.earnSteps` = 4 时获得 1 颗，最多持有 1 颗（已持有时改为 +500 分）。点底栏右侧的灵珠槽「装填」，下一发射出灵珠（再点一次取消）。灵珠命中珠子 B 后变成 B 的数字，从命中侧插入，并必然与 B 合成（随后照常连锁）。

### 3.6 链条推进

推进速度（只作用于尾段）：

```
v = stage.vBase · (1 + stage.creep · t_stage) · rubber(p) · near(p)       (px/s)
p = 链头 s / Ltrack       （链头 = 最前面那颗珠子）
rubber(p) = 1 + push.rubber · max(0, (push.rubberTo − p) / push.rubberTo)     push.rubber = 2.5, push.rubberTo = 0.5
near(p)   = p > push.nearFrom ? push.nearMul : 1                               push.nearFrom = 0.85, push.nearMul = 0.6
```

- **开场滚入**：关卡开始时以 `push.introSpeed` = 260 px/s 推进，直到链头到达 `push.introTo` = 0.28，然后切换到上式。滚入期间不能发射（可以瞄准），约 2.5–3 s，此时显示关卡横幅。
- **弹性推进**的手感：链头越靠后推进越快，玩家一次把链拉回 5 球，链条会在 2–4 秒里追回大部分。画面上入口闸门喷出尘土、尾部珠子滚动声变密，玩家能「听见」它在追。
- **近洞减速**：链头过 85% 时速度 ×0.6，给最后的挣扎时间，配合心跳音效。
- **定身**：封印时全链停 1.0 s。

### 3.7 胜负与关卡流程

- **失败**：链头珠子 `s ≥ Ltrack`，且链头所在段没有待判定的合成（有的话等它判定完，合成可能把链头拉回来）。随后：
  1. 全链以 600 px/s 冲进金蛇口（被吞的珠子依次闪灭），约 1.5–2.5 s，可点击跳过；
  2. 碎一枚玉佩。还有玉佩 → 「再试一次」横幅，本关重开（分数保留，本关封印数清零）；没有玉佩 → 本局结束，进入结算。
- **过关（收官）**：封印数达到配额的那一刻：
  1. 慢动作 0.4 s（timeScale 0.3），横幅「封印完成」；
  2. 入口闸门落下，停止出珠；当前弹丸照常飞完、连锁照常结算；
  3. 残链**退潮**：所有段以 360 px/s 倒流回闸门，每颗珠子进闸门时化为 `5 × 关卡号` 分并发出一个上行的叮声；
  4. 结算距离奖励：`clearBonus = round(1000 · (1 + 0.25·(stage−1)) · (1 − p_clear))`，`p_clear` 为达成配额瞬间的链头进度；
  5. 关卡小结卡片（1.6 s，可点击跳过）→ 进入下一关（若跨神殿，播放神殿转场）。
- 发射禁用的时段：开场滚入、退潮、失败吞噬、引导中不允许的步骤。

### 3.8 计分

| 事件 | 分数 |
|---|---|
| 合成（第 n 步） | `结果数值 × n × 连击倍率` |
| 三合一 | 上式再 ×2 |
| 封印 | `金印数值 × 5 × 连击倍率`（三合一越级封印再 ×2） |
| 退潮每颗残珠 | `5 × 关卡号` |
| 距离奖励 | 见 §3.7 |
| 已持有灵珠时再达成 4 连 | +500 |

- **连击**（连续命中）：连续每发都至少产生 1 次合成，连击数 +1；倍率 `1 + 0.1 · min(连击 − 1, 10)`，最高 ×2.0。一发不产生合成的插入、落空都会中断。
- 例：第 1 关射出 `4` 打进 `32·16·8·4`：4+4=8（8×1）→ 16（16×2）→ 32（32×3）→ 64 封印（64×4 + 64×5）= 8+32+96+256+320 = **712**。

### 3.11 链条出生器

出生器每次产出一个「片段」，再逐颗吐出：

| 片段 | 权重 | 内容 |
|---|---|---|
| 单颗 | `1 − stair − valley` | 在 `[lo, hi]` 内按 `0.75^(k−lo)` 加权随机 |
| 阶梯 | `stair` | 长度 2–4（不超过出生跨度），连续等级，50% 升序 50% 降序，例如 `4·8·16` 或 `32·16·8·4` |
| 山谷 | `spawn.valley` = 0.10 | `[k+1, k, k+1]`，例如 `16·8·16`：射一颗 8 → 8+8=16 → **三合一**成 64 |

- 后处理：若与前一颗相同，改为 `k+1`（超出 hi 则 `k−1`）；仍相同再换一次。保证不变式。
- 阶梯是本作的核心可读谜题：玩家一眼看出「从小到大一排」，射最小那头就能一路连上去。阶梯出现频率随关卡下降，后期更需要自己「搭」。

### 3.12 完整规则与边界情况清单

| 情况 | 处理 |
|---|---|
| 插入链头最前面（序号 0 的前面） | 合法。链头前进 1 球。若因此越过蛇口：若新珠有待判定的合成，等判定完再判失败 |
| 插入时两侧已经都和新珠相同 | 三合一（不变式保证插入前两侧不相同，所以三合一只来自「两侧都等于新珠」） |
| 合成结果与两侧都相同 | 三合一，等级 +2 |
| 三合一越过金印数（例如 sealLevel−1 的三合一） | 直接封印，封印得分 ×2 |
| 封印后缺口前段为空（封印的是链头珠） | 没有前段，不震退；链头 = 后段头珠 |
| 回吸中的前段被插入导致尾珠数字改变 | 每帧重算：两端不再相同则取消回吸，前段停下 |
| 两颗弹丸命中同一段 | 按命中先后依次插入，各自判定 |
| 收官后还在飞的弹丸 | 照常插入、照常结算，退潮在所有判定结束后开始（最长等 1.5 s） |
| 关卡开始时链条完全滚入前就有弹丸 | 不会发生：滚入期间禁止发射 |
| 当前球等级在链上消失 | 0.25 s 符文翻转重抽（§3.5） |
| 灵珠装填后射空 | 灵珠消耗（不退还），给出「落空」反馈 |
| 页面失焦 | 自动暂停 |
| 链条全空（理论上只在收官时） | 若未达配额却全空（极少：封印了最后一颗且闸门暂时没出珠），闸门立即出珠，并给一次「空场」奖励 +200 |

### 3.13 难度曲线与验证计划（规避第一批的问题）

**目标**（`npm run sim` 输出，作为验收门槛）

| 指标 | 新手机器人 | 认真机器人 |
|---|---|---|
| 一局中位时长（2 枚玉佩） | 4–6 min | 9–13 min |
| 止步关卡中位数 | 第 4–6 关 | 第 9–12 关 |
| 每关链头最远进度中位数 | 第 1–2 关 ≤ 0.6；第 3 关起 0.7–1.0 | 0.4–0.8（每关都有压力，但不撞墙） |
| 危险区（p ≥ 0.75）停留时间占比 | — | 每关 3–15% |
| 相邻关卡通关率落差 | ≤ 25 个百分点 | ≤ 15 个百分点（「突然成墙」检测） |
| 相邻关卡用时比 | — | ≤ 1.4 |

另有两项「一招鲜」检测：
- **贪心机器人**（总是打最近的一处能合成的位置，不看连锁、不交换）止步关卡要比认真机器人少 ≥ 3 关，说明规划有价值。
- **乱射机器人**（0.5 s 一发，随机打能看到的珠子）不得超过第 3 关，说明狂点没用。

**机器人定义**（`src/game/bots.ts`，模拟器和 `__game.autoplay()` 共用）：都使用真实轨道几何。每次决策时按 1° 间隔扫描 360° 射线，用 `raycastChain()` 得到每个方向的「目标珠 + 插入侧」，再克隆模型模拟结果打分。
- 新手：1.6 s/发（±25% 随机），只认「插入后立即合成」（看不到连锁），60% 的决策只看随机 1/3 的方向，瞄准误差 ±2.5°，不交换、不用灵珠。
- 认真：1.25 s/发，完整模拟连锁与封印，打分 = 合成步数 + 6 × 封印 + 0.4 × 「插入后形成阶梯」+ 链头附近权重，瞄准误差 ±1°，会交换、会用灵珠。
- 高手（参考用）：1.0 s/发，误差 ±0.5°，额外考虑下一个球的组合。

**阶段 1 抽象原型的结果**（Python 草稿，放在会话临时目录、不入库；不含几何遮挡，链条为一维数组，可见性用概率近似；每个机器人 30 局完整闯关 + 每关 30 次单关测试）：
- 用上表数值（2 枚玉佩），新手止步第 7 关（中位，约 8 min）、认真止步第 13 关（约 15 min）、高手第 18 关（约 19 min）。抽象模型没有遮挡和飞行时间，机器人能看到的选择比真人多，明显**偏乐观**；实际游戏会更难，数值的量级是对的，M2 用真实几何再收紧。
- 加入弹性推进之前，认真机器人在前 9 关链头从未超过 0.35（完全无压力）；加入后各关链头最远进度中位数为 0.34 → 0.96，平滑上升。弹性推进必须保留。
- 发现的台阶：① 原第 6 关配额 4 时新手通关率从 80% 掉到 33%，已改为 3（现为 63%）；② 第 6 → 7 关（换轨道 C + 金印 512）新手通关率 63% → 23%，超出 25 个百分点的门槛，M2 优先处理（候选：第 7 关 vBase 降到 36、或出生范围先保持 4–32）；③ 第 12 关（2048 × 4）是终章，认真机器人通关率 60%，属于有意的高峰。
- 阶段 2 用真实几何的模拟器复跑，按上面的门槛调 `vBase`、配额和 `stair`，结果和调参记录写回本文 §11。

## 4. 美术方向

### 4.1 风格关键词

**夕照下的丛林神殿 · 雕刻石材 · 透光玉石 · 鎏金铜。** 画面像一块被藤蔓覆盖的古代石雕游戏盘，在傍晚的暖光里，玉珠沿着刻出来的石槽缓缓滚动。

- 和第一批区分：dungeon-sweeper 是冷灰蓝石砖 + 暗夜烛光；本作是**苔绿暖灰的石头 + 明亮的夕照**，主体色是翡翠绿而不是黑。brick-survivor 的霓虹、sling-merge 的糖果浅色、pack-battle 的皮革纸张都不沾。
- 和同批区分：five-drop 是冷感极简、雾蓝灰、留白；hanzi-merge 是宣纸墨色。本作是**饱满、有体积、有金属反光**的厚重质感。
- 形状语言：圆（珠子、日轮、图腾）+ 阶梯状几何（玛雅式阶梯纹、回纹、羽蛇鳞纹）。UI 面板是**石板**，四角有阶梯形切角，边缘一圈鎏金线。

### 5.3 音色配方（WebAudio）

| 音 | 配方 |
|---|---|
| 钟片（合成） | 正弦 + 3.01 倍频 FM（调制指数 1.2 → 0），包络 A 2 ms / D 260 ms；音高从五声音阶 C D E G A 逐步上行，从 C5 开始，第 n 步升一个音级；数值越大加一层低八度 |
| 石头敲击 | 带通噪声（1.8 kHz，Q 4）10 ms 爆发 + 220 Hz 正弦 40 ms 快衰 |
| 铜锣（封印） | 3 个非整数倍频的正弦（1, 1.47, 2.13）× 110 Hz，慢衰 1.6 s + 噪声敲击 + 卷积混响 |
| 发射「咻」 | 白噪声 → 带通，中心频率 3 kHz → 800 Hz 指数下滑 120 ms |
| 心跳鼓 | 55 Hz 正弦，音高包络 90 → 50 Hz，两连击（「咚—咚」） |
| 玉石碰 | 2.4 kHz、3.6 kHz 两个正弦，极短衰减 |
| 吞噬 | 锯齿 200 → 40 Hz 下滑，低通 600 Hz，1.2 s |

### 5.4 程序化背景音乐

- 风格：丛林遗迹氛围。拇指琴/马林巴式音色（三角波 + 短衰减 + 轻微 FM）弹五声音阶的循环乐句（4 小节，按种子在 8 个动机里选），手鼓（滤波噪声 + 低频正弦），远处的鸟鸣与虫鸣（随机触发的调频啁啾、带通噪声）。
- 速度 92 BPM，每个神殿换一个调（I: D 宫，II: F 宫，III: A 羽，IV: C 宫）。
- 动态层：链头进度 p < 0.5 只有拇指琴 + 环境；p ≥ 0.5 加手鼓；p ≥ 0.75 加低音通鼓，拇指琴转小调变体；p ≥ 0.9 整体低通 1.2 kHz，只保留鼓和心跳。层切换用 1 小节淡入淡出。
- 合成音效的钟片音与背景同调（按当前神殿的调取五声音阶），连锁听起来像在演奏。

### 5.5 粒子、跳字与对象池

- 粒子池 600（中档 400，低档 200）：碎屑（按材质着色的小多边形，带重力和旋转）、金粉（加色混合的发光点）、尘土、光尘、萤火虫、冲击波环（每个 1 个对象，池 8）。
- 跳字池 12，同屏最多 6 条。**避让规则**：
  1. 一发的整个连锁只出 1 条累计跳字：第一步出现在合成点上方 26 px，之后每步更新同一条（数字累加并弹跳），跟随最后一步的位置平滑移动；
  2. 「连锁 ×N」徽章固定在图腾上方 70 px（不跟随合成点），避免和跳字叠在一起；
  3. 新跳字与已有跳字（含剩余上浮路径）相交时，按「上 → 左右 → 下」寻找空位；
  4. 跳字不进入 HUD 顶栏（y < 96）和底栏（y > 756），不压在图腾上；
  5. 让不开就省略（分数照常计入）。
- 拖尾段池 48，弹丸池 4。

### 6.1 流程

                      关卡内: 开场滚入 → 进行 → (收官 → 退潮 → 小结 → 下一关) | (失败吞噬 → 玉佩碎裂 → 重打 | 结算)

- 场景状态：`boot | title | playing | results`；关卡子状态：`intro | live | clearing | summary | failing`；叠加层：`paused | settings | tutorial`。
- `visibilitychange`（hidden）和 `blur` 时，若在 playing，自动暂停（显示暂停面板）；hidden 时停 RAF。回来停在暂停面板，由玩家点「继续」。

### 6.2 标题页

- 画面见 §4.6 ①。「开始」按钮是 HTML 里的静态 DOM，JS 加载完立即可点（字体、精灵在后台烘焙，先用系统字体显示）。
- 点「开始」先解锁音频再转场；未完成引导则第 1 关进入引导子状态。
- 键盘：Enter 开始。

### 6.3 首局引导（逐步脚本，目标 ≤ 30 s，全部在操作中教）

- 首次进入（`tutorialDone` 不存在）自动启用；设置「重看引导」或标题「玩法」也可进入。
- 引导期间：链条定身（第 4 步前），失败判定关闭；顶部右侧有「跳过引导 »」按钮（270,100,108,44）。
- 引导卡片：DOM 石板卡片，(24,100,240,64)（左对齐，给右侧跳过按钮留位），`pointer-events: none`，不挡瞄准。卡片永远在屏幕上方 1/5，**链条的引导布置一律放在图腾下方或侧方**，卡片和手指都不会挡住目标。
- 手势提示：半透明 SVG 手，CSS 关键帧循环演示「按住 → 拖向目标 → 松开」。

| 步 | 布置 | 卡片文案 | 引导视觉 | 完成条件 | 失败兜底 |
|---|---|---|---|---|---|
| T1 合成 | 轨道 A，链条只有 3 颗 `16·2·8`，位于图腾右下方（轨道下边），定身；当前球 `2`，下一个 `8` | 「按住瞄准，松手发射：把 **2** 射到 **2** 旁边」 | 手势从图腾拖向链上的 `2`；目标 `2` 外圈脉动 | 发生合成 | 打到别处：插入的珠子 0.6 s 后淡出复位，文案「差一点！幽灵珠旁出现 ＝ 时再松手」；3 次失败后自动帮玩家合成一次并继续 |
| T1 反馈 | — | 「相同数字 → 合成翻倍，链条缩短一格」（1.6 s） | 合成正常特效；链头方向的珠子回缩时，一个箭头沿轨道往回指 | 自动 | — |
| T2 连锁 + 金印 | 链条变为 `32·16·8·4`（从闸门方向快速滑入就位），当前球 `4`；HUD 金印徽章「64」高亮 | 「数字相同会接着合成——打出连锁！」 | 手势指向 `4` | 发生封印 | 同上 |
| T2 反馈 | — | 「凑出 **64** = 金印！封印即消除，还会把链条震退」（2 s） | 金粉飞向 HUD，徽章下第一颗菱形亮起并有指引光圈 | 自动 | — |
| T3 交换 | 链条 `8·2·16`；当前球 `4`（链上没有 4），下一个 `2` | 「手里的 4 没有搭档：点一下**图腾**换球」 | 图腾外圈脉动 + 手势点按图腾 | 完成交换，并射出 `2` 产生合成 | 交换后又换回：不计失败，继续提示 |
| T4 压力 | 解除定身，链条从闸门滚入（第 1 关正式开始，已有 1 枚金印计入，配额 2） | 「链条会一直推进，链头进入**金蛇口**就失败。再封印 1 枚就过关！」 | 金蛇口闪烁 3 次，进度条高亮一次 | 3 s 或第一次发射 | — |

- 完成 T4 后写入 `tutorialDone = 1`。整个引导玩家只需要操作 3 发 + 1 次交换，约 25–30 s。
- **情境提示**（每条只出现一次，记入 `tips` 位掩码；在底栏中间提示条 (80,776,230,40) 显示 2.5 s；同一时间只显示一条，排队）：
  1. 第一次在可见范围内出现「升序阶梯」（第 2 关起）：「从小到大的一排，打最小的那头能连到底」，并在那段阶梯下画一条淡金色下划线 2 s；
  2. 第一次三合一：「两边相同，三合一，直接 ×4！」；
  3. 第一次获得灵珠：「翡翠灵珠：会变成被击中的数字，点右下角装填」；
  4. 第一次进入危险区：「合成能把链条往回拉！」；
  5. 第一次出现缺口回吸：「缺口两端相同会自动吸合，连锁继续」；
  6. 第一次瞄准时手指压住了命中点超过 0.6 s：「手指放在图腾和目标之间，看得更清楚」。

### 6.4 操作（竖屏手机）

- **按住即瞄准，松手即发射**：在场地内（不在按钮上）按下，瞄准方向 = 从图腾中心指向手指。射线延伸到第一颗可击中的珠子，所以**手指不必压在目标上，放在图腾和目标之间即可**，命中点和幽灵珠都在手指前方，不被挡住。
- **放大镜**：当预测命中点距离手指 < 60 px（被手指挡住）时，在手指上方 120 px 处显示一个 r = 48 的圆形放大镜（×1.6，金边），里面是目标珠、幽灵珠和左右邻珠的数字。手指在 y < 220 时放大镜改到手指的左侧或右侧（朝屏幕中心）110 px。设置里可关闭。
- **快速点按**：按下到抬起 < 180 ms 且移动 < 12 px，直接朝点按位置发射（老手的快节奏玩法）。
- **取消**：拖回图腾（中心 46 px 内）后松手，不发射。
- **交换**：点按图腾（按下和抬起都在图腾 46 px 内，且 < 250 ms）。底栏左侧也有「交换」按钮。
- **灵珠**：点底栏右侧灵珠槽。
- 只认第一个指针；`touch-action: none`；阻止长按菜单、双指缩放、页面滚动、文本选中。
- **桌面**：鼠标悬停即显示瞄准线（不必按住），左键点击发射；右键或空格交换；E 装填灵珠；Esc/P 暂停。

### 6.9 转场

- 面板进场弹簧 0.35 s，退场 0.2 s ease-in。任何转场阻塞输入不超过 0.45 s。

### 6.10 桌面适配

## 9. 性能预算与策略

**目标**：中端手机稳定 60fps；桌面帧时间 ≤ 5 ms。

| 项 | 单帧预算 |
|---|---|
| 逻辑（2 个 120 Hz 步：链条 + 弹丸 + 判定） | ≤ 1.0 ms |
| 瞄准射线（每帧 1 次，约 85 颗珠子的射线–圆求交） | ≤ 0.1 ms |
| 粒子与跳字更新 | ≤ 1.5 ms |
| 绘制（静态层 1 次 drawImage + 珠子 ≤ 255 次 + 粒子 ≤ 600） | ≤ 6 ms（GPU 光栅） |
| DOM（只在变化时写，只用 transform/opacity） | ≤ 0.3 ms |

- 帧内零分配：珠子、粒子、跳字、拖尾、弹丸全部池化；`balls()` 返回复用的数组。
- 机器人模拟与渲染完全解耦：`simulate()` 在暂停的游戏里同步跑纯逻辑，一局（12 关）< 1 s。
- 静态层每关烘焙一次（约 30 ms，放在开场转场的遮罩期间）。
- 自动质量档见 §2.4。

### 10.2 风险与对策

| 风险 | 对策 |
|---|---|
| **难度曲线**：高手无压力或某关成墙（第一批最常见的问题） | 结构上用弹性推进保证压力始终存在；关卡表在 M2 用真实几何的机器人模拟按 §3.13 的门槛调；「一招鲜」用贪心/乱射机器人检测 |
| 遮挡让人觉得「打不到想打的」 | 第一个神殿是单圈无遮挡；射线预测 + 幽灵珠 + ＝ 提示让结果确定；弹药只出链上可见的数字，并有救场规则 |
| 数字小、读不清 | D = 40，最小数字 15 px；每级不同材质、色相、纹理；`showcase()` 截图检查 |
| 预测和实际不一致（链条在弹丸飞行时移动） | 弹丸 1500 px/s；发射时锁定目标珠 id 和插入侧，命中同一颗时沿用 |
| 连锁太快看不清 | 每步 60–130 ms 逐步加速；整个连锁只出一条累计跳字和一个「连锁 ×N」徽章 |
| 手指遮挡 | 射线延伸设计（手指可在目标前方）+ 放大镜 + 情境提示 |
| 第 1 关链条数学上消不完 | 胜利条件是金印配额，残链收官时退潮结算 |
