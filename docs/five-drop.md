# 五子落 FIVE DROP —— 设计文档

> 俄罗斯方块 × 五子棋。落下来的方块由黑白棋子组成，同色横、竖、斜连成五子即消除。
> 每一块都要同时考虑两件事：**放得下**（形状）和**连得成**（颜色）。

---

## 1. 一句话卖点与体验目标

- **卖点**：熟悉的「下落、旋转、硬降」手感，加上五子棋的「看线」思维。棋子按颜色消除，留下的子会补位下落、连锁成新的五连，斜线也算。
- **体验目标**
  - 3 秒内能开始玩：标题页「开始」按钮立即可点。
  - 30 秒内懂规则：在引导中**亲手**连成横、竖、斜三种五连。
  - 2 分钟时第一次打出「双线交叉」或「连锁」，体验高潮。
  - 一局时长：新手 3–5 分钟，认真玩家 9–14 分钟（第 10.3 节用模拟器验证）。
- **情绪基调**：安静、精确、冷静。画面像一块放在北欧工作室窗边的雾蓝色石板，上面摆着黑曜石和白瓷做的棋子。高潮时刻是一道冰蓝色的光贯穿五子，棋子随即碎成玻璃和瓷片。

## 3. 核心循环、完整规则与初始数值

### 3.1 核心循环

```
出块 → 玩家平移/旋转/翻色/暂存 → 落地（锁定延迟）→ 锁定
  → 结算循环：[五连检测 → 消除 → 补位下落] 和 [满行检测 → 多数色退场 → 补位下落]，重复直到稳定（每一轮记一次连锁）
  → 失败检测 → （按时间）升级 / 插入垃圾行 → 出下一块
```

玩家**必须懂的那一条规则**：**同色棋子横、竖、斜连成 5 个（或更多）就会消除。**引导用三个实操步骤分别教横、竖、斜。

### 3.2 棋盘

- **9 列 × 15 行**可见区，上方还有 **2 行隐藏出块区**，逻辑网格共 9×17，行号 −2…14，第 0 行是可见区最上面一行。
- **逻辑上是「格子」，视觉上是「交叉点」**：棋盘线画在格子中心，棋子正好落在线的交点上，看起来像围棋盘。格子边界不画线。这样既保留俄罗斯方块的格子逻辑，又一眼就能认出是五子棋。
- **为什么是 9 列**
  1. 五连横向需要 5 格，9 列能容纳横线和对角线，同时又窄到足以产生堆叠压力。
  2. **奇数**列让「满行多数色」判定（第 3.6 节）永远不会平局。
  3. 竖屏可读性：在 390 宽的屏幕上，格子是 **38px**，棋子直径 34px（格子的 0.9 倍）。黑白对比在雾蓝底上清晰可辨，手指拖动时每列的步长足够大，不容易误移。
- 星位（hoshi）小点画在 (2,3)、(6,3)、(4,7)、(2,11)、(6,11)，纯装饰。

### 3.3 方块

**形状**：没有五格块。五格直条单色时会直接送出一条五连，太容易；而且在 9 列的棋盘上太笨重。也不出二格块，只在引导里使用。

| 形状 | 格数 | spawn 朝向（在 N×N 框内的格子坐标 x,y，顺序就是颜色序号） | 框 N |
|---|---|---|---|
| I | 4 | (0,1)(1,1)(2,1)(3,1) | 4 |
| O | 4 | (0,0)(1,0)(0,1)(1,1) | 2 |
| T | 4 | (1,0)(0,1)(1,1)(2,1) | 3 |
| S | 4 | (1,0)(2,0)(0,1)(1,1) | 3 |
| Z | 4 | (0,0)(1,0)(1,1)(2,1) | 3 |
| J | 4 | (0,0)(0,1)(1,1)(2,1) | 3 |
| L | 4 | (2,0)(0,1)(1,1)(2,1) | 3 |
| I3 | 3 | (0,1)(1,1)(2,1) | 3 |
| V3 | 3 | (0,0)(0,1)(1,1) | 2 |

- 每一格都带颜色：`B`（黑曜石）、`W`（白瓷）或 `X`（冰晶子，第 3.8 节）。
- **旋转**：整块连同颜色一起刚性旋转。顺时针 `(x,y) → (N−1−y, x)`，逆时针 `(x,y) → (y, N−1−x)`。**O 块也能旋转**：位置不变，四个颜色轮转，这是一个有用的操作。
- **踢墙**：按顺序尝试偏移 `(0,0) (−1,0) (+1,0) (0,−1) (−1,−1) (+1,−1) (−2,0) (+2,0)`（y 负为向上），第一个不碰撞的生效，全部失败则旋转无效（播放轻微的「咔」声，方块左右晃 2px）。所有形状共用这张表，逆时针也一样。
- **翻色**：把当前方块的黑白全部互换，冰晶子不变。**不限次数，没有代价。**
  - 理由：①不让玩家因为「来错颜色」而陷入无解的挫败。②方块内部的黑白排列（哪一格是少数色）仍然是硬约束，翻色只是让「主色」可选，并不会让颜色变得无关紧要。③翻色加旋转的组合本身就是一个有趣的小谜题。
  - 翻色算一次「操作」，会重置锁定延迟（受 15 次上限约束）。
- **暂存（HOLD）**：1 格。每块落地前只能用一次。存入的方块回到 spawn 朝向，**保留**翻色状态。暂存区为空时，暂存后直接出下一块。
- **预告（NEXT）**：显示 3 块，颜色排列全部可见。

**方块生成**
1. **形状**：9 袋随机（每袋 I O T S Z J L I3 V3 各一个，洗牌后依次发）。三格块约占 22%，作为调整「堆叠速度」的旋钮。
2. **颜色类别**（按等级段加权，见下表）
   - 4 格块：`纯色` 4:0 / `主次` 3:1 / `对半` 2:2
   - 3 格块：`纯色` 3:0 / `主次` 2:1（对半的权重并入主次）

| 等级 | 纯色 | 主次 | 对半 |
|---|---|---|---|
| 1–3 | 40 | 45 | 15 |
| 4–7 | 30 | 45 | 25 |
| 8+ | 22 | 43 | 35 |

3. **具体排列**：主次型的少数色格从各格中均匀随机挑选；对半型从全部 C(4,2)=6 种分法中均匀随机。
4. **主色选择**（只影响视觉平衡，因为玩家可以翻色）：`p(黑) = clamp(0.5 + 0.4 × (盘面白子数 − 黑子数) / max(10, 盘面子数), 0.2, 0.8)`。
5. **防干旱**
   - 连续 5 块没有纯色时，强制下一块纯色。
   - 对半型不连续出现超过 2 次。
   - 生成器只看「将要出的块」，不会读盘面替玩家作弊。
6. **可解性**：不保证每一块都能凑成五连（这本来就是策略的一部分），但以下机制保证不会被逼进死角：翻色、暂存、3 块预告、满行退场（第 3.6 节）、冰晶子（第 3.8 节）。模拟器的「新手」机器人在 90% 的局里第一分钟内就能打出至少一次五连（第 10.3 节的验收项）。

### 3.4 下落、锁定与操作时序

| 参数 | 初始值 | 说明 |
|---|---|---|
| 重力 `secPerRow(L)` | `max(0.12, 0.90 × 0.86^(L−1))` 秒 | L1 0.90s，L4 0.57s，L7 0.37s，L10 0.23s，L15 0.12s |
| 软降 | `min(重力, 0.035s/行)` | 每格 +1 分 |
| 硬降 | 瞬间落到影子位置并立刻锁定 | 每格 +2 分 |
| 锁定延迟 | 500ms | 移动、旋转、翻色成功都会重置计时，每块最多重置 15 次，用完后一着地就锁定 |
| 出块位置 | 框水平居中：`x = floor((9 − N)/2)`；框的位置使方块最低格位于第 −1 行，出块后立即下移 1 行（能移就移） | 出块后玩家立刻能看到方块 |
| 出块延迟（ARE） | 无消除时 100ms；有消除时等结算动画结束后再 100ms | |
| 键盘 DAS / ARR | 150ms / 40ms | |
| 硬降防误触 | 新方块出现后 150ms 内不接受硬降；方块出现前就已经按下的指针手势一律作废 | 防止一次甩动连砸两块 |

### 3.5 五连判定（核心规则）

**判定时机**：方块锁定后，以及每次补位下落结束后。下落过程中不判定。另外，垃圾行插入后不立即判定，留到下一次锁定时（第 3.9 节）。

**线的定义**：沿 4 个方向（横 →、竖 ↓、斜 ↘、斜 ↗），对颜色 c ∈ {B, W}，把「颜色为 c 或冰晶子 X」的格视为匹配，找出所有**极大连续段**。满足以下两个条件的段算一条 c 色线：
- 长度 L ≥ 5；
- 至少包含 1 颗真正的 c 色子（全由冰晶子组成的段不算）。

检测范围是整个 9×17 网格，包括隐藏行，这样在顶线附近消除也能救命。

**边界情况（明确裁定）**
1. **一颗子同时属于多条线**（十字、X 形交叉）：这颗子只消除一次，但每条线**各自计分**，并触发「多线加成」。被两条以上线共享的子在动画里获得「交点」特效（第 5 节）。
2. **连成 6 个以上**：一段极大连续段算**一条**线，长度 L 计入分数（`100 × (L−4)`）。不会拆成多个重叠的五连重复计分。
3. **冰晶子同时服务黑线和白线**：例如 `W W X B B B B` 这一段中，X 和后面四颗黑子组成长度 5 的黑线；对白色而言 `W W X` 只有 3，不成线。如果一颗冰晶子同时属于一条黑线和一条白线，两条线都成立，各自计分。
4. 同一结算轮中检测到的所有线**同时**消除（取所有线上格子的并集）。

### 3.6 满行规则：「多数色退场」

**问题**：传统的「满行整行消除」会让颜色变得无关紧要，玩家只要像玩俄罗斯方块那样填满就行。但如果完全取消满行，每条五连只能移除 5 颗子，而一个四格块就放进 4 颗；模拟估算要求约 80% 的落子都参与五连，大量「死子」（颜色凑不成线的子）会让堆叠失控，压力过大，形状也会退化成次要因素。

**规则**：一行 9 格全部填满时（填满后、且本轮五连检测没有检出任何线），这一行里**数量较多的那种颜色**全部消除，少数色的子**留在原位**。
- 冰晶子算作「随多数色一起消除」。
- 多数色按 B/W 计数。9 是奇数，非冰晶子的子数为奇数时不会平局；如果因为冰晶子导致 B=W 平局，则整行全部消除。
- 被移除格子上方的子按第 3.7 节的规则补位下落。

**为什么这样能让形状和颜色都真正重要**
- **形状重要**：满行是主要的「减压阀」，而洞会让一行永远填不满；五连也需要相邻的落点，洞会打断横线和斜线。
- **颜色重要**
  1. 一次满行最多移除 5–8 颗子（因为本行内必然没有同色五连，多数色最少 5 颗），少数色会留下来，而且留下的位置零散。只靠满行，堆叠仍会以每行约 4 颗的速度净增长，最终失败。所以**颜色同时关系到生存**，而不只是分数。
  2. 一行的颜色构成决定退场的子数：多数色越占优，清得越干净（8:1 时只留 1 颗）。
  3. 少数色留下后，上方的子会落进空位，形成新的相邻关系。有意识的玩家可以借此**故意造连锁**：满行退场之后紧跟一条五连，按连锁第 2 轮计分。
  4. 计分上，满行每颗子 15 分，五连每颗子约 20 分起，且有多线、连锁、长线加成，追分的玩家一定会以颜色为主。
- 模拟器用两个「对照机器人」验证这一点（第 10.3 节）：「色盲」机器人只按俄罗斯方块的标准堆叠，「形盲」机器人只看颜色、不管洞和平整度。两者的存活时间都必须明显短于综合考虑的「认真」机器人。
- 备选方案（`config.fullRow.mode`，供调平衡）：`'majority'`（默认）/ `'all'`（整行清除，预计颜色会失去意义）/ `'none'`（不处理满行，预计压力过大）。模拟器会对三种模式各跑一遍，结果记录在文档末尾的回填章节。

### 3.7 补位下落（重力）

**逐子下落，仅限受影响的列**：
- 设本轮被移除的格子集合为 S。对每一列 c，若该列有被移除的格子，令 `r* = 该列被移除格中最靠下的行`。
- 该列中位于 r* 上方的所有子，按原有上下顺序向下压实，落到「r* 及其下方最靠上的一颗子」之上（没有子就落到底）。所以 r* 下方原有的洞，如果紧挨着被清空的位置，也会被填上。
- **没有发生消除的列完全不动**：原有的洞和悬空结构都保留。方块落地时是刚性的，不会自动塌落。这保证了形状和洞依然重要。
- 动画上每颗子以重力加速度下落（`g = 6000 px/s²`），着地时轻微压扁回弹 80ms，同一列的子之间间隔 18ms 依次落下，形成瀑布感。

### 3.8 冰晶子（第 3 级起）

- 从 L3 开始，每生成一块方块，有 `p = 0.08` 的概率把其中 1 格（均匀随机挑选）换成冰晶子 X。连续两块不会都带冰晶子。从 L9 起 p 降到 0.06（后期更依赖技巧）。
- X 在判定时**可以当黑也可以当白**（第 3.5 节）；翻色时不变；满行时随多数色一起消除。
- 视觉上是半透明冰蓝玻璃（唯一的强调色），用来救急和制造双色交叉。
- 第一次出现时，在信息栏弹出提示：「冰晶子：当黑当白都算」。
- 理由：中期（L3–L6）加入一个新变量，避免玩法单调；也给后期混色排列增多带来一个可规划的解法。`config.crystal.enabled=false` 可以关掉，用于对比模拟。

### 3.9 等级与压力曲线

- **等级按时间推进**：每 **45 秒**升一级（暂停时不计时；结算动画期间正常计时），上限 L15（10:30 时达到），之后保持不变，但垃圾行间隔继续沿用 L15 的值。
  - 理由：俄罗斯方块按行数升级时，打得差的人反而永远慢速。这里压力必须稳定上升。玩家变强时，体现为得分增长和更从容地造连锁，而不是让难度变低。
- **压力来源和递进**

| 阶段 | 时间 | 压力来源 |
|---|---|---|
| 学习期 L1–2 | 0:00–1:30 | 慢速（0.9→0.77s/行），纯色块多，盘面空，几乎零风险地学习五连 |
| 发展期 L3–6 | 1:30–4:30 | 速度渐快（0.67→0.43）；对半型增加（25%）；冰晶子出现；死子开始积累，满行退场的规划成为必要 |
| 压迫期 L7–10 | 4:30–7:30 | **垃圾行**开始从底部涌入；速度 0.37→0.23；对半型 35% |
| 终局 L11–15 | 7:30– | 速度 0.20→0.12；垃圾行间隔缩到 7 块 |

- **垃圾行**（L7 起）
  - 每落 G 块，在下一块出块之前，从底部推入 1 行，整盘上移 1 行。G 的取值：L7=14，L8=12，L9=11，L10=10，L11=9，L12=8，L13 起为 7。
  - 垃圾行有 9 格，其中 1 个空位，列号随机，且与上一行垃圾的空位列不同；颜色从左到右随机，但同色连续最多 2 个。插入前检查：不得与原有棋子组成五连，最多重试 20 次；若仍组成五连，则保留现状，留到下一次锁定时正常结算。
  - 预警：提前 2 块时，棋盘底边出现冰蓝色呼吸光带，信息栏显示「↑ 2」倒数。
  - 垃圾行是半填满的、颜色杂乱的一行：填上空位就满行，触发多数色退场，同样需要动脑。
- **危险态**：任意棋子位于第 0–2 行时进入危险态：顶线变成警示色并呼吸闪烁，暗角加深，环境音乐低频增强。退出时淡出 400ms。

### 3.10 失败条件

以下任一情况发生即失败：
1. **出块碰撞**：新方块在出块位置与已有棋子重叠（block out）。
2. **顶出**：锁定并结算完毕后，仍有任何棋子位于隐藏行（第 −1、−2 行）。注意先结算再判断，所以在顶线附近消除可以救命。
3. **垃圾顶出**：垃圾行把任何棋子推入隐藏行。

本作是无尽模式，没有胜利条件，目标是高分。

### 3.11 计分

```
一轮五连得分 = Σ_i 100 × (L_i − 4)            # 每条线，L 为线长
           × 多线倍率  (1 + 0.5 × (n − 1))    # n = 本轮线数
           × 连锁倍率  [1, 2, 3, 5, 8][min(k,5)−1]   # k = 本块的第几轮结算（从 1 起）
           × 等级倍率  (1 + 0.1 × (L − 1))
一轮满行得分 = 15 × 移除子数 × 连锁倍率 × 等级倍率   # 满行也占用一轮连锁序号
连击奖励     = 50 × (combo − 1) × 等级倍率          # combo = 连续多少块都触发过至少一条五连（≥2 时才有）
清盘奖励     = 2000 × 等级倍率                       # 结算后盘面没有任何棋子
软降 +1/格，硬降 +2/格（不乘倍率）
```

- 所有得分四舍五入为整数。
- 例：L4（倍率 1.3）时，一块落下同时形成一条 5 连和一条 6 连（n=2），随后补位又形成一条 5 连（k=2）：
  第 1 轮 (100+200)×1.5×1×1.3 = 585；第 2 轮 100×1×2×1.3 = 260；合计 845。
- 结算统计：总分、时长、等级、五连数、最长线、最大连锁、最大同时线数、移除子数（五连 / 满行各占多少）。

### 3.12 结算顺序（完整伪代码，照此实现）

```
onLock(piece):
  写入棋子；k = 0；anyFive = false
  loop:
    lines = findLines(grid)                          # 第 3.5 节
    if lines 非空:
      k++；anyFive = true；S = 所有线上格子的并集
      得分(五连公式)；播放五连动画（等待）；移除 S；applyGravity(S)（等待）
      continue
    rows = fullRows(grid)                            # 只看可见行和隐藏行中被填满的行
    if rows 非空:
      k++；S = 每一满行中多数色和冰晶子的格子（平局则整行）
      得分(满行公式)；播放满行动画（等待）；移除 S；applyGravity(S)（等待）
      continue
    break
  combo = anyFive ? combo + 1 : 0；按需给连击奖励
  if 盘面为空: 清盘奖励
  if 隐藏行有子: 失败（顶出）
  若到了垃圾行插入时机: 插入垃圾行（若顶出则失败）
  出下一块（若碰撞则失败）
```

**规则测试用例**（`npm run rules`，用 ASCII 盘面描述，断言消除的格子、得分、补位后的盘面）：横/竖/两种斜向五连；6 连和 9 连；十字交叉共享 1 颗子；X 形交叉；冰晶子同时连成黑线和白线；满行 5:4、8:1，以及冰晶子导致的平局；补位后形成连锁；补位填进 r* 正下方的洞；没有消除的列保持悬空；顶线消除救命；垃圾顶出。

## 4. 美术方向

### 4.1 风格关键词

现代极简、瑞士网格、大量留白。材质只有三种：**哑光雾蓝石板**（棋盘与背景）、**黑曜石**（黑子，深色玻璃质感，带锐利的高光和极淡的冷色环境反射）、**白瓷**（白子，温润的釉面，柔和的高光和蓝灰色阴影）。全作唯一的强调色是**冰川蓝光**，只用于影子、五连预告、消除光束、冰晶子和焦点 UI。没有木纹，没有暖色。

### 4.2 色板

| Token | 色值 | 用途 |
|---|---|---|
| `bg.deep` | `#161B21` | 页面最外层、桌面两侧的底色 |
| `bg.base` | `#212931` | 游戏区背景 |
| `bg.fog` | `#2E3843` | 背景雾气渐变的亮部 |
| `panel` | `rgba(54,66,79,0.72)` + 1px `rgba(255,255,255,0.06)` 描边 | HUD 面板（磨砂玻璃） |
| `slab.top` / `slab.bottom` | `#6F7E8D` / `#5D6B79` | 棋盘石板的竖向渐变 |
| `slab.line` | `#8F9DAB`（1px）+ 下方 1px `#505C68` | 刻线（亮线加暗线，做出雕刻感） |
| `slab.hoshi` | `#434F5B` | 星位 |
| `stone.black` | 本体 `#0C0E11`，中间调 `#1D2229`，高光 `#6B7682`，环境反射 `rgba(127,219,255,0.10)` | 黑曜石 |
| `stone.white` | 本体 `#F4F6F8`，阴影 `#C6CFD8`，边缘 `#A3AFBB`，釉面高光 `#FFFFFF` | 白瓷 |

| `text.1` / `text.2` / `text.3` | `#ECF1F5` / `#A2B0BD` / `#6E7C8A` | 主文字 / 次级文字 / 弱提示 |

对比度：黑子对石板 ≈ 4.6:1，白子对石板 ≈ 3.9:1（大面积圆形，可辨识度足够）；`text.1` 对 `bg.base` ≥ 12:1。

### 4.3 字体与排版

- 数字和英文：**Inter 300**，用于大号分数、Logo「FIVE DROP」，字距 −0.02em；**Inter 600**，用于全大写小标签（`NEXT` `HOLD` `LV`），11px，字距 +0.12em。
- 中文：系统黑体 500/600，正文 14px，提示 13px，最小 11px。
- 排版：严格的 8px 基线网格；左对齐的小标签加大号数字，形成瑞士海报式的层级；用细分隔线（1px `rgba(255,255,255,0.08)`）代替粗边框。

### 4.4 质感的程序化实现

- **石板**：在 256² 的离屏画布上叠两层值噪声（低频的云状明暗加高频颗粒，alpha 0.05），平铺使用，再叠一个从左上方来的柔光径向渐变。每条刻线是两条 1px 的线（亮线在上，暗线下移 1px）。棋盘四周有 10px 内阴影和 1px 高光倒角。
- **黑曜石子**：离屏预渲染。
  1. 底色：径向渐变，中心偏左上 `#2A3038` → 边缘 `#07080A`；
  2. 锐利的椭圆高光：左上 30°，`#FFFFFF` alpha 0.55，模糊 1px；
  3. 底边一道细弧形冷蓝反射 `accent` alpha 0.12；
  4. 投影：向右下偏移 2px，blur 4，`rgba(0,0,0,0.35)`。
- **白瓷子**：径向渐变 `#FFFFFF` → `#DDE3E9` → 边缘 `#AEB9C4`；宽而柔的高光（alpha 0.8，模糊 3px）；底部有 `#9FB3C6` 的淡蓝反光；投影与黑子相同。
- **冰晶子**：半透明 `rgba(127,219,255,0.55)` 的玻璃圆，内部 3 条细折射线，`lighter` 模式的高光，外圈 4px 光晕缓慢呼吸（周期 2.4s）。
- **影子（ghost）**：同色棋子的轮廓环（黑子用 `#0C0E11` alpha 0.45，白子用 `#F4F6F8` alpha 0.45），填充 `accent.dim`。这样一眼能看出是影子，又能看清落点的颜色。
- **背景**：`bg.base` 加上自顶向下的雾气渐变，四角暗角（alpha 0.35），12 颗失焦的黑白「漂浮棋子」（大小 20–90px，高斯模糊预渲染，透明度 0.06–0.12，以 6–14px/s 缓慢漂浮），再叠一层极淡的大尺度瑞士网格（间距 64px，alpha 0.025）。

### 5.3 层级与避让（防遮挡）

绘制顺序（下层在前）：背景 → 棋盘石板与刻线 → 底部垃圾光带 → 已落棋子 → 影子 → 预告光束 → 当前方块 → 碎片与粒子 → 冲击环与光束 → 跳字 → HUD → 提示卡片 / 引导手势 → 面板与遮罩 → 转场。

- **拖动不遮挡**：采用**相对拖动**，手指可以在棋盘任意位置甚至棋盘下方的空白区域滑动，方块按位移跟随，所以手指不必压在方块或影子上。
- **提示文字只在信息栏显示**（第 6.3 节的 y=60–124 区域）：连锁、多线、新机制提示都在那里轮流出现，**从不盖住棋盘**。同时最多一条：新提示把旧的挤出去（120ms），引导卡片的优先级最高。
- **跳字**：最多 3 个，彼此错开，自动避开当前方块所在的列区间（水平移到相邻空白处）。
- **预告徽标**放在影子右侧；右侧空间不够时放到左侧，始终位于棋盘内且不压住预告线上的子。

### 5.4 音频与音乐

- 总线：主音量 → 压缩器 → 输出。分为音效总线和音乐总线，各带开关（本地记忆）。共享一个混响（运行时生成 1.8s 的衰减噪声脉冲），用于钟声和琶音。
- **环境音乐**（程序化）：
  - E 小调（加 9 音）的柔和铺底：两个去谐三角波经过 900Hz 低通，每 8 秒换一个和弦（i–VI–III–VII 循环）；
  - 上层偶尔出现稀疏的 FM 「电子钢琴」音符，从五声音阶中随机选取，平均每 2.5 秒一颗；
  - 节奏层只有极轻的「滴答」，从 L7 开始出现；BPM 从 72 开始，每级 +3，上限 108；
  - 危险态时铺底换成低频脉冲加心跳。
- WebAudio 在第一次用户手势（pointerdown / keydown）时 `resume()`；页面切到后台时整体淡出并 `suspend()`。
- 振动：Android 上锁定时 `navigator.vibrate(8)`，五连时 20ms，多线 / 连锁时 `[20,40,30]`。设置里可以关闭，iOS 上静默跳过。

## 6. 界面与流程

### 6.1 屏幕适配与坐标系

- 设计帧是 **390×844**（逻辑像素）。真实视口中，帧宽 = `min(视口宽, 视口高 × 390/844, 520)`；高度方向多出的空间，分给信息栏下方和底部操作栏上方作为留白，各占一半。
- 安全区：用 `env(safe-area-inset-*)` 读到的值加在帧的上下内边距里。
- 格子尺寸 `cell = floor(min((帧宽 − 48)/9, 可用棋盘高/15))`，标准帧下为 38。
- canvas 尺寸 = CSS 尺寸 × min(devicePixelRatio, 2)；resize 时用 120ms 防抖重建离屏缓存。
- CSS：`touch-action:none; user-select:none; -webkit-touch-callout:none; overscroll-behavior:none;` 禁止页面滚动和缩放；viewport 加 `maximum-scale=1, user-scalable=no`；拦截 `contextmenu`、`gesturestart`、双击缩放。

### 6.2 标题页

- 布局见第 4.5 节画面 1。「开始」按钮（220×56，中心 (195, 600)）在首帧就可以点；字体加载最多等 300ms，超时先用系统字体绘制，加载完再重绘。

### 6.4 操作

**触屏（主方案）**：手势识别作用于手势区；底部按钮另外处理，并且按钮区和手势区不重叠。

| 手势 | 判定 | 效果 |
|---|---|---|
| 拖动（水平） | 位移超过 10px 后锁定轴向：|dx| ≥ |dy| 时为水平。之后只响应水平 | **相对平移**：目标列 = 起始列 + round(dx / (cell × 灵敏度))，灵敏度默认 0.9，设置里有 0.75 / 0.9 / 1.1 三档。方块逐列移动到目标列，遇墙或遇子就停 |
| 拖动（向下，慢） | 锁定为竖直轴，dy > 0 | 软降：每 cell × 0.8 的位移下移 1 行 |
| 甩动向下 | 竖直轴；松手前 80ms 内 vy ≥ 1.1 px/ms，且总 dy ≥ 56px | **硬降**（同时受第 3.4 节的硬降防误触约束） |
| 甩动向上 | 竖直轴；vy ≤ −1.1 px/ms，且 dy ≤ −56px | 暂存 |
| 轻点 | 总位移 < 10px，时长 < 250ms | 顺时针旋转 |
| 双指轻点 | 两个指针 250ms 内都按下又抬起，且都没移动 | 翻色（底部有按钮，这只是熟练玩家的捷径） |

**误触防护**
- 水平轴一旦锁定，同一手势中不会再触发硬降或暂存；竖直轴的手势不会平移。
- 硬降在新方块出现后 150ms 内无效；在旧方块存活时就已经按下的指针，对新方块无效。
- 底部按钮在 pointerdown 时触发（响应快），按住不会连发；硬降按钮在新方块出现后 150ms 内无效。
- 系统手势区（屏幕底部 20px）不放可交互元素。

**落点影子**：始终显示（设置里可关），带颜色，见第 4.4 节。

**五连预告**：每次方块的位置、朝向或颜色变化时（结果按状态缓存），在影子位置模拟一次锁定和第一轮 `findLines`：
- 将要形成的线画成冰蓝光束（已有棋子的部分加淡蓝外圈，影子的部分加亮）；
- 影子旁显示徽标：「五连」「双线」「6 连」；如果完整模拟结算后还会继续连锁，徽标追加「+连锁」；
- 如果会造成满行，该行显示一道淡水平光带，将退场的多数色子标为半透明。

计算代价：每次变化做一次网格拷贝（153 格）和完整结算模拟，耗时远小于 0.1ms。

### 6.5 首局引导（目标 ≤ 30 秒）

规则：引导期间重力关闭（方块悬停，不会自己落下）；每一步使用固定盘面和固定方块；右上角始终有「跳过」按钮（44×44）。一步完成后，冰蓝色勾号闪一下，0.6 秒后进入下一步。如果某一步失败（方块锁定后没有形成五连），盘面重置，再提示一次，并放慢手势动画。

### 6.7 结算

见第 4.5 节画面 6。

## 8. 性能预算与策略

- 每帧绘制：背景（缓存贴图 1 次 drawImage）+ 石板（缓存 1 次）+ 棋子 ≤ 153 次 drawImage（精灵）+ 特效。目标是中端手机上每帧 < 6ms。
- 对象池：碎片 320、粒子 400、冲击环 12、光束 12、跳字 8、残影 24。满了就复用最旧的，不新建对象。
- 主循环：`requestAnimationFrame`，dt 上限 50ms；逻辑用固定步长 1/120s 加累积器；补间用实际 dt。
- 预告与结算模拟按状态 key 缓存，只在输入变化时重算。
- 精灵在 resize 或 dpr 变化时重建；漂浮棋子的模糊在生成时预渲染，运行时不使用 `filter`。
- 磨砂遮罩：暂停时把当前帧缩小到 1/8 再放大绘制，近似模糊，只生成一次。

### 10.2 风险与对策

| 风险 | 对策 |
|---|---|
| **最大风险：消除效率与堆叠速度失衡**。只靠五连太难（死子堆积），满行太强又会让颜色失去意义 | ①规则上用「多数色退场」让满行只能部分减压（第 3.6 节）；②`fullRow.mode` 三种模式、三格块比例、颜色权重、冰晶子概率全部可调；③用模拟器加「色盲 / 形盲」两个对照机器人**量化**证明形状和颜色都重要，而不是只凭手感 |
| 竖屏触控不精准（拖过头、误硬降） | 相对拖动加轴锁定；甩动同时要求速度和距离；出块保护期；底部按钮作为完整的备选方案；灵敏度三档；实现阶段用 Playwright 脚本反复测拖动 1–8 列的准确率 |
| 新手看不出斜线 | 引导第 3 步专门教斜线；五连预告光束对斜线同样生效；新手机器人模拟「50% 看不见斜线」作为下限检验 |
| 中期无压力 / 某一级突然成墙 | 压力源分阶段叠加（第 3.9 节），垃圾行间隔平滑递减；模拟器检查每级死亡分布 |
| 连锁动画太长，打断节奏 | 每轮结算动画 ≤ 520ms；连锁 ≥ 3 后每轮压缩 15%；结算期间等级计时照走，但不出块 |

### 10.3 自动模拟器（`npm run sim`）

**命令**：`npm run sim -- --persona serious --games 200 --seed 1 --fullRow majority`；不带参数时依次跑四种人格加三种满行模式，输出表格。

**机器人**：对当前方块（以及暂存交换后的方块）× 是否翻色 × 4 个朝向 × 所有可达列，枚举硬降落点；用 `resolveAll` 完整结算后打分：

```
eval = w_clear·移除子数 + w_score·得分/100 − w_h·总高度 − w_hole·洞数 − w_bump·相邻列高差和
       − w_top·max(0, 最高列 − 10)² + w_pot·五子窗口潜力 − w_dead·死子数
五子窗口潜力：在 4 个方向上遍历所有长度为 5 的窗口；若窗口内只有一种颜色加空格/冰晶子，
            且有 k 颗该色子，则累加 {2:1, 3:4, 4:12}[k]
死子：不属于任何「可行窗口」的棋子
```

| 人格 | 设定 |
|---|---|
| 认真 serious | 全部权重；使用暂存；思考时间 0.9s/块 |
| 新手 novice | 在前 6 名候选中按 softmax（温度 0.6）抽选；50% 的局「看不见斜线」（潜力只算横竖）；有益的翻色只有 60% 概率被考虑；不用暂存；6% 概率落到相邻列（失误）；思考时间 1.8s/块 |
| 色盲 colorblind（对照组） | w_pot = w_dead = 0，评估时不知道颜色；只看堆叠和满行（五连只会碰巧形成） |
| 形盲 shapeblind（对照组） | w_hole = w_bump = 0，只看颜色潜力和清除量 |

**时间模型**：每块方块消耗的游戏时间 = 思考时间（受可用下落时间限制）+ 结算动画时间（每轮 0.45s）+ ARE。如果 `下落到影子所需时间 + 锁定延迟 < 思考时间`，候选范围按比例扩大并加噪声（模拟手忙脚乱）。等级随游戏时间推进，与实际游戏一致。

**验收指标**（各 200 局的中位数）

| 指标 | 目标 |
|---|---|
| 新手存活时长 | 3–5 分钟 |
| 认真存活时长 | 9–14 分钟（到达 L12 以上） |
| 新手在第一分钟内至少打出 1 次五连 | ≥ 90% 的局 |
| 色盲存活 / 认真存活 | ≤ 0.55；色盲得分 ≤ 认真的 25% |
| 形盲存活 / 认真存活 | ≤ 0.70 |
| 认真的移除子数构成 | 五连占 55–80%，满行占 20–45%（两种减压都在起作用） |
| 死亡集中度 | 认真组没有任何单一等级占死亡数的 35% 以上（没有「墙」） |
| 中期压力 | 认真组在 L5 时最高列中位数 ≥ 5 行；在 L9 时 ≥ 8 行（压力确实在上升） |
| 一招鲜检查 | 把认真机器人改成「只用硬降 + 不翻色」时，存活降至 ≤ 0.6（说明翻色有价值）；关闭冰晶子时存活下降 5–20%（说明有作用但不是必需） |
| `fullRow.mode` 对比 | `all` 模式下色盲与认真的差距应明显缩小（证明默认规则的价值），`none` 模式下新手存活 < 2 分钟（证明需要减压阀） |

不达标时的调参顺序：等级时长 → 重力曲线 → 颜色权重 → 三格块比例 → 垃圾行间隔 → 冰晶子概率。每次调整都记录到第 11 节。
