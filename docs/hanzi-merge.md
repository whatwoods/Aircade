## 1. 一句话卖点与体验目标

**一句话卖点**：在一张铺着米字格的宣纸上，把「木」拖到「木」上，墨迹一晕，就成了「林」；再添一木，成「森」。每一次合成都按真实的造字法（会意、形声、指事）拼出一个汉字：部件飞入、墨迹晕开、朱砂印落下。墨有限，要在墨用完前写完卷轴上的目标字。

### 1.1 体验目标

| 项 | 目标 |
|---|---|
| 单帖（关）时长 | 第一卷 30–60 秒；第三卷起 1.5–3 分钟；终章「长卷」约 3 分钟 |
| 整个闯关 | 30 帖，认真玩家约 60–75 分钟（含读新字卡） |
| 无尽「书斋」 | 中位数约 8 分钟一局，熟练玩家 12–15 分钟 |
| 首屏 | ≤ 1 秒出现标题和可点的「开始」；≤ 3 秒进入可操作状态（字体异步，先用系统楷体兜底） |
| 理解规则 | 首局引导约 25 秒，全部在操作中完成（§8.3） |
| 核心爽点（按优先级） | ① 合成瞬间：部件飞入拼合、墨迹晕开、落印 ② 「原来这个字是这么来的」：新字卡上的造字法与《说文》 ③ 一笔完成目标，卷轴上的描红字被墨填满 ④ 图鉴一格一格收满 |

### 1.2 玩家必须懂的那一条规则

> **把一个部件拖到另一个部件上，如果它们能按真实的造字方式组成一个字，就会合成这个字。每落一笔耗一墨；墨用完前，写完卷轴上的所有目标字。**

引导第 1–3 步（§8.3）用实际操作把这条规则的三部分（拖上去合成、只有真字才能合成、落笔耗墨）都演示一遍，并在第 2 步结束时用一句话说出来。

### 1.3 情绪曲线（单帖）

```
紧张度
 高 │                                  ╭─╮最后一墨写成 → 落大印
    │                    ╭╮墨见底     ╱  ╰╮
 中 │        ╭─╮新字卡  ╱  ╰─╮ ╭─╮  ╱     ╰── 帖成（朱印三枚依次盖下）
    │   ╭───╯  ╰──╮ ╭─╯      ╰─╯  ╰─╯
 低 │──╯           ╰╯
    └─开帖(看目标)─┬─布局(备部件)─┬─收官(凑最后几个字)─→
```

- **压力**来自三处：墨量（每取一个部件耗 1 墨）、纸面（4×4 = 16 格：备料和留作发现的干扰要占位置，第四卷起认真机器人峰值占用 31–50%、新手 31–69%，满了只能洗笔或先合成）、诱惑（笔架里会出现「能合成别的字、但会吃掉你需要的部件」的干扰部件）。
- **释放**来自合成高潮和新字卡（游戏暂停、可以慢慢读）。一帖的后半段墨见底时最紧张，最后一个目标字写成时是全帖高潮。
- 闯关**没有计时**。这是一款认字游戏，读新字卡和思考拆法需要时间；压力只来自资源，而不是手速。

## 2. 技术选型

### 2.1 总览

| 层 | 选择 | 理由 |
|---|---|---|
| 渲染 | **Canvas 2D**：一张舞台画布（棋盘、牌、特效、HUD）+ 一张背景画布（宣纸、山水、两侧装饰，只在 resize 时重绘） | 内容是字形、纸纹和墨迹精灵，同屏对象 < 120 个。字形先渲染到离屏画布缓存，每帧只 `drawImage`。WebGL 带来的好处（墨迹着色器）用预渲染精灵 + 合成模式也能做到，不值得增加 Pixi 等 300 KB+ 依赖 |
| 核心逻辑 | 纯 TypeScript，无 DOM 依赖（`src/core/`） | 同一份规则代码同时跑在浏览器和 Node 模拟器里（`npm run sim`），保证模拟结果就是实际规则 |
| 动画/缓动 | 自研 `tween` + `spring`（约 2 KB），对象池 | 只需要缓动函数、补间池和弹簧 |
| UI | 原生 DOM + CSS 覆盖层（标题、选帖、暂停、结算、新字卡、图鉴、设置）；游戏内 HUD（卷轴、墨锭、笔架）画在画布上 | 菜单和长文本用 DOM：文字清晰、易排版、Playwright 可用 `getByRole` 定位。HUD 和棋盘一起缩放、一起受特效影响 |
| 音频 | WebAudio 实时合成：Karplus-Strong 拨弦（古琴感）、非谐泛音钟磬、滤波噪声（纸、墨、风） | 素材约定要求程序化；拨弦音高可以随合成深度在五声音阶上升 |
| 汉字字体 | **霞鹜文楷 LXGW WenKai v1.250**（OFL-1.1），构建期按字库子集化后合并为**单个 woff2** | 覆盖全部偏旁变体（实测，§2.3）；楷体易读、有书卷气；子集后约 90 KB |
| Logo 字体 | **马善政 Ma Shan Zheng**（OFL-1.1），只取 Logo 和少量大字（约 12 字） | 毛笔行楷，做标题和「帖成」大字；子集约 9 KB。它缺 罒 爫 覀 等部首，不能做牌面字体 |
| 正文字体 | 系统楷体栈 → 系统黑体栈（0 字节） | 新字卡里的《说文》引文、释义用 `"Kaiti SC","STKaiti","KaiTi","BiauKai",…,"PingFang SC","Microsoft YaHei","Noto Sans CJK SC",sans-serif`。引文字数多，打包进字体会让子集膨胀到 500 KB 以上 |
| 构建 | Vite 8 + TypeScript 6（strict），只用 npm | 与第一批四款一致（`typescript ~6.0.3`、`vite ^8.3.5`） |

### 2.3 字体技术验证（已完成）

**问题**：npm 上的 LXGW 和马善政都只有按 unicode-range 切开的分片 woff2（fontsource 和 lxgw-wenkai-webfont 都是这样），没有完整 TTF；直接引用分片会让浏览器下载 40 多个文件。

**方案**（原型脚本已跑通，实现阶段整理为 `tools/build-font.ts`，在 `predev` / `prebuild` 中运行）：
1. 从 `src/data/hanzi.ts` 收集字符集：82 个部件 + 200 个字 + 偏旁变体字形（氵亻忄扌钅王讠饣纟礻衤刂犭阝月爫牜灬）+ 拼音字母（含声调）+ `src/data/uiText.ts` 的动态界面字（卷名、数字等）+ **`tools/glyph-scan.ts` 从源码扫描出的全部「用打包字体显示」的字面量**（画布 `glyphs.label/draw/get/drawFit`、`seal()`；DOM 里类名命中 `styles.css` 中 `var(--kai)` / `var(--logo)` 选择器的 `h()` / `btn()` 文本；`index.html` 中对应元素的文本）。实现后共 462 + 13 个码位。
2. 解析分片 CSS 的 `unicode-range`，找出每个码位所在的分片（当前 41 个分片）。
3. 每个分片用 `subset-font` 只保留需要的码位（sfnt 输出）→ 用 `fontkit` 读取每个字形的轮廓 → 用 `opentype.js` 写进一个新字体（保留原 unitsPerEm、ascender、descender、advanceWidth）。
4. 再过一遍 `subset-font` 输出 woff2，写到 `src/assets/fonts/hanzi-kai.woff2`。Logo 字体同样处理。
5. 字符集取哈希写进 `src/assets/fonts/charset.json`；字符集没变就跳过（构建 < 0.1 s）。生成的 woff2 同时提交进仓库，这样即使 dev 环境的 30 MB 源包没装好，也能直接开发。
6. **构建断言**：字库里任何一个字在源字体里缺字形，构建直接失败并列出缺字。`prebuild`（`build-font.ts --check`）核对生成的 woff2 覆盖完整字符集；`npm run build` 最后一步 `tools/check-dist.ts` 再用 dist 里带哈希的 woff2 核对一遍（字符集 ∪ `dist/index.html` 中以打包字体显示的文字），并检查体积预算，任一缺字或超预算即构建失败。
7. **运行时兜底审计**：`?debug=1` 下打开字形检查（画布上用打包字体绘制了子集外的字会 `console.error`），`__game.fontAudit()` 返回 DOM 中所有 `.kai/.logo` 元素里不在子集的字；Playwright 全流程断言其为空。

**实测结果**：

| 项 | 结果 |
|---|---|
| 部首变体覆盖（文楷） | 氵扌亻忄灬冖宀艹讠钅饣纟礻衤阝刂犭辶廴彳疒罒冫勹匚囗丬攵夂廾卄爫丷亠厶彡冂凵卩巾幺广弋彐覀 **全部有字形** |
| 文楷缺字 | `⺮`（竹字头，U+2EAE）、`⺶`（羊字头）、`⻊` 等康熙部首补充区字符、`耂`、`肰`。处理：竹字头和羊字头在合成动画里用「压扁的本字」代替（数据里 `v: { t: '' }`）；需要「肰」的「然」改用「召→昭→照」链来演示「灬」 |
| 马善政缺字 | 罒 爫 覀（所以不能做牌面字体） |
| 合并后体积 | 文楷 Regular **89.0 KB / 316 字（平均 288 B/字）**；Bold 86.7 KB（不用）；马善政 8.8 KB / 12 字 |
| 渲染验证 | 用 Playwright（Chromium）加载合并后的 woff2 渲染全部 316 字，截图人工检查：字形、基线、字宽正确，无方框 |
| 对比方案 A：41 个分片各自子集、用 unicode-range 声明 | 合计 93.4 KB，但 41 个请求；放弃 |

**预算**：汉字字体 ≤ **140 KB**（当前 132.5 KB / 486 码位；第三阶段加入变体字形与繁体字头后从 120 KB 上调，同时去掉了整段拉丁字母），Logo 字体 ≤ 15 KB，合计 ≤ 155 KB。界面字由 `tools/glyph-scan.ts` 扫描源码收集（含表达式里的字面量）；`check-dist` 还核对「界面上出现的每个字都在子集里」，不在子集的字（如说文古文 㐺、𦬆）构建报错。字库每加 1 个字约 +0.3 KB。`npm run build` 结束时打印字体体积，超预算报错。

**首屏策略**：
- 标题页的 Logo 先用 CSS 画的朱印 + 系统楷体渲染，不等字体。
- `<link rel="preload" as="font" crossorigin>` 预加载两份 woff2，`main.ts` 用 `document.fonts.load()` 等待（最多 2.5 s），就绪后重建字形缓存；超时则继续用系统楷体，字体迟到时（`loadingdone`）再重建。
- 字体就绪前，牌面用系统楷体栈 `"Kaiti SC","STKaiti","KaiTi",serif` 绘制；就绪后清空字形缓存，下一帧按需重绘（**偏差**：未做 300 ms 交叉淡入与「每帧 40 字」分帧重建——缓存是懒生成的，切换时同屏不足 60 个字形，实测无卡顿）。实测：字体请求人为延迟 6 s 时，0.44 s 可点「开始」、0.76 s 进入可操作的棋盘。
- 「开始」按钮从第一帧起就可点，不依赖字体。

### 2.4 渲染方案细节

- **字形缓存**：每个「字 × 字号 × 墨色档」渲染一次到离屏画布（按 DPR 放大，上限 2），之后只 drawImage。缓存在字体就绪、DPR 变化时重建。约 300 字 × 3 档 × 66 px，显存 < 8 MB。
- **墨色**：同一字形缓存三档——浓墨（字牌）、淡墨（部件牌）、描红（卷轴目标，朱色细描边 + 空心）。描红用 `strokeText` 加低透明度 `fillText`。
- **墨迹晕开**：预生成 6 张 256×256 的晕染精灵（径向渐变 + 分形噪声边缘 + 少量「飞白」缺口），运行时缩放、旋转、调透明度叠加，合成模式 `multiply`。不用实时着色器。
- **字形「墨显」遮罩**：合成时最终字形从中心向外显现：先画晕染精灵当遮罩（`destination-in`），遮罩半径按缓动扩大，边缘带噪声，看起来像墨在纸上洇开。另一种「笔扫」遮罩：一条带毛边的宽笔触从左上扫到右下，用于卷轴描红被填满。
- **宣纸**：启动时生成一张 512×512 可平铺纹理（值噪声 + 400 根随机短纤维 + 稀疏的草屑斑点），约 25 ms。
- **分层**：背景画布（纸 + 远山）→ 舞台画布（米字格 → 牌 → 特效 → HUD → 拖拽物 → 预览气泡）→ DOM 覆盖层（新字卡、菜单）。

### 2.5 备选方案对比

| 方案 | 结论 |
|---|---|
| DOM 牌面（每张牌一个 div + CSS 动画） | 文字最清晰，但墨迹晕开、遮罩显字、粒子都很难做；30 张牌同时做 transform 动画在低端机掉帧。放弃 |
| PixiJS / WebGL | 可以写真正的墨水扩散着色器，但运行时 400 KB+，首包翻倍；预渲染精灵已经足够好看。放弃 |
| 运行时加载完整字体或系统字体渲染牌面 | 系统楷体在 Android 上普遍缺失，牌面风格不可控。放弃 |
| 笔顺动画（Make Me a Hanzi 笔画数据） | 数据许可证为 Arphic Public License，且 200 字的笔画数据约 400 KB。放弃，改用「墨显遮罩 + 笔扫遮罩」表现书写感（§6.6） |

## 3. 核心玩法与规则

### 3.1 框架选择：四种方案比较

| 维度 | A. 棋盘拖动合成（合成类） | B. 2048 式滑动 | C. 配方工坊（自由组合，类似 Little Alchemy） | D. 消除式（三消里凑字） |
|---|---|---|---|---|
| 和「部件→字」的契合 | **高**：任意两张牌拖到一起，正好是「A+B→C」 | 低：滑动只能合并相邻、通常是相同的牌。只适合叠字（林、森），会意/形声几乎无法表达 | 高：随便组合，探索感强 | 中：相邻三连不对应构形 |
| 压力来源 | 墨（取牌消耗）+ 纸面空间 + 干扰部件 + 目标字 | 空间 + 随机生成 | **几乎没有**：没有失败，只有发现 | 步数 |
| 知识感 | 每次合成都能展示构形；目标字逼玩家思考「这个字怎么拆」 | 弱 | 强，但缺少目标，容易乱试 | 弱 |
| 触屏操作 | 拖放，直观 | 滑动，直观 | 拖放 | 交换 |
| 三部件字（品、森） | 支持「未成字」中间态 | 不支持 | 支持 | 不支持 |
| 失败与重玩 | 有 | 有 | 无 | 有 |

**选择 A：米字格棋盘上的拖动合成 + 卷轴目标字 + 墨量限制。** 同时借用 C 的「发现」乐趣：任何合成出来的真字都会收进图鉴，哪怕不是目标字；借用合成类游戏的「生成器」：部件从笔架里一个一个取，每取一个耗 1 墨。

理由：
1. 「把木拖到木上」这个动作本身就是用户描述的玩法（木+木→林，林+木→森），零学习成本。
2. 目标字 + 墨量让每一次取牌、每一次合成都是决策：这个「木」是留着做「森」，还是现在和「目」合成「相」？
3. 拼字的乐趣在于「想出拆法」。目标字始终以描红形式显示，玩家要自己想出它由哪些部件组成，提示可以逐级打开。

### 3.2 核心循环

```
看卷轴上的目标字（描红）→ 想拆法
   ↓
从笔架取部件（耗 1 墨）→ 拖到空格放下 / 直接拖到别的牌上合成
   ↓
棋盘上的牌互相拖拽合成（免费）→ 合成真字：墨迹晕开、新字卡（首次）
   ↓
合成出的字正好是卷轴目标 → 自动飞入卷轴，描红被墨填满，盖印
   ↓
全部目标完成 → 帖成：剩余墨量换分和星级 → 下一帖
（墨用完且棋盘上再也合成不出东西 → 墨尽，本帖失败，一键重写）
```

### 3.3 牌的种类

| 种类 | 外观 | 说明 |
|---|---|---|
| 部件牌 | 淡墨字；左上角朱色小字标出偏旁变体（如「氵」） | 来自 `BASES`，不能再拆 |
| 字牌 | 浓墨字，底部 11 px 拼音（设置可关） | 合成结果；可以继续作为部件（林→森） |
| 未成牌 | 两个部件以最终位置、70% 大小淡墨显示；虚线朱框；右下角小印「未成」 | 三部件字的中间态（口+口），只接受能补成三部件字的第三个部件 |

棋盘 4 列 × 4 行 = 16 格（第三阶段由 5×6 缩小：30 格时认真机器人到 L28 也只用到 10 格，「纸面压力」名存实亡；缩小后格子 82 px，牌面更大）。牌占一格；一格最多一张牌。

### 3.4 操作

所有操作都是**按住拖动、松手生效**（Pointer Events，鼠标和触摸一致）。点击只用于打开信息。

| 操作 | 拖动对象 → 落点 | 结果 | 耗墨 |
|---|---|---|---|
| 落笔 | 笔架当前部件 → 空格 | 部件放到该格 | 1 |
| 落笔即合 | 笔架当前部件 → 某张牌 | 能合成：直接合成；不能合成：弹回笔架，不耗墨 | 能合成时 1 |
| 合成 | 棋盘牌 A → 牌 B | 能合成：A 消失，B 变为结果（B 所在格）；不能合成：A、B 交换位置 | 0 |
| 移动 | 棋盘牌 → 空格 | 移动 | 0 |
| 洗笔（丢弃） | 棋盘牌或笔架部件 → 右下角洗笔池 | 牌被洗掉（墨在水里化开的动画） | 1 |
| 悔笔 | 点「悔笔」 | 撤销上一步（含耗墨），每帖 1 次 | 0 |
| 提示 | 点卷轴 | 下一级提示（§3.8），每级提示耗 1 墨；已解锁的提示不再耗墨 | 1 |
| 查看 | 点棋盘上的字牌 / 卷轴 / 笔架部件 | 小气泡显示拼音、释义（1.6 s 后自动消失，不暂停） | 0 |

- 笔架部件**点一下不会自动落子**，避免误触耗墨。
- 拖动开始的判定：按下后移动 ≥ 6 px，或按住 ≥ 180 ms。
- 墨为 0 时笔架变灰，只能在棋盘上合成、移动；洗笔不可用（提示「墨尽，不能洗笔」）。

### 3.5 合成判定（实现依据）

输入：被拖的牌 A、落点牌 B、落点方位 `zone ∈ {left, right, top, bottom, center}`。方位由拖拽物中心相对 B 格中心的位置决定：距中心 < 格宽 × 0.18 为 `center`；否则比较 |dx| 与 |dy|，取主方向。

判定顺序：
1. **B 是未成牌**（含部件 {X, Y}）：在三部件配方里找 {X, Y, A}。找到 → 合成该字；找不到 → 不合成。
2. **A 是未成牌**：同理，以 B 为第三部件。
3. 在二元配方表里找部件多重集合 {A, B} 的所有候选：
   - **0 个**：再看三部件配方里有没有包含 {A, B} 的。有 → 生成未成牌 {A, B}（放在 B 格）；没有 → 不合成。
   - **1 个**：合成它，**不管落点方位**。
   - **≥ 2 个**（同部件、不同位置，如 一+木 → 本/末，亡+心 → 忘/忙）：按方位选 A 在结果中的位置。A 落在 B 的上方 → 选 A 在上的那个（一在上 = 末）；下方 → A 在下（一在下 = 本）；左/右同理；`center` 或没有匹配 → 选数据里排在前面的「默认」候选。悬停时预览气泡会随手指方位实时切换，所以玩家能看到「放上面是末、放下面是本」。
4. 二元配方优先于未成牌：如果 {A, B} 本身能合成二元字，就合成二元字。校对脚本保证每个三部件字至少有一种起手对不和二元配方冲突（当前 8 个三部件字都满足，见 §4.4）。

结果牌放在 **B 的格子**里。A 来自棋盘则空出 A 的格子。

**偏旁变体**：部件牌上写本字（水、手、人、心……），合成时变为该字里的实际写法（休：人 → 亻）。**写法逐条写在配方的 `vv` 字段里，不按位置推断**——同样在下方，照的火写作灬，炎、灭、灾、焚的火仍写作火；从的左「人」不作亻；初的刀在右也不作刂。这既避免了「水」和「氵」是两张牌带来的混乱，又在合成动画里把变形过程演出来：飞入途中「水」交叉淡变为「氵」，并在新字卡上写明「水在左边写作氵（三点水）」。少数字形在字体里没有独立码位（竹字头、羊字头），动画里用按比例压扁的本字代替；看、告的上部同样画作压扁的本字（手、牛），卡片文字说明是变形。

### 3.6 目标字（卷轴订单）

- 每帖有一个目标字列表（§5.2），按顺序最多 **3 个同时展开**（第一卷第 1 帖 1 个、第 2–5 帖 2 个）。完成一个，下一个展开。
- **自动交付**：棋盘上出现一个与已展开目标相同的字（合成得到的），立即飞入对应卷轴（多个相同目标时填最早的）。新目标展开时，如果棋盘上已经有这个字，也立即交付。
- 交付后该牌离开棋盘，空出格子。
- 非目标字留在棋盘上，可以继续当部件用，也可以洗掉（耗 1 墨）。第一次合成出的任何真字都会进入图鉴。

### 3.7 墨与结束条件

- 每帖开始给定墨量 `ink`（§5.2 表格，由模拟器校准）。
- 每次从笔架取部件（落笔、落笔即合、从笔架直接洗笔）耗 1 墨；洗掉棋盘上的牌耗 1 墨；提示每级耗 1 墨。
- **胜利**：所有目标交付。立即进入帖成（剩余合成动画播完后）。
- **失败（墨尽）**：墨 = 0，且棋盘上不存在任何能合成的牌对（含未成牌补全）。每次操作后检查。墨为 0 但还能合成时游戏继续，HUD 上墨锭闪烁「墨已尽，看看还能拼出什么」。
- 棋盘满（16 格）且笔架部件无处可落：玩家仍可合成、洗笔，不会死锁（洗笔需要墨；墨为 0 时按上一条判定失败）。

**判定顺序**（每次松手）：①执行操作 → ②扣墨 → ③合成/未成牌生成 → ④检查交付（可能连续交付多个）→ ⑤展开新目标并检查已有字的交付 → ⑥检查胜利 → ⑦笔架补位 → ⑧检查失败。

### 3.8 提示分级

每个卷轴的提示有三级，帖子设定起始级别（`hintStart`）：

| 级 | 卷轴显示 | 例：清 |
|---|---|---|
| 0 只看字 | 描红字 + 结构图标（⿰⿱⿴ 等） | 清 ⿰ |
| 1 半示 | 加上一个部件（形声字给形旁） | 清：水 + ？ |
| 2 全示 | 全部部件 | 清：水 + 青 |

点卷轴升一级，耗 1 墨（第一卷免费）。部件本身也是合成字时（想 = 相 + 心），全示只显示第一层；再点一次（第 3 级，仍耗 1 墨）展开到底层（相 = 木 + 目）。

### 3.9 计分与星级

| 事件 | 分数 | 字段 |
|---|---|---|
| 交付目标字 | `100 × 叶子部件数`（林 200、森 300、想 300、品 300） | `score.orderPerLeaf` |
| 合成非目标真字 | `10 × 叶子部件数` | `score.extraPerLeaf` |
| 首次发现（图鉴新字） | +50 | `score.discovery` |
| 一次操作交付 ≥ 2 个目标（连成） | 额外 +100 × (n−1) | `score.multiOrder` |
| 帖成时每剩 1 墨 | +40 | `score.inkLeft` |

**星级**（三枚朱印）：一星 = 帖成；二星 = 剩墨 ≥ `star2`；三星 = 剩墨 ≥ `star3`。每帖的 `star2/star3` 由模拟器校准（§5.4）：「认真」机器人约 50% 拿到二星、约 20% 拿到三星（第三阶段由 P20/P65 收紧为 P50/P80）。

最高分：每帖记录最高分和最高星；闯关总星数显示在选帖页。无尽模式记录最高分和最远「章」。

### 3.10 笔架与出牌导演（director）

笔架显示**当前部件 + 后两个预告**。出牌序列由「导演」按种子确定性生成（`?seed=` 可复现），规则：

1. **需求表**：对每个已展开、未完成的目标，展开到叶子部件（想 → 木、目、心），减去棋盘上已有的、可用于该目标的牌（已有「相」就抵掉 木、目）。得到当前缺口多重集合。
2. 每次补位时：以概率 `decoyRate` 出一个干扰部件（来自本帖 `decoys` 列表），否则从缺口里按权重抽（缺得多的权重大，属于最早展开目标的 ×1.5）。缺口为空时（玩家已备齐）从「后续目标」的叶子里抽。
3. **保底**：某个缺口部件连续 `guaranteeWindow`（=5）次没出，下一次强制出它。
4. **防连发**：同一干扰部件不连续出现 2 次；干扰部件连续最多 2 个。
5. 预告的两个部件一旦显示就固定，不再随棋盘变化而改（玩家可以据此规划）。

干扰部件的设计原则：**它们能和本帖常见部件组成别的真字**（例如做「休」的帖子里出「目」：木+目→相，吃掉一个「木」）。这样干扰不只是占格子，还形成诱惑，同时让玩家顺手发现新字。

### 3.11 无尽模式「书斋」

- 闯关通过第二卷后解锁。棋盘、规则与闯关相同，**没有固定目标表**：3 个卷轴持续刷新。
- 起始墨 `endless.startInk = 30`；每交付一个目标，返还 `叶子数 + 奖励` 墨。奖励从 `endless.refundBonus = 1` 起，每 `refundDecayStages = 2` 章减 1，最低 `refundMin = -1`（**实现时新增**：不衰减时认真机器人能无限玩下去，见 §5.4 结果）。
- 目标从字库里按「章」抽取：第 1 章只出第一、二卷的字；每交付 `endless.ordersPerStage = 5` 个目标进入下一章，可抽的字库扩大一卷，干扰率 +0.04（起始 0.12，上限 0.40），提示起始级别逐步从 1 降到 0。
- 优先抽图鉴里**未收集**的字（权重 ×2），让无尽模式成为收满图鉴的主要途径。
- 结束：墨尽规则同闯关。结算显示分数、到达的章、本局新收的字。
- 压力上升：深层字（三层、三部件）需要更多部件、更多中间步骤，干扰更多 → 浪费增加 → 返还跟不上消耗。模拟器校准使「认真」机器人中位数约 7 分钟结束（4×4 棋盘下实测 P50 6.2 分、到第 10 章；新手 P50 8.0 分、到第 7 章）。

## 4. 字库与配方：正确性是第一风险

### 4.1 原则

1. **只收真实构形**。每条配方都是该字公认的构形拆分：会意（从 A 从 B）、形声（从 A，B 声）、指事（本、末）。不收民间拆字游戏式的拆法（如「朋 = 月 + 月」：朋本是串贝的象形；「吕 = 口 + 口」：吕是脊骨象形；「昌 = 日 + 日」：《说文》是从日从曰）。
2. **每条注明依据**：
   - `src = 说文`（156 条）：依据《说文解字》（大徐本），数据里存了说文原文片段 `check`，校对脚本逐条到说文数据里核对；卡片上的引文逐句比对，非原文的解说句由人工复核（§4.3）。
   - `src = 今`（44 条）：简化字（灭、尘、宝、国、泪、笔、阳、阴……）、后起字（尖、歪、她、妈、吗……）或说文未收的字。依据写明「简化字（繁体某）……」或「后起形声字：某表义，某表音」。
3. **楷书形体与古文字形不一致时，说实话**。例如「思」上部本是「囟」、「早」下部本是「甲」、「肥」右边本是「卪」、「雷」下部由「畾」简省、「时」的「寸」由「寺」简省、「鲜」在说文里是形声（羴省声）而非「鱼羊」会意——这些都照实写在卡片上。玩家在游戏里用的是楷书部件（田、十、巴），但卡片告诉他真相，这本身就是知识点。
4. **同一组部件只对应一个结果，除非能靠位置区分**。例如 本/末（一在下/在上）、忘/忙（心在下/在左）。其余同部件异构的字（杏/呆、叭/只、们/闪）首版只收一个或不收。
5. **说明文字只用基本区汉字**（U+4E00–9FFF）：卡片用系统字体渲染，扩展区字（如「𨸏」「𩺰」「𥝢」）在手机上会变成方框，所以改写为通行字并在括号里说明。

### 4.4 构形统计

- 造字法：形声 112、会意 86、指事 2。来源：说文 156、今 44。
- 结构：左右 111、上下 69、全包围 5、上包下 3、左下包 3、右上包 1、一上两下（三部件）8。
- 同部件靠位置区分：一+木 → 本（一在下）/ 末（一在上）；亡+心 → 忘（心在下）/ 忙（心在左）。
- 三部件字：品 晶 磊 犇 淼 毳 鑫（三个相同部件，任意两个起手都生成未成牌）、骂（只能从「口口」起手，因为「口+马」会先合成「吗」——这本身是个小谜题）。
- 部件被用作「字上生字」的中间字：林、炎、从、可→哥、圭、相、古、安、旦、早、加、利、召→昭、分、赤 等。

### 4.5 已知取舍

| 取舍 | 理由 |
|---|---|
| 不收「朋 吕 昌 出 羽 竹」等常被误拆的字 | 它们是象形字或说文另有分析，收进来就是编造 |
| 「赤」作为基础部件，不做「大+火」 | 说文确为「从大从火」，但楷书「赤」看不出大和火，母语玩家会觉得是编的 |
| 「众」= 人 + 从（⿱） | 甲骨文即三人；说文收作「㐺」（众立也，从三人）。卡片写明字形略异 |
| 「骂」「鑫」「尖」「歪」「她」等后起字 | 标「今」，写清是简化字或后起字，不冒充说文 |
| 首版不做「杏/呆」等更多同部件异位字 | 位置区分机制已支持，留作后续扩充 |

## 5. 难度曲线、关卡与模拟器

### 5.1 六卷结构

| 卷 | 名称 | 教什么 | 压力手段 |
|---|---|---|---|
| 一 | 叠字 | 拖上去就能合成；同字相叠（林森从众炎焱多哥圭双赫）；墨有限；洗笔 | 几乎没有压力，干扰从第 3 帖开始 |
| 二 | 会意 | 两个不同部件；包围结构（囚困因国闪闯间）；本/末：落点方位决定结果 | 干扰部件能和本帖部件组成别的字（诱惑） |
| 三 | 偏旁 | 形声字、形旁与声旁、偏旁变体（氵忄讠扌亻……）；同声旁字族（青：清情请晴睛精） | 目标数增多（最多 11 个），部件种类多，棋盘开始拥挤 |
| 四 | 上下与包围 | 宀艹辶穴雨 等字头字底；忘/忙 | 提示降为 0 级，要自己想拆法 |
| 五 | 字上生字 | 先合成中间字再合成目标（相→想/霜/箱，召→昭→照，加→架/驾） | 中间字占格子；干扰部件可能把中间字「劫走」 |
| 六 | 三才 | 三部件与未成牌（品晶磊淼鑫犇毳骂）；综合 | 未成牌占格、干扰率最高、终章 8 个深层目标 |

**曲线原则**（规避第一批的问题）：
- **每卷第一帖是喘息帖**：新概念 + 墨量宽松（slack +0.1）+ 提示全开。避免「某一关突然成墙」。
- **卷内递进**：目标数 ↑、干扰率 ↑、起始提示 ↓、墨余量 ↓，四个旋钮每帖最多拧两个。
- **中期压力**：第三卷起目标 7–11 个、同时展开 3 个，部件种类 8–13 种，16 格的棋盘会被备料和干扰占到 30–70%，必须取舍和洗笔。模拟器检查「中期无压力」：第三卷起新手通关率不得高于 85%。
- **没有一招鲜**：不存在通用最优策略——什么时候合成中间字、什么时候洗掉干扰、用不用提示，取决于目标和预告。模拟器里「贪心合成」的新手机器人在第五卷后明显吃亏，就是证据。

### 5.3 一局时长估算

单帖操作数 ≈ 取牌数 + 棋盘合成数 ≈ 最少部件 × (1 + 浪费率) + 内部节点数。认真玩家约 1.8 s/次操作，新手约 3 s/次，新字卡约 3 s/张（第一次）。
- 第 1 帖：5 部件 → 约 9 次操作 → 约 20 s + 2 张卡 ≈ 30 s。
- 第 14 帖：22 部件 → 约 45 次操作 → 约 80 s + 11 张卡 ≈ 2 分钟。
- 第 30 帖：24 部件（三层链和三部件多）→ 约 55 次操作 → 约 100 s + 少量卡 ≈ 2 分钟。
- 整个闯关约 60–75 分钟（认真），每次打开玩 2–4 帖。

### 5.4 自动模拟器（`npm run sim`，也可在 `?debug=1` 下 `__game.simulate()`）

模拟器直接调用 `src/core/` 里的规则代码（与游戏同一份），在 Node 中运行。

**机器人**

| 机器人 | 行为 |
|---|---|
| 新手 `novice` | 笔架部件：60% 概率随机放到空格，40% 概率放在「最近出现的同族部件」旁。合成落点：60% 的概率选「结果是目标字或其中间字」的方位（模拟玩家看预览气泡），否则随机方位（实现时新增，否则本/末、忘/忙类关卡的新手通关率失真）。每步后，只要棋盘上有任何能合成的牌对就随机合成一对（不管是不是目标需要的）。不用提示；棋盘满了才洗笔，洗最早放下的牌。每 8 步有 10% 概率「误拖」一次（随机移动） |
| 认真 `diligent` | 维护目标缺口（与导演同一算法）。笔架部件：能直接合成目标或目标的中间字 → 落笔即合；是缺口部件 → 放下；是干扰部件 → 棋盘占用 < 60% 时放下（留作可能的发现），否则直接洗掉。只做「对目标有用」的合成，不做会吃掉缺口部件的合成。看预告：如果下一个部件能和当前部件合成目标，先放下当前部件等它。卡住时（缺口部件迟迟不来）用提示不计入（它知道配方）。 |
| 上限 `oracle` | 在认真的基础上从不保留干扰部件（一来就洗），用来确认「每帖可解」。**偏差**：设计中的「对 3 个预告穷举」没有实现——导演加了可解性保护（见下）之后，这个贪心版已在 30 帖 × 200 种子上 100% 通关，穷举不再提供额外信息 |

**每帖输出**（200 个种子 × 3 个机器人）：通关率、剩墨分布（P10/P50/P90）、操作数、棋盘最高占用、洗笔次数、预估时长（操作数 × 每次耗时 + 新字卡）。另输出无尽模式 200 局的时长、到达的章、死因（墨尽时棋盘占用）。

**实现时的修订与结果**

- **导演可解性保护**（`core/game.ts`）：闯关模式下，只有当 `剩余墨 − 笔架张数 − 1 ≥ 当前目标缺口部件数 + 队列中目标的叶子总数` 时才允许发干扰部件。没有它时 oracle 在 L3/L5/L11/L19/L29 只有 99%（干扰连发把墨耗尽）。
- **墨量搜索**：保护让「墨 = 最少部件」的帖反而变简单（干扰被停发），所以校准从「最少部件 + max(2, 20%)」起搜（第一卷从最少部件起），在满足「认真 ≥ 97%、第三卷起认真剩墨 P50 ≤ 30%、新手落在目标带内（两侧各收 2 个百分点）」的候选里，取新手误差与最优相差 ≤ 0.04 的最小墨量。
- **验收项修订**：
  - 「棋盘最高占用 P50 ≥ 50%」第二阶段取消（30 格时实测只有 3–27%）。第三阶段把棋盘缩到 4×4，并改为检查「盘面过空」：**第四卷起认真机器人峰值占用 P50 ≥ 30%**。实测第四卷起认真 31–50%、新手 31–69%，全部通过。
  - 时长窗口改为「第一卷 15–70 s，其后 30–200 s」：原 60 s 下限按人类节奏估算，认真机器人（1.8 s/步）第二卷就只要 35–58 s。
  - 无尽新手标准由「3–6 分钟」改为「中位 ≤ 12 分钟且到达章低于认真」：新手每步 3 s，墙钟时长反而比认真长（P50 8.8 分），但只到第 7 章（认真第 11 章）。
- **结果**：全部验收项通过（`sim-report.md`「全部通过 ✓」）。无尽（4×4、起始墨 30、每 2 章衰减）：认真 P10/P50/P90 = 5.8 / 6.2 / 6.6 分、到第 10 章；新手 7.0 / 8.0 / 8.7 分、到第 7 章。

### 6.1 风格关键词

### 6.4 牌面设计

- **格子**：82×82（第三阶段；牌和合成特效按 `BS = 82/66` 整体放大），宣纸亮色底，四边 1 px 淡赭描边，内部朱色虚线米字格（对角线 + 十字）。空格就是一个空米字格。
- **部件牌**：比格子略小（62×62，圆角 6），底色比纸亮一档并带极轻的纸张投影（向下 2 px，`rgba(60,40,20,0.12)`）；淡墨字。（第二阶段的左上角变体小字已删除：变体因字而异，不能标在部件牌上，改在合成动画和新字卡里展示。）
- **字牌**：同尺寸；浓墨字，字下方 11 px 淡墨拼音；左下角极小的造字法标记（会意「会」、形声「形」、指事「指」，朱色 9 px 印形，可在设置里关）。
- **未成牌**：两个部件按最终位置淡墨显示，朱色虚线边框缓慢「呼吸」（不透明度 0.4↔0.8，周期 1.6 s），右下角「未成」小印。
- **待机动画**：字牌每 6–10 秒随机有一张做一次「墨润」——字迹边缘轻微晕开再收回（0.8 s）；整个棋盘有 1–2 个极淡的墨点缓慢漂移（环境粒子）。

### 6.5 质感处理

| 元素 | 做法 |
|---|---|
| 宣纸 | 512² 平铺纹理（值噪声 + 400 根短纤维 + 稀疏草屑），全屏暗角 `radial-gradient` 到 `rgba(80,60,30,0.18)` |
| 远山 | 背景画布底部 3 层程序化山形（1D 分形噪声生成轮廓，从下到上由清墨到更淡），慢速视差漂移（周期 60 s，±6 px）；山间有雾带（白色低透明横向渐变） |
| 墨迹晕开 | 6 张预渲染晕染精灵（径向渐变 + 噪声边 + 飞白缺口），`multiply` 合成 |
| 飞白 | 笔扫遮罩带随机缺口，字被扫出时边缘不连续 |
| 印章 | 圆角方形朱底；文字用文楷/马善政反白（白文印）或朱字（朱文印）；用噪声腐蚀边缘和内部，每方印随机旋转 −4°~4°；盖下时带 2 px 偏移的淡印残影 |
| 卷轴 | 上下赭石木轴（线性渐变 + 高光），纸面为宣纸暗色；展开/卷起是纵向缩放 + 木轴滚动 |
| 两侧装饰（桌面） | 左侧：竖排一方大砚台、一支毛笔（程序化绘制的笔杆渐变 + 笔毫）；右侧：竖排一幅淡墨竹（程序化竹节 + 叶片）和一方压角闲章 |

### 6.6 合成的高潮：分镜与时序

合成是全游戏的核心反馈，按「部件飞入 → 拼合 → 墨晕显字 → 落印」四拍设计。时长按事件分档：普通合成 640 ms；首次发现 1400 ms（第三阶段加长）；交付目标在其后接 700 ms 飞入卷轴。全程**不阻塞输入**（玩家可以同时拖别的牌，动画中的牌不可拖），首次发现卡片除外。

| 拍 | 时间（普通 / 首次） | 画面 | 声音 |
|---|---|---|---|
| ① 飞入 | 0–180 / 0–260 ms | A、B 两个部件从原位置飞向 B 格，在途中缩放、挤压到结果里的位置框（⿰：左框宽 46%、右框宽 54%；⿱：上 45%、下 55%；包围：外框 100%、内框 55% 放在开口处；品：上 50% 居中、下两个各 50%）。需要变体的部件在 40% 进度时交叉淡变（水→氵）。曲线 `easeInOutCubic`，A 走一条轻微的弧线 | 纸张摩擦（短促滤波噪声） |
| ② 拼合 | 180–240 / 260–360 ms | 两部件贴合瞬间，格子整体 0.92 挤压后回弹（spring），**命中停顿** 40 ms（首次 80 ms），一圈极淡的冲击环 | 「笔落」：低频木质闷响 + 古琴拨弦（音高按结果深度在五声音阶上取） |
| ③ 墨晕显字 | 240–560 / 360–900 ms | 部件字形淡出，结果字形从中心以带噪声边缘的晕染遮罩显现（墨从中心洇开），同时一圈清墨水痕向格外扩散到 1.6 倍格宽后淡出；6–12 颗墨点向外溅射并在纸上留下 1.5 s 才褪去的小墨渍。首次发现时字放大到 1.5 倍并上浮、停留后缩回格内；水痕环扩散到格宽 1.8 倍以上（首次、三部件再 ×1.3）并加一道描边环，明显越出本格（第三阶段加强） | 墨晕「嘶」声（带通噪声扫频，从高到低） |
| ④ 落印 | 560–640 / 900–1100 ms | 首次发现：一方朱色小印（造字法：「会意」「形声」「指事」）从 1.6 倍大落到牌右上角，overshoot 后定住，轻微震屏（trauma 0.10），2 颗朱色碎屑。普通合成：只有一个 1 px 的朱色点在拼音下闪一下 | 首次：印章「咚」（90 Hz 正弦 + 短噪声）+ 磬声 |
| ⑤ 交付（目标字） | +0–700 ms | 字牌抬起（阴影变大），沿弧线飞向对应卷轴（450 ms，`easeInOutQuad`），途中拖出淡墨尾迹；到达后卷轴上的描红字被一记**笔扫遮罩**从左上到右下填满浓墨（350 ms），卷轴右下角落一方「成」字朱印（中强度震屏 0.18、hitstop 40 ms），分数跳字从卷轴升起 | 磬声和弦（宫-角-徵）+ 印章声 |

**三部件（未成→成）**：未成牌生成时只做 ①② 和一个「虚线框画出」动画（虚线沿边框逐段画出 300 ms）；第三个部件到来时，未成牌里的两个淡部件先「墨色变浓」再与第三个部件一起走 ③④，晕染范围 1.3 倍。

**多拍连成**：一次操作导致交付多个目标时（例如新展开的目标棋盘上已有），飞行依次错开 150 ms，磬声逐个升高。

### 6.7 关键画面

**① 标题页**：满屏宣纸，底部三层淡墨远山缓缓漂移，山间一抹雾。画面上三分之一，马善政写的「造字记」三个大字竖排偏右（浓墨，带飞白），左侧一方竖长朱印「汉字合成」，印下小字 `HANZI MERGE`（11 px 字距加宽的淡墨拉丁字）。中部是一个放大的米字格，里面「木」「木」两个淡墨字每 4 秒自动演示一次合成为「林」（完整的晕染动画），再淡出换成「日月→明」「人木→休」——不用文字就告诉玩家这是什么游戏。下方一枚朱砂圆角大按钮「开 始」（继续最近一帖），其下一排三个淡墨小按钮：选帖、书斋、图鉴；右上角设置齿轮（毛笔画风的圆）。环境粒子：极淡的墨点和纸屑缓慢上浮。

**② 引导（第 1 帖）**：上方只展开一个卷轴，里面是朱色空心描红的「林」，下面一行小字「木 + 木」。棋盘只有中间一格的米字格被朱线描亮，笔架上的「木」有一只淡墨手指图标从它拖向那一格（循环）。底部一行楷体提示：「把木拖进格子」。玩家拖完，墨锭从 8 降到 7，旁边浮出「−1 墨」。

**③ 典型局面（第三卷第 4 帖）**：三个卷轴展开：「泡」（只示 ⿰ 结构）、「饱」（饣 + ？）、「驻」（马 + 主）。棋盘上散落着淡墨的部件牌「包」「水」「马」「食」「白」，两张字牌「住」「妈」（妈刚交付过，这是多做的一个），一个角落是被冷落的干扰部件「皮」。玩家正拖着「包」：棋盘上「水」「食」「手」三张牌浮起石绿色的淡光晕（能合成），「水」那张更亮还带朱色描边（能合成目标「泡」）。手指上方 64 px 是半透明的「包」，悬停在「水」上方时，「水」上方弹出一个小气泡：淡墨「泡 pào」。墨锭剩 11。

**④ 高潮时刻（第五卷末帖，首次合成「照」）**：玩家把「昭」拖到「火」上。两张牌飞向一处，「火」在半路变成四点「灬」，滑到下方；「昭」被压扁到上方。贴合瞬间格子一沉一弹，墨从中心洇出，「照」放大 1.35 倍浮在格子上方，一圈水痕荡开到旁边的格子，几颗墨点溅在米字格上。一方「形声」朱印落在右上角，屏幕轻轻一顿。接着新字卡从底部滑上来（见 ⑤），同时「照」又是卷轴目标——卡片关闭后它抬起飞向卷轴，描红的「照」被一笔扫满浓墨，「成」字印落下。

**⑤ 新字卡**：底部 54% 高的宣纸卡片，顶端两根赭石卷轴木杆。左侧大字「照」（112 px 浓墨）和「zhào」；右侧上方是拆解图：「昭」（淡墨）在上，「灬」（朱色，标注「火 · 四点底」）在下，中间一个 ⿱ 图标；下方两枚标签印「形声」「火表义 · 昭表音」；再下是释义「照耀」和一段楷体引文「《说文》：明也。从火昭声。底下的灬就是火。」；最底部一行淡墨小字「图鉴 · 已收 143 / 200」，以及「收入图鉴」朱色按钮（点任意处也能关闭）。

**⑥ 帖成结算**：卷轴全部收拢成一排，画面中央展开一幅横向长卷，马善政写的「帖成」两个大字由笔扫遮罩写出；三方空的赭石印框依次被朱印盖上（得几星盖几枚，每枚间隔 280 ms，盖下时轻震）；下方分数从 0 缓动跳到最终值，剩墨换分逐滴「滴」入分数；「本帖新识」一行列出本帖首次合成的字（每个字可点开卡片）。新纪录时右上角斜盖一方「新纪录」大印并洒朱色碎屑。底部按钮：「下一帖」（朱色主按钮）、「再写一遍」、「选帖」。

**⑦ 墨尽（失败）**：墨锭空了，棋盘上剩下的牌逐个褪成清墨；中央浮出淡墨大字「墨尽」，下面一句「还差：照、歌」（未完成目标的描红字），和一个朱色主按钮「再写一遍」（一键重开，0.6 s 回到可操作）。语气平和，不惩罚。

**⑧ 桌面适配**：中间是 390 宽的竖屏纸面（带纸张投影），左右是深一档的书桌纸色，左侧砚台和毛笔、右侧淡墨竹和闲章，暗角收边。

### 6.8 与同批游戏的区分

| | hanzi-merge 造字记 | five-drop | chain-2048 |
|---|---|---|---|
| 主调 | 暖米白宣纸 + 墨 + 朱砂 | 雾蓝石板灰 + 黑曜石/白瓷 + 冷光 | 苔藓翡翠 + 鎏金 |

## 7. 动效清单

### 7.1 强度分档

| 档 | 震屏 trauma | 命中停顿 | 粒子 | 用于 |
|---|---|---|---|---|
| 轻 | 0（或 0.04） | 0 | ≤ 4 | 拾起、放下、移动、交换、提示、点击 |
| 中 | 0.10–0.18 | 40 ms | 6–12 | 合成、交付目标、首次发现落印、洗笔 |
| 重 | 0.24–0.32 | 80 ms | 16–30 | 帖成、终章、新纪录、三部件成字（首次） |

震屏模型：`offset = maxShake × trauma²`，`maxShake = 5 px`，旋转上限 0.5°，trauma 每秒衰减 1.6。震屏只作用于舞台画布，不影响 DOM 卡片。设置里有「减弱动效」开关（震屏 ×0、停顿 ×0.5、粒子 ×0.5）。

### 7.3 音色配方（WebAudio）

| 音色 | 配方 |
|---|---|
| 古琴拨弦 | Karplus-Strong：噪声激励 20 ms → 延迟线（周期 = 1/f）→ 一阶低通（0.996 衰减）；加 1 个 2f 正弦泛音（音量 0.15）模拟泛音；4 kHz 低通，总长 1.2 s |
| 磬 / 编钟 | 3 个正弦，频率比 1 : 2.76 : 5.40，音量 1 : 0.5 : 0.25，指数衰减 1.8 s / 1.0 s / 0.5 s，起音 3 ms |
| 印章「咚」 | 90 Hz 正弦，音高 20 ms 内从 140 Hz 滑到 90 Hz，衰减 180 ms + 宽带噪声 30 ms（低通 1.2 kHz） |
| 木鱼「笃」 | 520 Hz 正弦，衰减 70 ms + 3 kHz 带通噪声 10 ms |
| 纸摩擦 | 白噪声 → 带通 2.5 kHz Q=0.8，包络 10/50 ms |
| 墨晕「嘶」 | 粉噪声 → 带通，中心频率 3 kHz 在 400 ms 内滑到 600 Hz |
| 水 / 涟漪 | 正弦 1.2 kHz 快速下滑到 300 Hz（水滴）+ 低频 80 Hz 正弦 300 ms |
| 风 | 粉噪声 → 低通 400 Hz，音量随 LFO（0.07 Hz）起伏 |

**音阶**：五声音阶 D 宫（D E F# A B），合成音高 = 基音 × 音阶[深度 + 连击步数]，跨两个八度封顶。

### 7.4 程序化背景音乐

- **层 1 · 底**：两个微失谐的正弦（D2 与 A2），音量极低，配合风声噪声，营造「空」。
- **层 2 · 古琴**：每 2.5–5 秒（随机）弹一个短乐句（2–4 个音，取自五声音阶，偏重宫、徵），偶尔加滑音（延迟线周期在 150 ms 内变化 ±3%）和泛音。
- **层 3 · 箫**（第四卷起或无尽第 4 章起加入）：正弦 + 气声噪声 → 低通，长音 3–5 秒，慢起慢收。
- 墨 ≤ 3 时古琴乐句间隔缩短、音域下移；帖成时音乐整体淡出 1 s，让结算音效独占。
- 音乐和音效分开开关，主音量经 `DynamicsCompressor`。

## 8. 界面与流程

### 8.1 流程

```
加载（≤1 s）→ 标题页
   ├─ 开始 → （首次）第 1 帖 + 引导 → 游戏中
   │        （非首次）最近未完成的一帖 → 游戏中
   ├─ 选帖 → 六卷 × 五帖 → 游戏中
```

### 8.5 拖拽与信息避让

- **拖拽物位置**：触摸时显示在手指上方 64 px（`input.touchLiftPx`），落点判定以拖拽物中心为准，所以手指不会挡住落点；鼠标为 0 偏移。
- **预览气泡**：出现在被悬停牌的正上方 76 px 处（与拖拽物错开，拖拽物在牌上，手指在拖拽物下方）；如果牌在第 0 行（上方是卷轴），气泡改放到牌的左侧或右侧（选空间大的一侧）。
- **原格虚影**：拖起的牌在原格留下 30% 透明的虚影，松手失败时从拖拽物位置弹回。
- **从笔架往上拖**：笔架在棋盘下方，向上拖动时手指不会挡住棋盘大部分区域；拖拽物抬高后能直接看到最下一行。
- **跳字**：分数跳字只从卷轴升起（不在棋盘上）；同时最多 3 个，第二个起每个向右错开 18 px、延迟 80 ms。
- **重复合成气泡**：同时最多 1 个。
- **提示层级（从高到低）**：新字卡（模态）> 暂停面板 > 引导手指 + 提示条 > 情境提示 > 预览气泡 > 重复合成气泡 > 跳字。新字卡打开时其他提示全部挂起。

### 8.6 新字卡与情境提示

### 8.7 暂停

暂停按钮、`blur`、`visibilitychange(hidden)` 都会暂停（新字卡打开时已暂停）。面板（DOM，从上方垂下的卷轴）：继续（主按钮）、重写本帖、选帖、图鉴、设置、回到标题。面板背景压暗棋盘。继续后 200 ms 恢复输入（防止点击穿透）。

### 8.8 结算

- **帖成**：§6.7 ⑥。记录：本帖最高分、最高星、首次通关时间。「下一帖」可直接进入（第 30 帖通关后改为「回卷首」并播放终章特别动画：全部 200 字在长卷上依次淡入）。
- **墨尽**：§6.7 ⑦。显示已完成目标数 / 总数、本帖新识的字。一键「再写一遍」（同一种子：出牌顺序相同，方便改进策略；设置里可改为「换一组出牌」）。
- **书斋结算**：分数（缓动滚动）、历史最高（新纪录庆祝同上）、到达章、本局新收字、「再来一局」（新种子）。

### 8.9 选帖

纵向滚动的六卷，每卷是一幅横向小卷轴，标题「卷一 · 叠字」，内含 5 个帖子印框（显示帖号、星数）。未解锁的卷是卷起来的状态（灰墨）。通关一帖解锁下一帖；每卷最后一帖通关解锁下一卷。卷名下方小字列出这一卷的代表字。

### 8.10 图鉴（「字帖」）

- 顶部标签：按卷 / 按造字法（会意、形声、指事）/ 部件。顶部进度「已收 57 / 200」缓动。
- 网格每格一个米字格：已收的字为浓墨 + 拼音；未收的显示结构图标（⿰⿱…）和淡淡的「？」，不剧透字形。
- 点已收字打开该字的新字卡（只读版）。部件页列出 82 个部件、名称和变体（「水 · 氵三点水」）。
- 收满一卷 / 一种造字法时，标签上盖一方「全」字小印。

`core` 是可变状态 + 事件（`Game.act(action) → GameEvent[]`，悔笔用一步快照），没有做成不可变 `apply`；模拟器同样直接调用。

**模块接口要点**

| 模块 | 对外接口 |
|---|---|
| `core/recipes` | `resolveMerge(a: TileSpec, b: TileSpec, zone: Zone): MergeResult`；`candidatesFor(a, b)`；`leaves(char)`；`canMergeAny(board)` |
| `core/level` | `createLevel(def, seed)`；`apply(state, action): { state, events: GameEvent[] }`（不可变更新，便于悔笔和模拟器）；`legalActions(state)` |
| `core/director` | `nextPiece(state): string`（纯函数，读 state 里的 rng） |
| `render/mergeFx` | `play(event: MergeEvent)`：消费 core 产生的事件做动画，动画结束前对应格子锁定 |
| `ui/card` | `show(char): Promise<void>` |
| `sim/runner` | `simulate({ levels, seeds, bots }): Report` |

**事件驱动**：`core` 只产生事件（`Placed / Merged / PendingCreated / Delivered / OrderOpened / Discarded / InkChanged / LevelWon / LevelLost / Discovered`），渲染、音频、UI 订阅事件。模拟器不订阅任何东西，所以跑得快（目标：30 帖 × 200 种子 × 3 机器人 < 60 s）。

**`src/config.ts` 包含**：§3.12 全部字段；`layout.*`（§8.4 坐标）；`fx.*`（时长、强度档、粒子数）；`audio.*`（音量、音阶、BGM 间隔）；`sim.*`（机器人参数、验收阈值）；`endless.*`。关卡数据在 `data/levels.ts`，但其中 `ink / star2 / star3` 由模拟器回填。

## 10. 性能预算与策略

| 项 | 预算 / 做法 |
|---|---|
| 帧率 | 稳定 60 fps；主循环 `requestAnimationFrame`，dt 上限 50 ms |
| 每帧分配 | 0：粒子（上限 200）、跳字（上限 12）、气泡、补间全部对象池 |
| 绘制 | 字形缓存 drawImage；背景画布只在 resize 时重绘；棋盘静态层（格子 + 米字格）缓存成一张离屏画布 |
| 启动 | 宣纸纹理 25 ms、晕染精灵 6 张约 30 ms、印章按需生成并缓存；首帧 ≤ 300 ms（中端机） |
| 字形缓存重建 | 字体就绪时分帧重建（每帧 40 个字），避免一次卡顿 |
| 首包 | ≈ 141 KB 传输（§2.2），其中字体 ≈ 99 KB |
| 内存 | 字形缓存 < 8 MB，精灵 < 4 MB |
| 低端机降级 | 帧时间连续 2 s > 20 ms：关闭远山漂移、粒子 ×0.5（**偏差**：晕染精灵数不减半——精灵在启动时一次生成，绘制成本不随数量变） |

## 12. 实现记录（第二、三阶段）

### 12.1 验证方式

- `npm install && npm run build`：0 类型错误、0 警告；`prebuild` 子集化并核对字体覆盖，`check-dist` 核对产物字体覆盖与体积（文楷 115.0 KB / 463 码位，Logo 9.5 KB / 13 码位）。
- `npm run dev` / `npm run preview` 均在 5107 端口。
- Playwright（Chromium）在 390×844（isMobile、hasTouch、DSF 2）和 1280×800 两种尺寸下，dev 与 preview 都跑通：标题 → 引导（真实鼠标拖拽完成「木→格子」「木+木=林」「林+木=森」）→ 暂停 / 继续 → 结算 → 再写一遍；另跑选帖、图鉴三个标签与只读字卡、设置、书斋与书斋结算、墨尽结算、新纪录结算。控制台 0 error / 0 warning，`__game.fontAudit()` 为空。
- 慢字体测试：woff2 人为延迟 6 s，0.44 s 可点「开始」，0.76 s 进入棋盘（系统楷体兜底）。
- 合成动画逐帧截图（`timeScale(0.25)`，河 = 水→氵 + 可，首次发现）：飞入、变体交叉淡变、拼合挤压、墨晕显字、「形」印落下、飞向卷轴、笔扫填墨、「成」印，四拍 + 交付全部可见。

### 12.2 与设计的偏差（均已在对应章节标注）

| 项 | 设计 | 实现 | 原因 |
|---|---|---|---|
| 关卡墨量 / 星级 | §5.2 初值 | §5.2.1 校准值；L12、L22 干扰率降为 0.12；L6 墨 14 | 模拟器验收 |
| 导演 | 无可解性约束 | 闯关模式下墨不够时停发干扰 | oracle 99% → 100% |
| oracle 机器人 | 3 步预告穷举 | 贪心（干扰一律洗掉） | 保护加上后贪心已 100% |
| 新手机器人 | 随机方位 | 60% 按预览选方位 | 本/末类关卡失真 |
| §5.4 验收项 | 占用 ≥ 50%；时长下限 60 s；无尽新手 3–6 分 | 占用只报告；时长 30–200 s（第一卷 15–70 s）；无尽新手 ≤ 12 分且到达章低于认真 | 见 §5.4「实现时的修订」 |
| 无尽返还 | 叶子数 + 1 | 奖励每 3 章 −1，最低 −1 | 否则认真玩家不会结束 |
| 震屏档位 | 0.08 / 0.18 / 0.32 | 0.04 / 0.16 / 0.30 | 轻档太晃 |
| 字体就绪切换 | 300 ms 交叉淡入、分帧重建 | 清缓存、懒重建 | 同屏字形少，无卡顿 |
| 字体体积 | ≈ 90 KB / 316 字 | 115.0 KB / 463 码位（预算 120 KB 内） | 加入拼音声调字母与界面字，界面字改由源码扫描自动收集 |
| 首次合成「林」（引导） | §6.6 全套 + 新字卡 | 引导中不弹卡，改为卷轴下一行说明「林 · 从二木 · 会意」 | 引导目标 25 s，不打断 |
